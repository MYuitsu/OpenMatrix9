## Design decisions

1. New pure module `standalone/crates/om9-app/src/workbench_regions.rs` (`pub mod workbench_regions;` in `lib.rs`), extending the existing crate and layered on `DockLayout`. It does not duplicate `dock_layout.rs` constants or persistence. Reason: `resolve()` is silent and scalar-only, and the four-viewport geometry is trapped in egui code. A separate pure module gives a typed, serializable-ready, egui-free region model, and leaves `dock_layout.rs` free for L3-003/004/005/008.
2. Typed model (names fixed; the implementer may add private helpers only):
   - `WindowSize { width: f32, height: f32 }`.
   - `RegionRect { x, y, width, height }` (plain f32, `Serialize/Deserialize`, `Copy`).
   - `RegionKind { LeftRail, Center, RightDock, CommandInput, Toolbar, StatusBar }`.
   - `ViewSlot { view: ViewId, rect: RegionRect }`. The center holds exactly 4 slots in `ViewId::ALL` order for the standard four-view layout, or 1 slot when the workspace maximizes one view. Reuse the existing 2 px gap and 2x2 order from `ui.rs`.
   - `RegionPlan { window, left_rail: Option<RegionRect>, center: RegionRect, views: Vec<ViewSlot>, right_dock: Option<RegionRect>, command_input: RegionRect, toolbar, status_bar, notes: Vec<RegionNote> }`.
   - `RegionNote` (a visible, non-silent fallback record): `RightDockYielded { reason }`, `LeftRailShrunk`, `CommandInputKept`.
   - `RegionError` (Debug, Display, `std::error::Error`; maps into `om9_core::Error::Invalid(&'static str)` at the UI boundary): `InvalidWindow { width, height }` (non-finite, zero or negative), `WindowTooSmall { min_width, min_height }`, `CommandInputUnavailable`, `ViewSetInvalid { count }`.
3. Single entry point: `pub fn compute_regions(layout: &DockLayout, window: WindowSize, views: &[ViewId]) -> Result<RegionPlan, RegionError>`. It is pure (`&DockLayout`, no mutation) and delegates sizing to `DockLayout::resolve` so there is one source of truth for constants. Behavior:
   - Non-finite, zero or negative window -> `Err(InvalidWindow)`. The caller keeps the last good plan; no layout mutation.
   - A window smaller than the minimum usable window (left rail min 240 + canvas min 320 wide; toolbar + status + `COMMAND_MIN` + `CANVAS_MIN_HEIGHT` tall) -> `Err(WindowTooSmall)`. The UI keeps the last good plan and shows a status message. It never paints overlapping regions.
   - Narrow window (width < `NARROW_WINDOW_WIDTH` or `left + right + CANVAS_MIN_WIDTH > width`) -> the right dock is dropped (`right_dock: None`) with `RegionNote::RightDockYielded`. The left rail and command input keep their rects.
   - Hidden right dock (no visible right sections) -> `right_dock: None` without a note (a defined state, not an error).
   - Command input is critical: if `PanelState.visible == false` for `PanelId::CommandLine`, `compute_regions` still reserves `COMMAND_MIN` height and returns `RegionNote::CommandInputKept` instead of hiding it (DECISION; flagged under "Business-rule consent" below). If the height cannot fit `COMMAND_MIN`, return `Err(WindowTooSmall)`.
   - Invariants (asserted in tests and by a `RegionPlan::validate()` method returning `Result<(), RegionError>`): all rects have width and height >= 0 and are finite; left, center, right and command input are pairwise non-overlapping and lie inside the window; `command_input.height >= COMMAND_MIN`; `views` rects tile the center without overlap.
4. Minimal seam toward `OM9-L2-01-02` (command dispatch / undo) and `OM9-L2-01-03` (document / scene), defined in `workbench_regions.rs`, not in those modules:
   - `pub trait CommandInputHost { fn command_input_ready(&self) -> bool; }`
   - `pub trait ViewportSceneHost { fn visible_views(&self) -> Vec<ViewId>; }`
   - `pub fn compute_regions_for(layout, window, scene: &impl ViewportSceneHost, cmd: &impl CommandInputHost) -> Result<RegionPlan, RegionError>`, which returns `CommandInputUnavailable` if the host reports not ready.
   - In tests use local stub structs. In `ui.rs` adapt the real objects that already exist (`controller.workspace.visible_views()` and the CMD frame) via thin private adapters. Do not implement L2-01-02 or L2-01-03, do not edit `om9-core`/`om9-scene` behavior, and do not mark them satisfied. Docking holds no document, transaction or scene state, so an error path cannot change the scene or the render cache by construction. Test this.
5. UI integration in `ui.rs`: replace the inline 2x2 math in the `CentralPanel` block with `RegionPlan.views` (same pixel results as today). Call `compute_regions` each frame next to `self.dock.resolve(...)`. On `Err`, keep the previous plan, set a visible status via the existing `status_surface` (an error-kind message, never a silent no-op), and keep `self.dock` untouched. Do not touch chrome menus, persistence, reorder/float, reset or the builder slot. No second Matrix Main Menu, no mechanical-CAD UI.
6. Rust only, safe code (`#![forbid(unsafe_code)]` already applies). No C++, no Python, no native exception. Python is used only for the existing `tools/public_source_audit.py`.
