## Recorded deviations (owner decision possible)

- **ADR-03-5 (owner decision 2026-10-17: KEEP)** — the pre-implementation audit proposed
  `FeatureId = HistoryId` and "no aliases". The implementation adds a real typed document feature
  (`FeatureId`, `FeatureKind`, `Document.features`, `Mutation::FeatureInsert`) so that the L3-001 oracle
  (feature identity and lifetime, stable across save/reopen, never reused after deletion) is provable
  without going through the evaluation graph. The owner decided to keep it as delivered, `Feature.outputs`
  included. The ownership split is recorded in `api.md` §7.2: identity/output refs live in
  `Document.features`, evaluation lives in `HistoryGraph`, and M04's recipe must reference the
  `FeatureId` it evaluates.
- **ADR-03-6** — persistence option A applied: `(Document,"groups")`, `(Document,"features")` and
  `(Entity,"extensions")` are admitted additively in schema 4 with a legacy-key guard, no version bump
  and no migration; a document carrying none of them encodes byte-identically. `Document.tolerance` was
  deliberately NOT added because `OM9-L2-01-08` (typed units and tolerance) is not implemented.
- **Change batches are recorded while at least one observer is subscribed.** A controller nobody
  observes holds no baseline and therefore no change ring. This is a memory decision forced by
  `scene_allocation_peak`; it is part of the API contract (`is_recording_changes`), not hidden.
