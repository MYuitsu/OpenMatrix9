# Desktop viewport — GPU renderer only

Date: 2026-10-19. The user requested removing CPU rendering to reduce code, then explicitly approved saving the GPU rule in `openmatrix9-ui`: “Có, lưu quy tắc GPU này”. This applies to the desktop viewport renderer, not document/model/picking math or transient UI preparation.

## Changes

The document viewport always uses `om9-render` through eframe/wgpu. The old egui scene painter branch has been deleted, including CPU grid projection/drawing, point/curve/mesh drawing, flat Lambert triangle shading and original-position ghost drawing. GPU render failure shows a viewport diagnostic; there is no alternate scene renderer to fall back to. Gumball, captions, selection outlines, tool previews and other egui interaction surfaces remain UI overlays submitted through the GPU-backed UI renderer.

`om9-render` is an unconditional default dependency. Viewport initialization no longer calls OCCT to make a demo sphere, and the unused renderer/mesh fallback fields and draw branch were removed from `GpuViewport`. Per-pane colour/depth targets, shared scene buffers, dirty redraw, GPU preview matrices, highlights and ghost batches remain. Optional stress scenes are still GPU paths. The old `gpu-sphere` feature name now controls only the independent native OCCT fixture dependency, preserving existing feature invocations. Default rendering needs neither that feature, OCCT DLLs nor `OM9_GPU_SPHERE`.

Desktop startup checks the typed wgpu adapter class: discrete, integrated and virtual GPU identities are accepted; missing/empty, CPU and unknown adapter classes produce a renderer failure. The software-fallback success/warning branch was removed. The owned negative startup fixture and tests now expect that renderer diagnostic. Headless widget tests construct UI state without a native surface and can observe the GPU-unavailable label; they do not render document geometry with a CPU backend.

`tools/validate_m02_selection.py` now requires all four GPU scene panes on every run, and uses the GPU mesh-highlight pixel oracle. Its old `--gpu` spelling is accepted as an inert compatibility argument; no CPU mode or opt-in GPU environment toggle remains. `--brep` only supplies the optional native fixture/runtime.

The approved rule is synchronized byte-for-byte between repository and installed `openmatrix9-ui`. This approval concerns reusable renderer policy, not a manual UI acceptance signature.
