# SNAPS point-input contract — working decisions

2026-11-17. Implementation contract for P00 of the [SNAPS gap plan](2026-11-17-snaps-menu-gap-plan.md). This is a proposed OM9 contract, not runtime evidence or a claim of exact Matrix 9 behavior. The plan contains the 21-control crosswalk and source provenance.

## State and input

- The persistent O-Snap mask starts with End and Mid selected; the master switch starts on. Turning the master off preserves the mask. A one-shot selection overrides the persistent mask for one accepted point, including when its kind is not selected; a miss does not consume it. Escape cancels the subprompt or override without committing the outer command.
- The recovered Matrix90 SNAPS initialization routine sets RhinoScript's mode mask to End plus Mid and enables the master. It sets Project, Planar, and Ortho off. The separate Intersection icon toggles the standard RhinoScript Intersection bit. This establishes the writes made by the panel routine. Startup order, saved-preference restoration, and apparent-intersection behavior still need runtime evidence. [Source trace](../validation/2026-11-17-snaps-p07.md#matrix9-intersection-source-trace-on-2026-11-18)
- The shipped and persisted Matrix90 Rhino 5 x64 schemes specify a 45° Ortho angle, End plus Mid, and SmartTrack off. The installed Rhino factory uses gray `#C8C8C8` solid SmartTrack guides and a 300 ms activation delay. The Matrix90 schemes have no explicit overrides for those fields. The OM9 viewport now emits the same gray stroke and uses its UI hover delay. [Installed reference evidence](../validation/2026-11-17-snaps-p07.md#installed-rhino-5-defaults-for-apparent-intersection-and-smarttrack) · [Viewport regression](../validation/2026-11-17-snaps-p07.md#solid-gray-smarttrack-guide)
- The four Grid Snap choices are 0.1, 0.25, 0.5 and 1.0 mm, independent of display grid spacing. OM9 stores internal length in canonical millimetres (`crates/om9-core/src/units.rs`); quantize in those units in the active construction-plane frame, independently of display units. The audited screenshot indicates 0.5 as the displayed choice; it does not establish a persisted startup default. Grid Snap starts off until a stronger source establishes otherwise.
- Coordinate input is explicit and bypasses grid and pointer-only directional constraints. For pointer input, a valid object snap normally wins over grid and Ortho. The native Rhino 5 free-point path uses a grid-quantized point to choose the Ortho direction. In the diagonal case it projects the raw pointer onto that direction, then adjusts along it to a grid line. Shift temporarily reverses Ortho. [Native composition](../validation/2026-11-17-snaps-p07.md#rhino-5-native-grid-snap-and-ortho-composition)
- Planar uses a plane parallel to the command CPlane through the last accepted point, including when enabled mid-command. Project uses that plane when Planar has a valid base and uses the command CPlane otherwise. Preview, cue and acceptance share the projected point. Surface snaps still require source verification before acceptance. [Approved rules and replay](../validation/2026-11-17-snaps-p07.md#approved-grid-snap-plus-ortho-and-planar-plus-project)
- Between is a nested, cancellable two-point prompt and returns one midpoint to the outer point request. Surface and polysurface target selection retain source identity and reject invalidated targets; left invocation is one-shot and right invocation persistent as documented in the plan. No nested reference pick is committed as outer geometry.

## Intersection and direction-dependent snaps

- A true intersection means points on both source curves/edges within document tolerance. Intersection does not require an earlier point. Tan and Perp require an earlier point; do not synthesize one at command start.
- Apparent intersection is view dependent and must be distinguishable from a true 3D source intersection. The installed Rhino 5 factory enables `Snap to apparent intersections`, and the shipped Matrix90 scheme leaves it at the host default. The native point path tries 3D then a view-projected fallback. It evaluates both source points and ranks the events before Project. When prior ranking criteria tie in Looking Down, the final depth comparison predicts the nearer source. With a valid Line base and Planar on, Project uses a parallel plane through that base. Live preference restoration, competing pairs and desktop output still need comparison. [Native point path](../validation/2026-11-17-snaps-p07.md#rhino-5-native-int-and-project-point-path)
- Rhino 5 documents the first-point condition and ordinary object-snap precedence: [Object snaps](https://docs.mcneel.com/rhino/5/help/en-us/user_interface/object_snaps.htm), [Accurate modeling](https://docs.mcneel.com/rhino/5/usersguide/en-us/html/ch-05_accuratemodeling.htm). Rhino's [modeling aids](https://docs.mcneel.com/rhino/mac/help/en-us/options/modeling_aids.htm) describe apparent intersections as a separate setting. These sources inform OM9 decisions; they do not prove Matrix 9 defaults or all interactions.
- The OM9 Perspective replay retains both source IDs and the original NURBS point when its control polygon crosses behind the camera. The scene regression checks that an apparent crossing outside the near plane is refused. [Perspective visibility evidence](../validation/2026-11-17-snaps-p07.md#apparent-int-on-a-partly-visible-perspective-curve)
- The native solver tries true before apparent for each pair. Once it accepts a pair, it skips later apparent passes and requires a smaller pick-space distance for a later true replacement. At the exact crossing in the three-Line fixture, reversing the creation order changes which pair gets the first accepted result. [Competing pairs](../validation/2026-11-17-snaps-p07.md#rhino-5-native-int-across-competing-curve-pairs)
- The native apparent-pair check compares source separation on the near plane as well as world separation. Perspective uses rays from the camera through the source points. A projected crossing must recover the original source parameters. The off-axis fixture has a screen chord fraction of 4/9 for a 3D Line parameter of 0.5, and its two source points return distinct World X coordinates after Project. [Perspective fixture](../validation/2026-11-17-snaps-p07.md#apparent-intersection-in-perspective)

## OM9 behavior and verification

- For Grid Snap plus Ortho, OM9 uses grid-quantized coordinates to select the 45-degree direction, then projects the raw pointer onto that direction and selects the nearest crossing with an X or Y grid line. Explicit coordinates bypass both pointer constraints. [Approved rules and replay](../validation/2026-11-17-snaps-p07.md#approved-grid-snap-plus-ortho-and-planar-plus-project)
- At an exact negative half-step with Grid Snap alone, OM9 replay yields `-2.5` for raw X `-2.25` and a 0.5 mm step. The Rhino 5 ordinary grid helper yields `-2.0` for that input. Updating the standalone tie rule is pending approval. [Half-step probe and binary trace](../validation/2026-11-17-snaps-p07.md#standalone-grid-snap-negative-half-step)
- Planar uses the current input plane's orientation and a parallel plane through the current point base. The base is recalculated after accepted points and for Between's second point. A standard command session retains its captured input plane; other point consumers use their active input plane. Changing views does not retroactively move an accepted point.
- For free pointer input, Planar sets the height through the current base. For an object-snap result, Project uses the Planar height when an accepted base and both settings are present. SDK callers supply it as `base_mm` in `SnapConstrain` or as `from_mm` in the query that issues their hit. For equal hits in the same context and invocation, the latest matching query supplies the base.
- A surface target is selected using the actual source pick. With Project also enabled, a later projected pick is accepted only after a witness confirms it lies within document tolerance of the selected surface. When the original and projected points are farther apart, an asynchronous source-membership query supplies that witness; an inconclusive query is reported. This path does not search for another point on the surface/CPlane intersection.
- OM9 implements an opt-in apparent Intersection fallback for visible straight segments. Its native-feature worker also handles circular arcs and supported positive-weight rational NURBS, including Perspective curves with a visible crossing and controls extending behind the camera. The O-Snap context menu and `ApparentIntersections On/Off` change the same session setting. For each supported pair the solver tries the true point first, evaluates both source points at the screen crossing, and uses the selected source before Project. The marker says `Apparent Int`. The setting starts off. OM9 replay verifies the creation-order effect for three newly authored Lines at one pixel and preserves it through archive reopen. Direct Matrix9 observations and live preference restoration remain open. [Perspective replay](../validation/2026-11-17-snaps-p07.md#apparent-int-on-a-partly-visible-perspective-curve) · [Competing pairs replay](../validation/2026-11-17-snaps-p07.md#om9-creation-order-for-competing-intersections)
- SDK callers request `apparent_intersection` to allow the same projected fallback in a snap query. The issued result includes both sources and the selected unprojected World point. `snap_constrain_hit` applies Project when the add-on consumes the issued point in the same invocation. [SDK replay](../validation/2026-11-17-snaps-p07.md#apparent-intersection-through-the-sdk)
- The default viewport worker reports an Int candidate on a joined Polycurve using the normalized traversal fraction of that Polycurve. Nested and reversed segments map into the original source range. Apparent Int follows the selected constituent even when both branches share one source identity. [Reversed Polycurve replay](../validation/2026-11-17-snaps-p07.md#intersection-parameter-on-a-reversed-polycurve)
- The synchronous scene path uses the same Polycurve traversal ranges for its supported curve pairs. It recovers the original fraction of a degree-one rational NURBS from the active span's endpoint weights. [Scene test coverage](../validation/2026-11-17-snaps-p07.md#scene-intersection-source-parameters)

Windows OM9 also recorded the two `Apparent Int` heights with Project off and on. Matrix9 desktop coordinates and the human M02-UI gate remain open.
