# Clipboard metadata and preservation checkpoint

The selected OM9 archive retains self-contained gem, mesh UV, trimmed-surface and extrusion extensions. Gem IDs are remapped to the pasted object or block member. External textures, unknown extensions and unsupported history or feature dependencies are rejected instead of silently discarded. Tests cover cross-document gem copy, nested-block gem identity, malformed gem data, UV and the self-contained surface/extrusion records.

Four-rail profile metadata is supported when all four referenced rail curves are selected along with the profile: references are remapped to the pasted root identities, with Undo and Redo tested. Selecting the profile without all rails is refused; copying unselected dependency curves automatically remains open. Referenced material and line-pattern records on selected entities and their layer ancestors now transfer to the destination in the paste transaction. Identical destination records are reused; conflicting IDs get new records and remapped references. Tests cover direct and layer references, collision preservation, repeat paste, Undo/Redo, malformed identities, duplicate and stale transactions. Other exchange record families remain out of scope for this slice.

Following this change, all 17 clipboard integration tests passed with the authenticated native exchange adapter and the application debug build succeeded using `-j 2`. The public-source audit reported zero errors and artifact pruning removed no runs.

After adding material and line-pattern transfer, 17 clipboard integration tests plus one transaction admission test passed, including the authenticated native exchange cases; the expanded repeat-paste test also passed separately. The debug application built with `-j 2`; the public-source audit checked 14,975 files with zero errors, and artifact pruning removed no runs. These checks do not constitute a new desktop UI or Rhino interoperability test.

OM9 feature records whose complete output set is selected are now captured and pasted with fresh feature and output identities in the same transaction. Partial feature selection is rejected. Detached History outputs are explicitly rejected too, rather than losing their recipe during capture. Nineteen clipboard integration tests, one transaction admission test and 31 document-graph regression tests passed, including native exchange fixtures. The application debug build succeeded with `-j 2`, and the public-source audit reported zero errors; no new desktop or Rhino test was performed.

Clean history recipes and current published results now transfer when every referenced input and output is selected and no semantic subshape references are present. Recipe IDs, output IDs, input stamps and member selections are remapped; the paste is one transaction. Pending input stamps and typed ports are rechecked against the staged document before publication. Incomplete selections, non-clean recipes, stale/unowned results and semantic references remain explicitly unsupported. Fifty-five clipboard, transaction, history and associative regression tests passed across five suites, including native exchange fixtures. A further focused Redo reference check passed; no new actual Rhino or desktop test has been made.

For 3DM paste, a paired layer sidecar is accepted only after its digest and its object/layer identities, hierarchy, colors and flags are verified to agree with the inspected native 3DM. A mismatched sidecar, current-layer state or unsupported persistent flags rejects the paste before the transaction. This is not a general source-wins layer merge.

Windows OLE backup can duplicate a CF_BITMAP GDI handle and stream media with bounded size. Detached data-object tests checked bitmap and stream bytes after releasing their sources without writing the interactive clipboard. A separate read-only snapshot of the then-current interactive image clipboard succeeded; it did not test publication or restoration. Other OLE media remain unsupported and cause publication to fail before replacing the prior clipboard.

Validation on Windows: 22 app clipboard and pinned-command tests passed with the authenticated native exchange adapter, four native-owner clipboard unit tests passed (three interactive tests excluded), and the debug application built with `CARGO_TARGET_DIR=L:/om9-target` and `-j 2`. Public-source audit: 14,974 source files, zero errors. The pruning tool retained cited old runs and removed none. These are simulated/native adapter checks, distinct from the earlier limited desktop checks.

Previously verified desktop checks covered line-copy shortcut status and text paste in a separate Windows debug window; these do not establish comprehensive geometry or real Rhino 5 interoperability. Real two-way Rhino 5 clipboard exchange remains unverified. The application must still preserve or explicitly reject remaining dependent metadata, and broaden real-world clipboard and desktop validation.
