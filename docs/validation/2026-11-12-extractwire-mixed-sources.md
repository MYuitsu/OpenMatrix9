# ExtractWireframe on mixed source types

Before the change, selecting a B-rep Box, triangle mesh and standalone open NURBS plane together returned `Invalid("edge extraction B-Rep")`. Multi-root extraction now prepares supported B-rep, mesh and open-surface source edges under a shared reservation and publishes them in one transaction. It preserves the source placement for mesh and surface outputs and retains the existing B-rep placement behavior. Non-supported types, closed/periodic surfaces and degenerate mesh edges still refuse the entire operation.

For a saved/reopened Box, translated triangle mesh and translated open plane, both the CMD and menu dispatcher paths produced 12, 3 and 4 edges respectively. The fixture checks independent midpoint coordinates for the three source types, output save/reopen and one Undo/Redo. A second reopened fixture forces the B-rep to be processed before a mesh with a zero-length edge: the command fails without publishing partial output or losing existing Redo. A valid Box/mesh fixture with simulated managed-memory exhaustion also retains document and Redo, then succeeds after pressure is released and can be undone. An egui-handler test checks the warning/retry path after simulated pressure is released without deleting an unnecessary Undo step.

The wireframe integration suite passed 51 tests with four diagnostics ignored, six Curve menu tests passed, and the mixed-selection recovery handler test passed. The debug application build and no-default-features check passed; the public-source audit reported no errors. These tests do not establish behavior for all imported shapes, arbitrary affine placements or all combinations and sizes, physical mouse interactions, physical RAM exhaustion, or native peak memory. Source-preparation reservations are conservative; no desktop timing has been established. The change does not implement source-only restore or display eviction.

## Mixed affine placement and downstream Length

A separate reopened fixture selects an OCCT Box with nonuniform scale and shear, a triangle mesh with reflection and shear, and a planar NURBS surface with scale and shear. ExtractWireframe produces all 19 expected unique edges in one transaction. Their endpoint pairs are compared with independently transformed source corners; output entities retain the corresponding source placements. Undo/Redo restores the documents. After saving and reopening the outputs, Length on one edge from each source type matches its independently calculated world-space endpoint distance. The Wireframe suite passed 56 tests, five ignored (including the known pending conical-apex regression), and six Curve menu tests passed. This is one set of transforms and straight edges; curved mixed-source outputs, near-singular matrices, physical desktop and native peak remain unverified.

## Actual executable, mixed closed surface

A separate-process test launches Cargo's actual debug `om9` executable with `--mcp` and opens an authored saved document containing a Box, a translated triangle mesh and a translated closed cylindrical NURBS surface. It selects all three, runs `ExtractWireframe`, observes 3 → 21 objects, Undo → 3, Redo → 21, saves the result and reopens it independently. The three source entities remain unchanged. The 18 outputs comprise 12 unique analytic Box edges, three distinct expected mesh edges, and two circular ends plus one seam on the cylinder; their placements and sampled points are checked. The complete MCP stdio suite passed nine tests with one unrelated desktop-result inspection ignored. This is an actual executable and file roundtrip, not a physical menu or pointer test, the user's live window, a full-curve proof or native peak-memory measurement.
