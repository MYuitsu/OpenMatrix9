# Top11 Join: independent polycurve domains in 3DM

An authored test first reproduced a failure exporting the result of joining oppositely directed lines with domains `[2,5]` and `[7,12]`: native writing refused noncontiguous segment domains. OM9 evaluates a polycurve using equal fractions per segment. The selected openNURBS adapter now gives an `ON_PolyCurve` equal parent intervals independently of the exact domains of its child curves. It appends a unit-domain copy and restores the original child through openNURBS `CopyFrom`, avoiding a repeated rescale of all previously appended segments. This native C++ work is limited to the required openNURBS serialization API; document and command logic remain Rust-owned.

The real-native Join test now exports and imports successfully. A separately built authored-fixture executable cold reads the 3DM, inspects each parent and child domain, and evaluates nine points directly on the native polycurve. These are compared with OM9's independent fractional evaluation and the imported segment geometry. Additional real-native tests cover a line/arc polycurve and five line segments with varied domains. The test scope is authored fixtures, not a proof for every segment type, nesting depth, extreme numerical range or external Rhino application.

An imported native polycurve can instead have unequal parent intervals: mapping it onto OM9's equal-segment fractions would silently change evaluation. An authored native counterexample with parent intervals `[0,1]` and `[1,3]` is now retained without geometry projection and receives a diagnostic; cold inspection likewise produces no projected geometry. Equal-parent comparison allows eight machine epsilons of relative difference for `ON_PolyCurve`; polyline parent widths are checked exactly. This protects parameter fidelity but does not implement a host representation for arbitrary unequal parent intervals. Reversed polycurve metadata and general UV mesh transfer remain separate limitations.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target`, `-j 2`: four explicitly invoked real-native polycurve fixture tests passed, including the unequal-parent refusal; all nine explicitly invoked native staged-export tests and six mirrored geometry/BRep integration tests passed on the final build.
