# STL capture session identity, 2026-11-04

The STL options lifecycle used to cancel a capture only when the persistent document UUID changed. Reopening the same file retains that UUID but creates a fresh runtime session, so a replacement through the Controller outside the normal menu path could leave the previous session's pending export available. A capture now compares document ID, runtime owner session and session generation when the UI checks it. The Controller's admitted synchronous captured-export route also rejects a capture from a previous session before obtaining its export permit or touching the destination. Edits, selection changes and Undo/Redo retain the captured immutable source within the same session, as required; New/Open/close UI cancellation remains in place.

A headless egui/Controller fixture saves a mesh document, captures it, edits, undoes and redoes while confirming the capture survives, then opens the same file through the Controller. It confirms the UUID is unchanged but the runtime owner changes, direct Controller export refuses the old capture and preserves an existing STL byte-for-byte, and the next UI frame clears the pending capture and options. The previous UUID-only condition would not detect this same-file replacement. Another existing menu/New capture test passed before the final Controller-guard addition. The full 60-test `stl_export` integration suite passed, including canonical sources, placement, open surfaces, encoded topology, cancellation and existing target preservation. E: default-feature debug target, Cargo `-j 2`, OCCT runtime: UI build 28.19 s and test 0.51 s; STL integration build 25.31 s and tests 118.02 s.

At that stage a detached `StlExportCapture::export_with_profile` had no current Controller session to compare, and the experimental background worker was not canceled by that check. The follow-up below addresses session invalidation for those routes; the worker remains outside the UI and aggregate native-memory admission remains open. This is not a global STL accuracy certification, a real desktop interaction test, or evidence that the 512 MiB checkpoint or full plan is complete.

## Session invalidation through final publication

Each Controller owns an export-session token shared by its captures. Successful New/Open, snapshot or Master replacement invalidates the previous token; a failed New does not. A window close request invalidates the current token and creates a new generation so a user who cancels closing can export again. Ordinary edits, Undo and Redo do not invalidate it. Detached exports and the experimental `StlExportJob` bind their cancellation checks to this token. Invalidation and the last staged-file rename take the same session mutex: if invalidation wins, publication returns canceled; if rename holds the guard first, it can complete before replacement/close proceeds. OCCT calls already underway are not forcibly interrupted, so cancellation can be delayed until the call returns. The permit and RAM reservation remain held until the worker exits.

A controlled worker uses a real encoded triangle and pauses after verification but immediately before acquiring the publication guard. New and a simulated close invalidation each occur during that pause; both tests return canceled, leave an existing destination unchanged and release the worker reservation. A separate Windows egui close test verifies the actual close-request path cancels a detached capture and permits a fresh export after the user cancels closing. Same-file Open checks pending UI, Controller and detached captures; failed New retains a usable capture; snapshot and Master restores invalidate old captures. The race tests deliberately gate a helper worker at one boundary; they do not exhaustively prove every thread schedule, real OS failure or desktop timing.

With default features, E: debug target, `-j 2` and OCCT runtime: 40 cancellation tests, the same-file UI fixture, Windows close fixture and 11 document-contract tests passed; 60 STL integration tests passed in 122.42 s after a 3.55 s build. A subsequent test-only follow-up tested the two New/close publication races (28.67 s build, 0.01 s tests). An initial build used an incorrect test-only dialog enum and was corrected; an early race fixture retained its capture outside the worker, so its 16-byte selection lease correctly remained live until the fixture moved the capture into the worker. At this stage detached export had no aggregate shared RAM reservation; the [later partial admission](2026-11-04-detached-stl-shared-reservation.md) still leaves live scene and other owners incomplete. The worker is not integrated into the UI, and native OCCT peaks, responsive cancellation inside OCCT, global accuracy and desktop validation remain open.

## Controller owner destruction

The experimental headless MCP server can replace its Controller directly rather than using the GUI's New/Open swap. A Controller-owned RAII token now invalidates its export session when the Controller is dropped; captures and workers retain the token but cannot keep it valid. This uses the same session mutex as final STL publication. Candidate construction or Open failure leaves the current Controller alive and therefore does not cancel its capture. This also covers ordinary standalone Controller destruction; it does not change the separate RAM-admission gap for a detached export while its owner is alive.

Default-feature E: debug checks with `-j 2` and OCCT runtime: 42 STL cancellation tests passed (28.21 s build, 0.12 s tests), including controller destruction, failed New, session replacement and controlled New/close publication races. A headless MCP unit fixture confirmed failed Open retains the capture and successful New invalidates it without changing the STL destination; the Windows close fixture and 11 document-contract tests passed. Six `stl_export` capture-filtered integration tests, including the experimental worker and retained old-capture accounting, passed (3.43 s build, 0.08 s tests). The previous 60-test suite predates this RAII follow-up. No real desktop shutdown, native cancellation timing or process-wide RAM peak was measured.
