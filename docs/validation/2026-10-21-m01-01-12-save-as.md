# Save As through SDK v1 — 2026-10-21

A plugin can now ask the host to start its own Save As flow after the command commits, so the
user — not the plugin — chooses the destination. This is the second file-lifecycle slice at
`OM9-L2-01-12` (`OM9-L3-01-12-005`); it deliberately does not give the plugin a path.

## Changed

| Layer | Change |
|---|---|
| Public SDK | `Host::save_project_as` and `SaveProjectAs`; capability entry. |
| Host | `PluginRun.save_as`; `save_project_as` stages the flag, and combining it with `save_project` in one command is a `save` refusal so the order is never ambiguous. |
| App | After a successful publish it calls `begin_file_operation(FileKind::SaveAs)`, which starts the host path dialog and performs the existing atomic save once the user answers; a busy file operation becomes a `Warn` event, not a command failure. |
| Example plugin | `ProjectDemo` supports `{"save_as":true}`. |
| Tests | Host test for the staged flag, the untitled-independent Save As request and the save/save-as combination refusal; native DLL test that runs `ProjectDemo {"save_as":true}`, confirms a `SaveAs` operation is pending, accepts a destination, and reopens the written `.om9`. |

## Semantics fixed by this slice

- The plugin requests the host flow; it never sees, supplies or writes a path.
- The command's transaction commits before the dialog starts, so the document is consistent
  while the user picks a destination.
- `save_project` and `save_project_as` are mutually exclusive in one command (`save`
  refusal); a plugin cannot queue two conflicting file outcomes.
- Accepting the path performs the same atomic archive save with fingerprint/receipt as the
  host Save command, and the document becomes clean only after that save.
- A busy or failed host file operation is a `Warn` event; the committed command stays
  committed.

## Not proved here

- The interactive path dialog itself is host UI; the native test accepts the destination
  programmatically. UI acceptance was not performed.
- Write-failure recovery (disk full, partial file) was not re-exercised through the plugin
  path.
- Plugins still cannot open, create or replace a document.
- macOS host and plugin execution are unverified. No manual or M09 gate was promoted.
