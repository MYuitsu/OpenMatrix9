# Hover worker shared-buffer lease — 2026-11-05

The background hover picker used to reserve the entire scene again despite sharing render-buffer `Arc`s with the viewport. It now acquires the same Controller buffer lease as viewport preparation and reserves only its independent snapshot metadata and estimated picking scratch. Hover still requires a physical RAM sample and checks it when admitting a new buffer owner and its worker scratch. The worker drops its scene snapshot before releasing its captured document, buffer lease and scratch reservation.

The controlled 64 MiB managed-budget fixture uses a 40,000-vertex mesh and leaves enough space for hover metadata, picking scratch and only half another buffer. A viewport buffer owner and hover worker obtain the same lease and hover admission succeeds; after New replaces the document, the old snapshot remains charged until the worker owners are released. This tests ownership under managed-budget pressure, not real OS exhaustion. A separate 130-object simulated UI hover test verifies a failed admission retries after pressure clears and that worker-only reservation is released while the live scene's buffer lease remains.

Default features, OCCT 8.0.1 runtime, E: debug target, `-j 2`, serial: ten `hover_` tests passed including delayed stale-result rejection and pressure recovery; five viewport snapshot owner, 20 OSnap UI, 11 gesture and 27 offscreen GPU/egui tests passed without GPU skips. OSnap tests took 21.51 s and the GPU suite 54.26 s. The first build failed from an unqualified fixture type, then the first test run reported the older assumption that all CPU cache reservations drop to zero after hover. The assertion now verifies that only the precisely calculated live scene buffer/owner charge remains, and the rerun passes.

## Limits

Picking scratch is an estimate and does not bound every sorting/evaluation allocation. Current buffers register at the first viewport or background-hover capture, rather than during startup, and complete scene rebuilds and other workers may still cause duplicate accounting. Snapshot metadata remains independently reserved, and physical free-memory policy may conservatively charge already allocated buffers again. No process-wide 60% guarantee, actual desktop pointer latency, real OS pressure, current-source release timing or native OCCT bound is established.
