# Vulkan selected-device GPU memory sample

P2 partial: the Windows native owner queries `VK_EXT_memory_budget` through the exact wgpu Vulkan adapter/device HAL guards, verifying that both share the same Vulkan instance and physical device. It reads the extension only when enabled on that device. The sample reports per-heap size, OS/driver budget and usage plus `DEVICE_LOCAL` and `HOST_VISIBLE` capabilities. If the backend or extension is unavailable, or handles do not match, it returns no sample. An enabled interaction log records the sample once at application startup. DX12 retains its existing DXGI path.

Windows, `CARGO_TARGET_DIR=L:/om9-target`, Cargo `-j 2`: three native-owner GPU-memory tests passed with real DX12 and Vulkan adapters, including a matching Vulkan device. The Vulkan test observed two heaps: a 12,701,401,088-byte device-local and host-visible heap with an 11,896,094,720-byte budget, and a 34,317,656,064-byte non-device-local host-visible heap with a reported 50,650,140,672-byte budget. These are point-in-time test-process samples, not a calculation of usable capacity or proof of the adapter in the user's open window. One offscreen four-viewport reuse test also passed.

`HOST_VISIBLE` plus `DEVICE_LOCAL` does not by itself prove UMA; it can also describe host-visible discrete GPU memory. Heap budgets can differ from heap size, as observed above. No UMA classification, deduplication with system RAM, 50% cap, dynamic budget refresh, allocation accounting, eviction or full-scene batch rendering is implemented here. Unavailable-extension fallback and mismatched-device behavior are coded but were not both exercised on distinct hardware in this run. Desktop present timing and release performance remain open; the active OM9 session was not changed.
