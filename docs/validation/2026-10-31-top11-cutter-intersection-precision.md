# Top11 Split/Trim: cutter intersection precision

On a one-million-mm line, a cutter 0.05 mm from its start was discarded by a fixed fractional cutoff. Split rejected it; Trim could treat it as an endpoint and delete the entire target. Two cutters 0.05 mm apart could also be merged by a fixed `1e-6` fraction threshold. The application now classifies endpoints and merges adjacent intersection fractions using document tolerance along the placed curve. It first compares world-space points, then measures the intervening curve length when necessary; this avoids merging a self-retracing curve's distinct parameters merely because their positions coincide. Lines use direct world distance, including numerically identical points.

The Rust core and controller share this normalization. OCCT's adapter now retains distinct in-domain native intersection fractions instead of combining all hits within `1e-7` of the curve fraction; Rust performs tolerance-aware deduplication after the native call. Exact duplicate native fractions are still removed in the adapter. The C++ exception is confined to the required OCCT intersection interface; curve classification and tolerance logic remain Rust-owned.

Regressions cover CMD and toolbar Split using two near-end cutters, an additional cutter within document tolerance, Trim of the long side, Undo/Redo and `.om9` persistence. Core tests cover nonuniform placement, tolerance duplicates and two distant parameters at the same position on a retraced polycurve. A 0.05-mm-thick OCCT box cuts a long line at both faces, and both Top11 invocation paths retain three pieces. A real-native 3DM fixture exports/imports the line-cut Split result for both paths and checks the three lengths.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target`, `-j 2`: 116 app Top11 tests, 83 Top11 BRep tests, 33 core Top11 tests, 204 core library tests, 116 no-default app Top11 tests, and six OCCT ellipsoid/extrusion tests passed. The first direct kernel test invocation omitted the `3dm-brep` feature and failed to link two 3DM symbols; the correctly configured `--features 3dm-brep` run passed. During development the ellipsoid suite exposed coincident line fractions that could create a degenerate temporary line; the direct line-distance branch fixed that regression and the suite passed on rerun. Existing no-default unused-code/import warnings remain.

Native 3DM adapter SHA-256 `bddca46577747333f9377b379351a077b710158f47ce6e279d7b6e21e6439615`. These are command, OCCT and 3DM interoperability checks, not openNURBS measurement batches. General intersection solvers, closed/self-intersecting curves, extreme scales, numerical arc-length error bounds, all other BRep topology and actual desktop input remain incompletely verified. The adapter has a finite native hit capacity and reports overflow rather than silently truncating.
