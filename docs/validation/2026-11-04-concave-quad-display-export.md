# Concave authored quad: display, picking and STL

The scene previously triangulated every quad as a fan from its first corner, while STL selected an interior diagonal. For the authored concave quad `[(0,0), (1,0.5), (2,0), (0,2)]`, the scene included an area outside the polygon and used different triangles from STL. The diagonal selection now lives in Rust core and is shared by scene buffer generation and STL export. Valid concave quads use the interior diagonal in both paths; the native mesh-face ID remains the original face index.

A document-to-STL test compares the displayed triangle coordinates to the encoded triangles, verifies a point in the concavity is not picked, and verifies an interior point and the original face ID are picked. The prior crossed-quad STL rejection remains. For an invalid or crossed quad, scene generation intentionally retains its former fan fallback while STL rejects it; this is not a general polygon repair or nonplanar-surface certificate. No display mesh or source geometry is persisted or changed by this fix.

On E: with `-j 2`, 12 scene acceptance, 4 scene admission and 4 subobject tests passed; 58 STL export, 12 selection overlay, 11 gesture and 19 B-rep picking tests passed. The final face-ID assertion was added after the full STL run and passed in a focused quad rerun, together with the existing axis/winding quad test. The 26 GPU publication tests passed serially; their captured output was truncated, so no assertion is made about adapter-skip messages in that batch. Public-source audit passed. A physical desktop check remains open.
