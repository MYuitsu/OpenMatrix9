# Sphere history proof: partial integration, 2026-11-10

The production Sphere insertion can now retain its already admitted topology proof in the insertion history entry. On a cache miss the controller can retrieve a matching proof from Undo/Redo history; source, topology, object and session identities are checked and the native proof is validated before use. The proof is optional: refusal to retain it leaves the committed Sphere and its v4 display intact. The entry still owns the original document and display.

History inventory counts a history-exclusive proof once and excludes an externally shared owner. Deferred release moves evidence out of discarded Redo or trimmed Undo before the memory-account mutex is released, then drops the proof and its reservation outside that mutex. Temporary release storage is itself admitted. If admission fails, publication is refused without changing the document or Redo. Closing a document removes the associated evidence and updates its inventory counters.

Validation: core library 360 passed; app topology-owner group 50 passed and two ignored (native 3DM environment and isolated timing probe); app Sphere filter 18 passed. The real Sphere fixture removes the optional proof cache, uses Undo and Redo, remeshes using the history proof, and verifies that discarding the Redo branch releases it. Focused core tests cover external and snapshot owners, history-exclusive inventory, Redo discard, Undo trimming, scoped publication, admission refusal and document close. Public-source audit and diff whitespace check passed.

When quota trimming removes an evidence-bearing entry, the core now moves that owner without allocation to a later vacant entry whose before/after state contains the same document, session, object generation, source allocation and topology allocation. A core fixture trims an insertion, restores the deleted object via Undo using the moved evidence, then trims the final recoverable version and verifies that its reservation is released. Another fixture replaces the source twice and verifies the old evidence is not transferred to a different version. The five focused history-evidence tests passed; the earlier full core run passed 360 tests and the app topology group passed 50 with two ignored after the implementation change.

A production-controller native Sphere fixture passes after removal of the optional cache and quota trimming of the insertion. A two-Sphere fixture initially reproduced proof loss when both insertion entries were trimmed. A coordinator-owned, admitted overflow vector now retains multiple proof owners when a matching history entry already contains evidence; it also rehomes evidence when a Redo branch is discarded. The regression now passes through Undo, remesh of both native Spheres and a new branch. Core tests cover two owners, snapshot, close, release and refusal to allocate the overflow storage without changing document or history. Core 363 and app topology 52 passed; two topology tests requiring a separate environment remain ignored.

The coordinator now also keeps an already retained proof when its source is present in the current document even if all journal entries are cleared. A proof for a current source is excluded from the Undo-specific quota while its reservation remains charged globally; once the source is absent from both the current world and recoverable history it is released outside the memory-account lock. A native Sphere fixture clears history through an unrecorded transaction, remeshes with the optional cache removed, then deletes the Sphere and verifies proof release. This fixture exercises coordinator and controller behavior, not a desktop command for clearing history. Core 364 passed and app topology 53 passed with two environment-dependent tests ignored.

Sphere production now prepares and validates the shared proof, tries to retain it with the insertion history first, and only then tries the optional cache. A simulated cache refusal on the production Sphere path retains the proof across Undo/Redo and remesh. A separate native Sphere helper fixture exhausts the actual shared account after retaining the proof, verifies cache admission refuses without changing the coordinator, releases pressure and remeshes from the retained proof. The real-pressure fixture exercises the same retention/cache functions in that order but does not inject pressure inside the synchronous production command. App topology 55 passed with two ignored, and the Sphere filter passed 23. A failure to prepare or retain proof can still leave a valid Sphere with v4 display only.

After successful remesh publication or a validated cache hit, the controller now retries retention of an already verified current proof. The coordinator uses admitted overflow storage, deduplicates the same owner, leaves document and history entries untouched, and marks Undo inventory for later reconciliation. A production Sphere fixture simulates refusal of initial history retention, performs an intervening Point edit, remeshes using the still-cached native proof, removes the optional cache and verifies proof through Undo/Redo. A core test checks real storage refusal preserves the snapshot, later retry succeeds, duplicate retry is idempotent and deletion releases the reservation. Core 365 passed; app topology 56 passed with two ignored. This cannot recreate a proof that has already disappeared, and a retry can still fail under pressure.

Closing a document previously discarded every shared journal entry touching it, including evidence for a different document still open. Close now transfers evidence from removed entries into the already admitted overflow storage before pruning owners with no remaining current or historical source. A two-document core fixture verifies that closing the first document removes the shared Undo entry while retaining the second document's proof, and closing the second releases its reservation. Core 366 passed. An additional native Sphere controller fixture builds a two-document transaction, closes the other document, refreshes the scene, and remeshes using the retained proof. Its native fixture construction uses an unrestricted test callback, and it does not establish desktop multi-document behavior or native peak admission.

On an optional-cache miss with no explicit object, production previously scanned the history separately for each current entity. The coordinator now scans evidence once, validates each candidate against its current document/source/topology and lets the caller filter proofs, choosing the lowest matching object ID. If an earlier candidate for an object fails the display filter, the scan can now consider another matching candidate for that same object; actual remesh still performs full proof validation. Core coverage checks ordering and filtering with two owners; the two-Sphere native fixture verifies selection after removing the optional cache. This is an algorithmic bound rather than a measured latency result; document lookups and proof filtering still contribute cost. It does not add source-only restoration or alter the strict Undo participant comparison.

A core regression now exercises the strict participant boundary with two individually valid BReps sharing identical source and topology IDs but having different display fingerprints. Without a provenance receipt, replacing the current display is rejected as a stale Undo participant and leaves world, Undo and Redo unchanged. This is a portable synthetic fixture, not native attestation or a positive source-only restore. It guards against weakening comparison to source hash or UUID equality alone; a future restore must carry proof that ties the regenerated display to the expected history version and must still reject this fixture.

Sphere proof evidence can now retain its separately tracked source/topology lease; the remesh worker reuses a clone of that same lease after validating the current proof and account. An admitted Undo inventory index distinguishes leases held only by evidence from additional worker or snapshot readers. It counts shared history source/topology allocations once and accounts a source held by evidence even when a synthetic journal fixture has no BRep document owner. Handle clone/drop increments the capture generation so a clone/drop ABA invalidates concurrent inventory. Core fixtures verify shared-owner deduplication, external-reader and snapshot transitions, foreign-account and wrong-source rejection, synthetic source-only inventory and race refusal; a native Sphere fixture verifies the worker path shares the retained lease. Core 370 and app topology 58 passed, with two environment-dependent app tests ignored.

This source/proof attachment is optional: admission can fail and leave the v4 display fallback. Current document and history BReps still retain display; the synthetic inventory fixture is not a valid, restorable source-only history record. Source-only Undo restoration, safe cache eviction, complete v4 handling, large-model latency, native peak and desktop remain unproven. The accounting relies on all source lease readers using tracked handles; the caller must still validate the native proof before attaching it.

Limits: proof attachment is best effort, so a Sphere created under pressure or loaded from v4 need not have proof; merely keeping existing proof does not provide attestation for every version. The cache and history can both own a proof, in which case the proof is excluded from the Undo-specific quota although its reservation remains charged to the shared memory account. A conservative bound prompts re-inventory near the quota, and inventory reports reconciliation pending while evidence exists. The overflow capacity is admitted and included in Undo inventory; infallible diagnostic snapshots clone its metadata without their own admission, like existing snapshot metadata. Rehoming and pruning scan history and may be costly with many objects and entries; per-publication deferred-release scratch adds allocation/admission work. Large-model latency, peak memory and desktop behavior are unmeasured. The core evidence API relies on its caller to supply a correctly accounted owner and byte count; the Sphere caller validates its native proof and reservation.

This does not implement source-only document or history, display eviction, a fully attested v4 recovery path, or M1 completion. Do not enable eviction until every recoverable history branch retains or can restore a validated proof and the memory/Undo behavior is established under pressure.
