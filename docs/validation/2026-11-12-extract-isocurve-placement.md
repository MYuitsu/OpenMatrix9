# ExtractIsocurve placement after save/open

Default parameter follow-up: on a saved/reopened planar surface whose V domain was trimmed to `[0.2, 0.4]`, entering ExtractIsocurve and pressing Enter previously failed because the fixed default `0.5` was outside that domain. The default is now the midpoint of the selected surface's V domain for the initial U-direction curve. The fixture verifies three world-space points on the expected line at `y=3`, then Undo and Redo; all 11 Isocurve integration tests passed. This is one planar trimmed-domain fixture, not certification of all parameter domains or desktop interaction.

Input follow-up: lowercase `u=` and `v=` now use the same parsing as their uppercase forms. On a planar fixture, each lowercase option produced the same curve as its uppercase counterpart and Undo/Redo restored the document. The complete Isocurve integration suite passed 10 tests; desktop keyboard entry was not checked. The user previously declined updating reusable guidance for the pending retry change, so it remains unchanged.

A standalone planar NURBS surface with translation `[10, 20, 30]` was saved and reopened. Before the fix, `ExtractIsocurve`, `V=0.5`, Enter produced a curve at local `[5, 0, 0]` rather than the source's world point `[15, 20, 30]`. The command now retains the selected surface entity's placement with the extracted curve.

The regression uses the reopened plane with translation and with a scale/shear plus translation. Five points of each resulting curve are checked against the transformed source surface; one Undo and Redo restore the respective complete documents. This comparison uses OM9's curve/surface evaluators and does not independently certify all NURBS geometry. Three isocurve, 17 DupBorder and six curve-menu tests passed; `cargo check -p om9-app --no-default-features --target-dir L:/om9-target -j 2` passed with existing warnings.

An additional reopened standalone cylindrical surface with scale/shear and translation was tested in both parameter directions. Six samples of the circular isocurve satisfy the analytic radius and height, and six of the longitudinal isocurve satisfy the analytic line; placement and Undo/Redo also passed. The resulting batch has four passing isocurve tests and two known-issue tests ignored as described below. This is evidence for one cylinder, not all curved surfaces.

The fixtures exercise the CMD path on single standalone surfaces. Other curved and trimmed surfaces, B-rep input, the actual desktop menu, arbitrary transforms and pending-command failure/retry are not certified. ExtractWireframe is a distinct command; this fix does not implement its missing displayed isocurves or its standalone-surface support.

Follow-up: two intentionally failing tests exposed that an out-of-domain parameter or simulated memory pressure exits the pending ExtractIsocurve command. In both observed cases, the document snapshot and existing Redo remained intact. The tests are temporarily ignored while awaiting the user's decision on retaining the pending input; the pressure fixture does not identify a more precise internal failure point. No retry behavior change is claimed.

**Later implementation:** the user approved retaining the session for retry. On isocurve construction or commit failure, the pending direction, parameter, surface and placement are retained; on success or Cancel the session ends. The captured source stamp is revalidated before extraction, and a deleted or changed source is refused. The previously ignored invalid-parameter and simulated-pressure tests now pass: document and Redo remain unchanged on failure, correction or retry succeeds, and Undo/Redo restores the output. Additional tests cover Cancel after invalid input and refusal after deleting the source during retry. All eight Isocurve integration tests passed. The pressure fixture does not identify the exact internal allocation failure; desktop and arbitrary source changes are not fully covered.

An additional focused test moves the source through a Gumball placement transaction after a failed attempt, then retries with a valid parameter. The source stamp check refuses the stale input and no curve or further document change is published; the user can cancel. Placement mutations increment `geometry_revision`, which is part of the checked source stamp. This verifies the moved-source fixture as well as the earlier deleted-source fixture; it does not certify all external mutation paths.
