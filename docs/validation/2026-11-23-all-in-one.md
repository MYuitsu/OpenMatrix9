# OpenMatrix9 all-in-one Windows and Apple Silicon builds

Windows x64 uses the existing standalone packaging flow. Cargo builds the isolated BRep restore and 3DM BRep workers before building OM9. The application embeds the digests of both worker images. The package builder verifies the images and checks their DLL dependency closure. The all-in-one variant adds the verified OM9 Matrix native add-on and Ring Sizes library to the normal read-only system add-on repository. Enable them through Tools → Add-ons on a new profile.

The macOS arm64 build uses macOS 15, the pinned OCCT 8.0.1 source with the existing accuracy patch, and the pinned openNURBS source. The .app includes dylibs, native 3DM exchange, both workers and the same two add-ons. Linked images use bundle-relative locations. Windows uses its existing native owner. Darwin uses a dedicated process group, bounded output, cancellation, a data-segment limit and physical-footprint sampling. The memory limit mechanisms differ by operating system. The Darwin staged file owner checks identity and bytes before atomic rename and coordinates cooperating processes through advisory locks.

The macOS workflow checks arm64 Mach-O architecture and ad-hoc signatures, then exercises the packaged BRep save and reopen path, 3DM export and reimport, and native add-on loading in a temporary profile. Developer ID signing, notarization and physical desktop verification require a separate release validation. Build results are recorded against the exact CI commit.
