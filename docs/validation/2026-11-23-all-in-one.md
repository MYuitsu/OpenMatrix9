Windows x64 uses the existing standalone packaging flow. Cargo builds the isolated BRep restore and 3DM BRep workers before building OM9. The application embeds the digests of both worker images. The package builder verifies the images and checks their DLL dependency closure. The all-in-one variant adds the verified OM9 Matrix native add-on and Ring Sizes library to the normal read-only system add-on repository. Enable them through Tools → Add-ons on a new profile.

The macOS arm64 build uses macOS 15, the pinned OCCT 8.0.1 source with the existing accuracy patch, and the pinned openNURBS source. The .app includes dylibs, native 3DM exchange, both workers and the same two add-ons. Linked images use bundle-relative locations. Windows uses its existing native owner. Darwin uses a dedicated process group, bounded output, cancellation and physical-footprint sampling with a lifetime peak check before accepting a worker result. The Darwin staged file owner checks identity and bytes before atomic rename and coordinates cooperating processes through advisory locks.

The macOS workflow checks arm64 Mach-O architecture and ad hoc signatures, then exercises the packaged BRep save and reopen path, 3DM export and reimport, and native add-on loading in a temporary profile. Developer ID signing, notarization and physical desktop verification require a separate release validation. Desktop geometry clipboard integration still uses the Windows OLE adapter.

## Windows runtime receipt

The locally built Windows x64 ZIP at candidate commit `661401f673a396dcd62f49b26077350c07cbf4f9` is 42,886,310 bytes. Its SHA-256 is `8503a4a4370a58f93f45a415b45a3a3a373ee9d3a93d1aef068e73194d9dbbbc`. The archive includes OM9 Matrix 0.9.5 and Ring Sizes 1.0.0. The executable starts from the extracted bundle with a system-only PATH, creates a Box, saves and opens the BRep project, exports and reimports Rhino 3DM, and loads both system add-ons in a temporary profile.

The batch 3DM import saves through the current project writer and retains exact Rhino BRep payloads. This avoids asking the v5 writer to encode canonical BReps and preserves the data before interactive topology work.

Python packaging and release tests passed 18/18. The native-owner Rust library and the application with developer fallback features passed an Apple Silicon cross-check. The latter compiles the platform application layer only. The full package uses the default OCCT feature and requires the native runner.

[Windows run #95](https://github.com/MYuitsu/OpenMatrix9/actions/runs/45115225948) passed the smoke test from the extracted ZIP and attested the package provenance. GitHub Actions recorded 42,653,299 bytes and SHA-256 `32aeb941634add203d3f7cbf795d4031d7953f09d1a3d4722977c1e7f919a183` for the outer artifact.

The first three macOS runs isolated patch line endings, a Windows SHA-256 call in the retained 3DM path, and the order of arguments to lipo. Run #5 compiled the full default-feature application, workers and add-on. Code signature verification flagged an add-on data file placed under Contents/MacOS, so the bundle now includes add-on assets under Contents/Resources and verifies the Matrix dylib signature separately. Run #6 identified the native 3DM digest as another resource that belongs outside Contents/MacOS. The digest now lives in Contents/Resources. Before signing, the build checks that every file under Contents/MacOS is an ARM64 Mach-O executable.

[Apple Silicon run #7](https://github.com/MYuitsu/OpenMatrix9/actions/runs/45102975617) passed those signature checks and reached the packaged runtime. Document startup failed because the shared memory admission guard had no Darwin physical RAM sample. The Darwin native owner now reads capacity through `hw.memsize` and estimates availability from Mach free and pageable file-backed pages, accounting for overlap with speculative pages. [Apple Silicon run #8](https://github.com/MYuitsu/OpenMatrix9/actions/runs/45106595840) checks the RAM sample and exercises the app after ZIP extraction at commit 56781bb7.

The v6 BRep Open route now holds a Darwin shared read lock for its regular file and checks the file identity after loading and before publication. The existing UI owners call AppKit panels for OM9 documents, 3DM, STL, project archives and folders, add-on ZIPs and viewport images. A native-owner-only build exposed the modal AppKit feature dependency hidden by eframe's unified features. [Apple Silicon run #10](https://github.com/MYuitsu/OpenMatrix9/actions/runs/45107954348) checks both the memory and file ownership paths at commit 35497f27 before the default-feature app build.

Apple Silicon run #8 verified the ZIP checksum and extracted signatures and created one OCCT Box BRep. The v6 Save route still rejected Darwin in the archive staging layer. That layer now shares the existing verified staged-file owner on both platforms. [Apple Silicon run #11](https://github.com/MYuitsu/OpenMatrix9/actions/runs/45110521417) uses commit 8dcee8ae and checks archive replacement before running the packaged BRep and 3DM smoke. The workflow saves the pinned native build inputs and outputs after the SDK step, keyed by the native source and Xcode version.

Run #11 passed archive replacement and reached the BRep save worker, which failed during startup with Darwin `EINVAL`. Run #12 reproduced the error even from a fresh launcher. The Darwin virtual-map data ceiling also counts existing mappings, so it is unsuitable for the worker's physical memory budget. The native owner now checks the sampled and lifetime physical footprint, kills over-budget workers, and reaps the process group before returning a result. [Apple Silicon run #13](https://github.com/MYuitsu/OpenMatrix9/actions/runs/45115225929) checks startup, output, timeout, cancellation, and footprint enforcement before building the package at commit 787afe9c.
