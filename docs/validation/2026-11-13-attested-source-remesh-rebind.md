# Remesh rebind of an attested canonical source

2026-11-13. The OCCT remesh path can find and rebind an existing native topology attestation by its exact canonical source and topology, without treating a replacement document display as attested. The source lease originates in a full earlier native proof; matching source bytes or hashes alone never creates that proof. Source rebind validates canonical integrity and admits the topology-validation scratch, retains session/account/object-generation checks, and marks the binding as source-only. APIs requiring the old display attestation reject that binding until the full display is validated again. The worker reconstructs and rebinds its new display against native descriptors before publication.

On Windows, using `CARGO_TARGET_DIR=L:\om9-target`, OCCT 8.0.1 runtime and `-j 2`:

- Product controller fixture: replacing a Box display with another portable-valid display while preserving exact source and topology leaves the original display proof ineligible; source rebind followed by remesh produces a 0.05 display with the attested topology. A source-scratch refusal leaves the current document, history and scene intact; changing topology IDs despite identical source text is refused. Remesh does not alter document, Undo/Redo counts or epoch. It may attach technical proof evidence to retained history; whole coordinator snapshots are therefore not byte-identical after a successful remesh.
- App `--lib topology_ -- --test-threads=2`: 161 passed, 6 ignored. App `--lib wireframe -- --test-threads=2`: 29 passed. These batches include stale, cancellation, proof retention, scene publication and GPU fixtures.
- Core lib: 386 passed, 1 ignored; kernel lib: 33 passed, 3 ignored. Kernel printed `File was not written with this version of the topology` after its success summary. Workspace check passed with two existing warnings, and app no-default-features check passed with 21 warnings.

This is a scoped source-only rebind for an existing in-process attestation, not a proof for arbitrary v4 or opaque NativeBrep input. Lookup and rebind still run source comparison/validation on the caller, while native remesh runs on a worker. Document and Undo still own display, general eviction and cold restore are not connected, `.om9` remains v4, and physical OOM, process/native peak and desktop behavior are not established.
