# STL authored mesh and generated degenerates

P3a partial implementation. Authored `Geometry::Mesh` vertices now retain their original index identities rather than being position-welded. Generated B-rep/native B-rep/surface vertices still use source-scoped distance welding. If generated vertices weld into a collapsed triangle, the triangle is omitted only when two original points are exactly equal; the receipt reports the count. A generated triangle with distinct original points that would collapse causes an error before destination replacement. Authored zero-area or quantization-collapsed triangles are not silently filtered and remain subject to writer validation.

Windows default features with OCCT, `CARGO_TARGET_DIR=L:/om9-target`, Cargo `-j 2`: `cargo test -p om9-app -j 2 --lib weld_tests` passed 2 tests; `cargo test -p om9-app -j 2 --test stl_export` passed 17 tests. Direct fixtures cover exact generated collapse, a near-but-distinct generated collapse being refused and authored points retaining their identity. A document export fixture independently reads an authored triangle with two vertices 0.0000005 mm apart and confirms that it remains in the STL. Existing integration fixtures cover generated sphere/B-rep and native B-rep behavior. The exact-generated-omission count is directly checked in the weld test; its application receipt warning has not been separately exercised by a fixture.

Generated B-rep/surface welding still uses distance, not proven kernel seam or shell identity: nearby unrelated generated points can merge without collapsing an individual triangle. An authored mesh with duplicated vertex records at a geometric seam remains separate and may now report boundary edges; no repair is performed automatically. Exact-equality omission is a conservative limited special case, not a proof that all generated degeneracy is harmless. General error bounds, export-quality UI, resource reservations, self-intersections, GPU budgeting, checkpoints and desktop/release performance gates remain open.
