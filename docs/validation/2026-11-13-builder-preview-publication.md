# Builder preview preparation and publication token

2026-11-13. `BuilderSession` can prepare a producer request separately and later publish its result only if builder identity and revision, document identity, owner session, epoch, session generation, document revision and context revision still match. The output object must match the session. Reset and preset removal invalidate a prepared result; rejected diameter edits no longer silently change the ring standard without incrementing the revision. An explicit preview clear allows an asynchronous caller to prevent Apply while work is outstanding.

Using `L:\om9-target` and `-j 2`, core `builder_session` (12), `builder_controls` (7), `builder_style` (15), and `ring_tools` (6) all passed. The session suite includes a real secondary thread producing a request, owner-thread publication, refusal after field edit, reset, preset removal, foreign document, changed context and wrong output identity, and the invalid US diameter case. With the OCCT 8.0.1 runtime, app `ring_family_panel` passed 5 tests; the build emitted two existing warnings.

This is a publication mechanism, not a production worker. Normal Builder remains synchronous; no coordinator reservation, cancellation, job-generation/scene freshness check, topology admission or retained-preview lease has been connected. Requests with inputs still clone their input snapshots and require their own admission accounting. The worker test does not establish UI responsiveness or memory bounds. Display-derived associative signatures, source-only Document/Undo, eviction, cold restore and v5 remain open.
