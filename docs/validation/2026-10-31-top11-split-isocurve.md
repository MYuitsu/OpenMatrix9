# Top11 Split Isocurve for typed NURBS surfaces — 2026-10-31

The normalized Top11 Split reference calls for a single-surface Isocurve option with U, V, Both and Toggle directions. Before this change the option was absent. On one selected typed NURBS surface, the Split cutter prompt now offers Isocurve; it switches to a point prompt with a shared Direction option and U/V/Both/Toggle actions. U runs along the surface U direction (constant V), V along V (constant U); Both creates four regions at the picked UV. U is the provisional OM9 default; the local reference does not establish the default. The command option is only offered before cutters are selected. Typed coordinates use the shared point parser; viewport input uses a hit on the selected surface. A typed point must be within document tolerance of the surface; viewport tessellation hits are projected to the NURBS surface.

Rust projects the picked world point using the transformed control net, then creates child surfaces with restricted parameter domains. Original knots, poles, weights, attributes and placement are preserved: no sampling-based surface refit is used. Results replace the source in one transaction. This corresponds to retaining the underlying surface, not Shrink=Yes.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target`, `-j 2`:

- The Isocurve option regression failed before implementation because the option was absent. Afterward the CMD/controller fixtures cover U, V, Both, translated targets, off-surface and boundary refusal, correct UV domains, and Undo/Redo.
- Selection after invoking Split, activating Isocurve and toggling Direction through the shared option interface, Both and Cancel pass. A rational quadratic surface under nonuniform scale retains its original NURBS data, evaluates identically in each output domain, survives `.om9` save/open and Undo.
- A simulated viewport click on a surface at Z=3 exercises selection of the actual surface and verifies the split domain and Undo. The Top11/options/BRep/snapshot suites passed 118 tests (55 + 10 + 50 + 3). The no-default Top11/options/snapshot suites passed 68 tests; surface target admission in that developer build is still unavailable.

Limits: this Isocurve path currently accepts typed NURBS surfaces only, not single-face BReps; Shrink=Yes is not implemented. Surface projection is a numerical coarse-grid/local solver, and a tessellated viewport hit is projected rather than refined along its camera ray. Periodic surfaces, complex near-boundary inputs, preview, 3DM, real desktop input, SDK plugin parity and human M03-UI acceptance remain unverified. The inferred default and exact Toggle-from-Both behavior need original Matrix confirmation.
