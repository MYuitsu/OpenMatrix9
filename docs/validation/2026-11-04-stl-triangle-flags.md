# STL triangle source flags

STL soup construction previously kept a separate `Vec<bool>` with one element per triangle until finalization, to distinguish generated collapses from invalid authored mesh triangles. Each source is now validated immediately after appending: only generated triangles with repeated indices are marked in place, and authored degeneracy or any out-of-range index is refused. Finalization removes the marks in place while preserving the order and allocation of the remaining triangle array. The marker is `[u32::MAX; 3]`; all append paths cap the vertex count at `u32::MAX`, so no valid index can equal `u32::MAX`. Authored invalid indices are rejected before finalization.

This removes the separate source-flag allocation, at least one byte per triangle previously represented, without changing the requested tessellation quality. It does not establish a measured process-memory reduction, eliminate OCCT or topology scratch, certify STL deviation, or authorize UI background export. Earlier worker-floor notes describing a live source-flag vector are historical; the topology-array lower bound is unchanged.

On the external E: target with `-j 2`, 24 STL session tests passed, including generated collapse, invalid authored index, cancellation, in-place compaction and mixed-source ordering. All 60 serial STL integration tests passed with the native runtime, including the independent sphere and topology fixtures. Public-source audit found no errors. The additional source-validation pass has not been separately benchmarked; desktop and release peak measurements remain pending.
