# OCCT snapshot copy preflight

The Rust OCCT snapshot callback used to check each source array against `max_bytes` independently, allocate all owned copies, and only then validate their combined retained storage. Several individually permitted arrays could therefore already be allocated when aggregate validation refused the result. The callback now sums the minimum requested bytes for source text, points, triangles, segments, vertices, adjacency, generated topology UUIDs and the source allocation metadata with checked arithmetic before copying any snapshot array. It also checks topology counts and addressable-array size before allocation. Actual capacity and full object validation still run afterwards.

This is a lower-bound preflight, not a complete reservation: the native source arrays and OCCT mesher allocations coexist with Rust copies; grouped shell and edge-binding arrays, allocator over-allocation, validation scratch and other callers remain separate. It does not establish an RSS limit, lift the interactive 256 MiB cap, or authorize the background STL worker in UI.

On the external E: target with `-j 2` and the matching `3dm-brep` feature, all eight kernel unit tests and 74 editing integration tests passed. A synthetic callback fixture uses null array pointers with individually fitting lengths but a combined size over budget; the budget error arrives before any pointer read. Exact-boundary and checked-overflow cases also pass. All 60 serial STL integration tests passed with the default native runtime. These tests do not inject an actual allocator failure or measure process high-water.

## Grouped topology accounting

The grouped OCCT path now shares one synchronous callback account between the Rust-owned snapshot and the shell-group/edge-binding vectors. Each callback checks its minimum against the bytes already accepted by the other callback; after successful allocation it charges actual retained vector capacity or `Brep` storage. A nonzero native return after a successful snapshot callback is now refused instead of returning a partial result. The current adapter invokes group data first, but admission does not assume that ordering. Synthetic tests simulate both admission orders, the exact boundary, and refusal before snapshot pointer reads; the reverse ordering is not an actual native callback fixture. Allocator over-allocation may briefly exist before the actual-capacity recheck. Native buffers and OCCT transients, fingerprint/validation scratch, caller-owned data and process-wide admission remain open.

On E: with `-j 2` and `3dm-brep`, ten kernel unit tests passed; a real box snapshot fixture verifies that retained snapshot storage is added to a pre-existing group charge and a simulated native failure after its callback is refused. The 74 kernel editing integration tests and all 60 serial STL integration tests passed. This is not a complete memory or desktop acceptance result.
