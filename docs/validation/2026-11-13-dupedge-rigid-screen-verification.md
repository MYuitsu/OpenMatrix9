# DupEdge source-point screen verification

2026-11-13. The source resolver returned both a curve and a source point, but the product path checked the source point's screen position only for non-rigid placement. For rigid placement it reprojected the displayed chord point instead. A coarse cylinder chord at high zoom reproduced acceptance although the resolved source point was outside the click radius. The first focused regression failed against the prior code.

The controller now checks the resolved source point in the captured camera and viewport for rigid and non-rigid placement. For the tested coarse rigid cylinder, the mismatch requests the existing worker to build a fresh source view and preserves the document and Redo when canceled. A saved/reopened trimmed arc in simulated egui requires the fresh view for the 0.5 mm display profile; selecting again creates the expected source arc and Undo/Redo works. For one NativeBrep cylinder at extreme zoom, even its temporary 0.01 mm source view is too coarse: the command refuses without an endless refresh loop and retains the document and Redo. The user approved recording this tested scope in the feature guidance.

The focused controller test went from failing to passing; 18 source-pick tests, 22 source-view worker tests and 29 simulated DupEdge UI tests passed, with four UI 3DM tests ignored in that group. The authored 3DM trimmed-arc regression was explicitly run separately and passed. The no-default-feature check, public source audit and existing debug executable build passed. This is not a guarantee for arbitrary geometry, camera, precision, occlusion, physical desktop or native peak memory. The old direct-commit expectation for the coarse arc was updated to test completion after reselection, not dropped.

## High-zoom limitation and possible next step

The existing temporary view uses a fixed source deflection no larger than 0.01 mm, independent of zoom. The NativeBrep extreme-zoom fixture above therefore refuses a valid circular source when even that view is too coarse; this is a safe refusal, but the user cannot complete that selection at the tested zoom. No further refinement is currently performed.

One possible change, awaiting the user's decision, is to derive a smaller local-space deflection from the captured camera pixel scale and a conservative bound on placement magnification, then build one more private view through the existing admitted, cancellable worker. The camera-derived value would be a mesh request, not proof of accuracy: the existing unique source-edge and screen checks must still pass. A lower deflection and bounded number of refinements are needed to stop repeated rebuilds; exceeding either limit remains a refusal. The old document and original scene must survive pending work, failure, cancel and stale results, and the original scene backup must not be replaced by a temporary scene. The current publisher explicitly refuses a second temporary publication, so its lifecycle and simultaneous buffer ownership require tests before this can be enabled. Initial direction, budgets and tolerances are not yet implemented or approved.
