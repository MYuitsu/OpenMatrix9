# STL proximity-weld diagnostic

Generated B-rep/NURBS face meshes currently use source-scoped positional proximity to join nodes. That does not establish that two nearby points belong to the same canonical edge, and can join unrelated nearby features. An initial experimental change refused all non-identical proximity merges: the unit fixture then passed, but six of 29 existing integration fixtures, including spheres and curved surfaces, failed because ordinary OCCT meshes also contain non-identical near seam nodes. The blanket refusal was removed.

The existing weld is retained provisionally and now counts non-identical point merges and adds an explicit receipt warning that shared topology was not verified and distinct features may have been joined. Exactly identical positions do not increase this count. The warning is available in the UI message and existing MCP warnings array. This is a diagnostic, not proof that the merged nodes were safe or a replacement for canonical edge-based seam identity.

Two weld unit tests and all 29 application STL integration tests passed before adding the fixture below; the sphere fixture checks that an unverified-weld warning reaches the receipt and user-facing message.

## Confirmed separate-solid gap loss

A new OCCT fixture makes two 1 mm boxes separated by 0.0000005 mm, joins them into one B-rep compound, and independently checks the source contains two solids. The gap is representable in binary `f32` at this coordinate. The exported STL loses the second boundary; its receipt reports 28 unverified proximity welds. The ordinary fixture checks that this loss is disclosed and passes; a separate ignored acceptance test requires the gap to survive and was run explicitly, failing as expected. The ignored test is a known open defect, not a passed gate.

The current adapter emits per-face triangle points and face/edge membership, but no binding from each face-mesh node to a canonical edge/vertex. The installed OCCT API exposes `PolygonOnTriangulation` as a possible source for such bindings; the existing separately sampled display edge polylines are not proof that a mesh node belongs to a specific edge. A future export-specific snapshot must bind source, face mesh, edge and vertex identity consistently, including seams and shared vertices, without treating approximate coordinate proximity as topology. No implementation or global topology proof is claimed here.

## Interim refusal for multi-solid native B-reps

The normal export path now counts unverified welds per source. When such a source is an OCCT-backed `Geometry::Brep`, it measures the captured source; if it contains more than one solid, export is refused before destination publication. The two-box fixture now verifies refusal and that existing destination bytes survive. A separate fixture exports two separated box solids without non-identical welds. Thirty application STL tests and two weld unit tests passed; the additional separated-box fixture also passed. The full gap-preservation acceptance remains ignored because the unsafe case is refused, not exported correctly. A no-default-features check passed with 17 existing warnings.

This is conservative: it can refuse a multi-solid B-rep even when its ambiguous welds occur only at legitimate seams inside separate solids. It does not prevent uncertain joins between shells of one solid, or in retained `NativeBrep` or NURBS sources. Single-solid sources still use proximity welding and report a warning. OCCT measurement is synchronous, its native memory peak and latency are unmeasured, and production reservations do not yet cover it. Topology-aware welding is still required.

## Solid-scoped snapshot and gap fixture

The OCCT adapter now offers an export-only face-to-solid mapping emitted from the same parsed shape and face map as its tessellation. Group IDs are transient; a face not belonging to a solid has group zero, and a face attributed to multiple solids is refused. Rust validates the mapping length and triangle-node ownership before using `(selected source, solid group)` as the proximity-weld scope. Snapshot points used only by display edge/vertex data, rather than any output triangle, no longer participate in welding. No native IDs are stored as persistent document topology.

The previously failing 0.0000005 mm two-box acceptance now exports and retains both encoded boundary coordinates, and is no longer ignored. Thirty-two STL integration tests, two weld unit tests and the OCCT grouped-snapshot test passed. The grouped-snapshot test checks two solid owners and their independent face-mesh coordinate ranges. The no-default-features check initially exposed a type-inference error; after an explicit annotation it passes with 17 existing warnings.

This separates different solids in the tested `Geometry::Brep` path. It is not shared-edge identity: proximity welding within a solid, multiple shells/cavities of the same solid, unowned faces, retained `NativeBrep` and NURBS remain unresolved. The prior conservative refusal remains for a multi-solid B-rep with non-identical merges within a group. The new native owner scan and group arrays add unmeasured work and memory, not covered by a production reservation. No desktop or global error guarantee is established.

## Shell-scoped snapshot and cavity fixture

The previous solid grouping did not protect two shells of one solid. An OCCT difference fixture creates one solid with an internal box cavity; the cavity corner is 0.0000005 mm from each of three outer faces. Before this change the exported STL lost the corner and reported three unverified welds. The source measurement verifies one solid and two shells.

The export-only callback now derives face groups from canonical OCCT shells, using the same shape and face index as tessellation. Different shells therefore do not enter the same proximity-weld group, including cavity and outer boundaries. An unowned face receives group zero; a face shared by multiple shells is refused. The regression now passes, checks the encoded cavity corner, source-scoped indexed closedness, and signed volume against the expected outer-minus-inner volume within `1e-6` cubic mm. The two-close-solid fixture continues to pass. Thirty-three STL integration tests, two weld unit tests and the grouped OCCT snapshot test passed.

This is still not canonical edge/vertex mapping: unrelated features inside a single shell or multiple unowned faces can be fused, and the conservative multi-solid ambiguity refusal remains. NativeBrep and NURBS still use the earlier path. Output topology checks are source-scoped index checks, not a self-intersection certificate; the fixture does not certify arbitrary cavities or curved trims. Native work/memory, reservation and desktop behavior remain unmeasured.

## Retained NativeBrep cavity

The retained 3DM-backed path now passes its converted canonical OCCT B-rep through the same shell-grouped export snapshot. A new test reproduces the thin-cavity failure before the change. The fixture uses a `1e-8 mm` document tolerance, since the earlier `0.001 mm` import correctly rejected shells only `0.0000005 mm` apart; its STL request is independently set to `0.001 mm`. It verifies one solid and two shells and the cavity corner in the converted source before export, then checks the encoded corner, indexed topology and signed volume. All 34 STL integration tests and the MCP receipt test pass; the expanded source-corner assertion also passes separately.

The converted NativeBrep is currently tessellated once during 3DM conversion and again for the grouped snapshot; the extra native time and peak memory are not measured or production-reserved. Shell grouping is not edge/vertex identity; multiple features within one shell, unowned faces and direct NURBS remain open. This fixture does not prove general 3DM conversion accuracy or desktop responsiveness.

### Avoiding the extra NativeBrep tessellation

The export route now invokes the existing native 3DM-to-OCCT-source conversion, which does not construct a mesh, and then requests one shell-grouped export snapshot from that source. The prior two-snapshot route is no longer used by STL export. The cavity test compares the converted source's shell count and corner, exercises invalid payload rejection, and verifies the encoded cavity. All 34 STL integration tests and the MCP receipt test pass.

This is established by the selected code path, not by a timed benchmark or native allocation trace. Conversion still serializes and reparses OCCT source, runs synchronously, and lacks a measured or production-reserved memory envelope. General 3DM conversion accuracy, in-shell seam identity, NURBS and desktop responsiveness remain open.

## Experimental edge-node bindings

An opt-in grouped OCCT snapshot can now return `(mesh point index, source edge index)` pairs from `BRep_Tool::PolygonOnTriangulation`, using the same face triangulation and source topology map as the snapshot. Rust checks callback array sizes, allocation failures and all point/edge indices; IDs are local to that snapshot. The normal STL path does not request the additional bindings and still uses shell-scoped proximity welding.

On the two-box fixture, all 24 source edges have bound mesh nodes from exactly their two neighboring faces, with no edge crossing shell groups. On one periodic sphere fixture, 22 pairs of coincident mesh nodes shared an edge binding and none of the coincident pairs lacked one. These are bounded fixture observations, not proof of complete seam or trim coverage. The 34 STL integration tests also pass after the adapter change.

An edge ID alone is insufficient to authorize a weld: distinct nearby points on the same edge may represent different curve parameters, and nodes at shared vertices or periodic seams require careful identity and correspondence. Edge-parameter/vertex mapping, missing polygon data, multiple face occurrences, trims, placement and native allocation/latency accounting remain open. The new edge bindings are not yet used to change export geometry or validate topology.

### Edge curve parameters

The opt-in binding now also carries the OCCT polygon's edge-curve parameter when present; missing parameters remain explicitly absent. Its callback layout and bounded-copy checks were updated, and infinite native parameter values are refused. No additional bindings are requested by the ordinary STL path.

In the tested box pair every binding has a parameter, and at least one edge contains distinct parameter values, demonstrating that edge identity alone cannot distinguish its points. In the sphere fixture all 48 bindings carry parameters; all 22 coincident node pairs sharing an edge also have a matching parameter within `1e-12` in that fixture. Both OCCT tests and all 34 STL integration tests pass. This fixed numeric comparison is a fixture observation, not a universal parameter tolerance or proof of edge correspondence. Shared source vertex identity, missing or periodic parameter cases, very short edges, nonuniform transforms, trim/seam coverage, reservations and actual topology-aware welding remain open.

### Optional canonical endpoint binding

Experimental edge-node records now also carry a snapshot-local source vertex index when the node's polygon parameter exactly equals an OCCT edge endpoint parameter and its position lies within that endpoint's OCCT tolerance. Absent or unverified bindings remain absent; conflicting endpoint identities are refused. Rust validates the returned vertex index and reserved ABI field. No extra bindings are requested by the normal STL path.

The two-box fixture binds all 16 canonical vertices and observes each from three adjacent faces, with bounded coordinate checks. The sphere fixture reports 8 edge-node records with verified endpoints; it is not an assertion that every possible pole representation was covered. Both adapter tests and 34 STL integration tests pass. Exact parameter equality deliberately favors omission over guessing; this does not establish completeness for periodic parameter wraps, degenerate edges, vertices with unusual tolerances, trims or transformed instances. The data is not yet used for welding, and missing bindings require a safe fallback.

### Conservative source-site predicate

An experimental Rust predicate identifies a shared source site only for two bindings from the same snapshot: both verified endpoints must have the same vertex ID, or otherwise both must share an edge ID and an exactly equal known parameter. Conflicting verified vertex IDs are refused even if an edge parameter matches. Missing parameters and merely close parameters do not match. Its unit fixture covers those cases, and the OCCT two-box fixture confirms a shared corner can match across different incident edges while distinct positions on one edge do not match.

The predicate is not a complete weld algorithm. Snapshot-local IDs must never be compared across snapshots or source objects; the eventual caller must enforce this scope and verify transformed world-space separation against the allowable error budget. Exact parameter equality can reject valid joins; periodic wraps and missing endpoints require a conservative fallback. No export path consumes the predicate yet, and no trim, short-edge or desktop guarantee follows from these tests.

The comparison is now exposed through an `EdgeBindingSet` owning the bindings from one snapshot; it reads both compared entries from that set and returns no result for an out-of-range index. The direct comparison on an individual binding is private. The box fixture verifies shared-vertex and different-parameter cases through the set and checks invalid-index refusal; one unit and both OCCT adapter fixtures pass. Callers must still derive both numeric indices from the same set and associate it with the correct source snapshot; this API alone cannot prove an index came from the intended set or enforce the world-distance check.

### Snapshot-bound transformed-distance check

The experimental API now returns one `EdgeTopologySnapshot` that owns the B-rep mesh, shell groups and edge bindings together. Its `may_weld` method checks indices and source-site identity from that snapshot and compares separation after the placement's linear transform against a caller-supplied world-unit bound. It cancels translation analytically before calculating distance, avoiding loss of small differences when subtracting two large translated `f64` coordinates. Invalid transforms, non-finite points and invalid distance limits are refused.

Two unit tests cover source identity and synthetic nonuniform scaling, reflection, large translation and non-finite input. Two OCCT fixtures cover source-local indices and an actual coincident sphere seam. An attempted test requiring a *nonidentical* same-site pair in that sphere was invalid because that fixture had none; it was replaced with a synthetic nonidentical pair plus the separate actual coincident-seam check. This method is not yet connected to STL welding and does not solve binding completeness, periodic parameter wraps, representative choice, transitive merging or cumulative error. The requested bound is supplied by the eventual caller and is not itself an error-budget proof. Runtime memory/performance and desktop remain unmeasured.

### Experimental topology remap

An opt-in Rust remap now groups mesh nodes by snapshot-local shell and either verified vertex ID or an exact known `(edge, parameter)` pair. Unbound nodes remain separate; a node assigned conflicting source vertices is refused. Every union conservatively tracks an upper bound from the chosen representative to its members after placement, refusing a merge if the bound exceeds the caller's world-space limit. This prevents a chain of individually close merges from silently accumulating beyond that limit. It does not normalize periodic parameters or guess missing identities.

In the two-box OCCT fixture, the remapped triangle indices have two incident faces per edge without joining the separate shells. The sphere fixture merges at least one verified periodic seam site. A synthetic three-node test verifies refusal when transitive displacement would exceed the limit; the normal adapter and identity/transform tests pass. The algorithm is experimental and not connected to STL export: incomplete bindings can leave open boundaries, its conservative radius bound may reject safe joins, and final triangle validity, canonical edge correspondence, trim/periodic cases, cancellation, memory reservations, measured cost and global error budget remain open.

### B-rep STL integration

The OCCT `Brep` and converted retained `NativeBrep` STL paths now use that topology remap. They do not subsequently apply the positional-proximity weld to those sources. The remap is bounded by `min(1e-6 mm, requested linear tolerance / 10)` in transformed world space and checks cancellation periodically. Before writing, the export path rejects a non-identical triangle collapsed by remapping or a remapped triangle whose world-space normal collapses or reverses. Exactly coincident generated triangle corners may still be omitted and reported as before. Unbound mesh nodes remain distinct; the receipt's boundary counts expose resulting open indexed topology.

A new OCCT fixture creates one solid and one shell with a slot, then applies nonuniform scale so its two distinct walls are 0.0000005 mm apart in output coordinates. Both encoded walls remain present, and the indexed shell is closed. Attempts to construct the slot directly at sub-micron width produced an invalid two-solid/three-shell fixture and were discarded; an initial zero-coordinate equality assertion was also corrected after observing OCCT's `2.78e-17` arithmetic residual. The previously established close-solid, cavity, NativeBrep, sphere and mirror fixtures pass. All 35 STL integration tests, four kernel identity/remap/cancellation tests, one triangle-orientation unit test and the MCP receipt test pass; the no-default-features check passes with 17 existing warnings.

This is partial topology-aware export, not a global tolerance or watertightness certificate. Exact edge-parameter matching can leave legitimate seams open; periodic wraps, missing bindings, unusual trims and degenerate topology require further fixtures. Direct `Geometry::Surface` NURBS still uses the older proximity path with an explicit warning for non-identical welds. Native tessellation itself remains non-interruptible, and the additional binding/remap memory and latency are unmeasured and not yet reserved under the production budget. Desktop responsiveness and complete encoded topology remain open.

### Direct NURBS STL integration

The direct NURBS surface path now converts its validated face to canonical OCCT source without first tessellating, then uses the same topology-aware export snapshot and triangle checks as `Brep` and `NativeBrep`. The now-unreachable positional-proximity weld and its extra remap buffers were removed; authored meshes remain unchanged. The native source callback now uses fallible reservation before copying. Missing source-edge bindings still remain distinct and may produce an open result reported by indexed topology checks.

A new U-shaped NURBS sheet fixture uses nonuniform scale so unrelated sides are 0.0000005 mm apart in output space. The previous proximity path rejects it after collapsing a non-degenerate triangle; the new path exports both sides and reports the sheet open. The earlier first 36-fixture run passed after the change, and all 36 passed again after removing the proximity path. Nine STL unit tests cover cancellation, triangle finalization and orientation; both NURBS-focused tests passed again after the callback allocation change. The no-default-features check passed; one newly introduced unused-variable warning was subsequently corrected. This does not certify general trimmed/periodic surfaces, full error bounds, runtime memory or desktop responsiveness. Native conversion and tessellation remain synchronous and not production-reserved.

### Periodic NURBS and encoded STL checks

The full cylindrical NURBS fixture (geometrically closed but its periodic flag is false) checks encoded edge incidence, two boundary loops and outward winding under identity, nonuniform scale and reflection. A separate fixture uses certified repeated periodic bases: an uncapped tube periodic in one direction and a toroidal surface periodic in both. Across identity, nonuniform scale, reflection and both surface orientations, 12 cases check actual binary-STL geometric edge incidence and directed winding, compare encoded boundary counts with indexed receipt counts, and require two loops for the tube and none for the torus. The torus has nonzero encoded signed volume whose sign changes on surface reversal. This is scoped to the tested components and does not prove general watertightness or lack of self-intersections.

For those 12 periodic cases, 252 points evaluated independently from the canonical NURBS source were transformed and compared with their nearest decoded STL triangles. Maximum sampled distance was **0.000306956 mm**, below the captured template tolerance **0.001 mm**. The point-to-triangle comparison helper has separate face, edge and vertex oracle cases. This is a one-way sampled check, not a global or bidirectional error bound. A separate truncated parameter-domain periodic tube passed an encoded-boundary test with one connected loop.

The default-feature E: run with `-j 2` passed 39 STL integration tests, then the new trimmed-periodic test passed separately. An earlier 39-test run failed because two existing nearby-solid tests used the same temporary filename concurrently; they now use distinct names, and the rerun passed. A later full run of the expanded `om9-app --test stl_export` suite passed all 47 tests in 66.26 seconds, including the periodic and trimmed-periodic cases. No runtime export code changed in this batch; native tessellation costs, scratch admission, unusual seams and general error certification remain open.
