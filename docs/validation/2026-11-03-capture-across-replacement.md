# Capture accounting across document replacement

P0 partial: replacement controllers inherit the previous coordinator's external-document capture registry. Before a New/Open/snapshot/master replacement commits, the old controller's retained owners and scene are included while the candidate is constructed; adopting the registry validates the candidate with still-live captures. Failure restores the candidate's original registry without modifying the old coordinator. Weak entries allow a capture to stop being charged when its final strong owner is released.

Windows with default OCCT/openNURBS, `CARGO_TARGET_DIR=L:/om9-target`, Cargo `-j 2`: six retained-owner unit tests passed, including transfer and rejected-adoption rollback. STL integration fixtures confirmed the old captured document remains accounted after real New and Open replacements and is released from accounting after the capture drops; the full 29-test STL suite passed. The 20 file-lifecycle tests, 11 document-contract tests and two project-manager persistence tests passed. These test accounting estimates, not actual peak RAM or live desktop behavior.

The registry covers external captures within this controller replacement chain, not every independent app session or all payloads. Nested shared subpayload deduplication, cache/kernel/export allocations, simultaneous job admission, physical available-memory enforcement, and the 60% total managed budget remain incomplete. The global 256 MiB byte limit remains. The UI export is synchronous, and a worker's New/Open/close cancellation has not been integrated. The active OM9 session was not modified.
