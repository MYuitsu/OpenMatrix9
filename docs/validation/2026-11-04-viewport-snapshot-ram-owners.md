# Viewport preparation snapshot RAM ownership, 2026-11-04

GPU scene, shared line and viewport overlay workers previously cloned a presentation scene without a tracked document capture or shared-account RAM reservation. Their immutable document and render-buffer Arcs could remain alive after an edit or document replacement without that worker lifetime appearing in the account. These preparation jobs now acquire a tracked document capture and a CPU-cache lease before creating a fallible presentation snapshot. Workers for the same document allocation, scene epoch and hidden-source set share one snapshot and lease, including across Gumball preview revisions as described below. The cache holds only a weak pointer; cancellation, enqueue failure or completion releases each worker's strong owner, and the last owner drops the snapshot before the lease. Cached snapshots are rejected if their document is no longer the Controller's current document.

The reservation conservatively charges the entire original scene cache alongside the currently held scene, including buffers shared between them. Thus it can temporarily count those bytes twice and refuse a valid large scene; distinct scene versions can also coexist. It avoids counting the same snapshot multiple times across simultaneous workers but does **not** implement the final unique-allocation accounting required by the plan. It does not bound line/mesh preparation buffers, GPU uploads/driver memory, allocator capacity excess, other scene paths, or the independently retained published scene after the worker exits. Physical memory is sampled when available; the existing managed-only fallback applies when it is unavailable. The desktop UI must still be tested for responsiveness and real memory pressure.

## Share across preview revisions

GPU preparation uses source placement; the current Gumball preview transform is applied separately when drawing. The previous snapshot key included preview revision and could retain another full scene lease merely because a drag moved. The shared snapshot now has identity preview transforms and its key excludes preview revision. Scene preparation also skips `object_spheres()` when close-range culling is disabled; that path previously built bounds even though its result could not affect rendering. If close-range culling is enabled in future, its snapshot and preview handling require a new correctness review.

Two snapshot owner tests and 27 serial GPU/egui tests passed with no adapter skips on the E: default-feature debug target, `-j 2`, OCCT runtime; final build 28.07 s, owner tests 0.01 s and GPU tests 55.58 s. Coverage includes preview pixels in two viewports, a mixed-scene pixel comparison, pressure retry through a preview change, selection invalidation, Gumball drag and focus. The owner test verifies changing preview revision reuses the same snapshot and lease. An earlier GPU suite failed because the selection invalidation test compared an old freed allocation address with a new one; a weak reference now keeps the old allocation header alive for that comparison without retaining its GPU buffers, and the suite passed. Another earlier pressure test assumed two frames would finish within 250 ms; the test now uses a controlled longer deadline. No release or desktop performance or physical-memory measurement was taken for this follow-up, and the main live-scene double charge remains.

## Admission-pressure retry backoff

A snapshot `Budget` failure now delays another attempt for the same document allocation/scene epoch/hidden-source key by 250 ms instead of reattempting every 2 ms, including when unrelated UI frames arrive earlier or only the Gumball preview changes. The next repaint is requested for the remaining interval. A changed scene key bypasses the old delay, and ordinary worker completion polling retains its previous cadence. This bounds attempts per unchanged viewport rather than guaranteeing an overall process CPU limit; other repaint sources and viewports remain independent.

Two serial offscreen GPU/egui tests passed on the E: debug target with `-j 2` and OCCT runtime. One holds a competing reservation, verifies two intervening frames do not renew the retry deadline, releases pressure and verifies successful image publication and error clearing. The other extends the old deadline to 60 seconds in the test, changes the document and confirms the new scene publishes without waiting for it. Two snapshot-sharing/lifetime tests also passed. Final targeted build 27.94 s, GPU tests 2.21 s, owner tests <0.01 s; an earlier run preceded adding document allocation identity to the retry key, so the tests were rerun. No adapter skip, real OS exhaustion, desktop CPU or end-to-end latency measurement. The release replay below predates this failure-path change.

Two focused default-feature E: debug unit tests with `-j 2` originally covered same-key sharing, then preview-key separation, scene change while an old snapshot remains charged, stale-scene refusal, last-owner release, and refusal/retry under a competing reservation. Preview-key separation was later replaced with sharing as recorded above. A real offscreen GPU/egui fixture forces managed pressure during first viewport preparation; after releasing pressure the image completes and the transient error clears. Twenty-five GPU/egui Gumball tests also passed after the ownership change and current-document guard; the transient-error clearing line and the additional GPU pressure fixture were added afterward and the targeted pressure fixture passed.
