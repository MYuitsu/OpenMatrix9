# Preserve editing of short Lines

Preserve import now admits an OM9-marked short Line when its native geometry is a valid non-rational degree-one, two-pole NURBS, the marker has the expected value, and the only native userdata is the one-string OM9 marker. The same native shape validation is used for projection and admission. Rust additionally requires a Line projection and no other unsupported geometry fields. A replacement in the retained-current writer may discard and regenerate this owned marker; foreign userdata, unknown record chunks and opaque attribute data remain protected by existing checks.

One authored fixture imports the marked line in Preserve mode, moves an endpoint using Top11 Control Points, verifies Undo/Redo and `.om9` save/open, writes via the retained-current API, cold-inspects and republishes the file, then reimports the edited Line. A separate fixture adds an unrelated native string: the marked Line stays retained-only, an independent Line is edited, and an independent SDK fixture verifies that both original strings survive the retained-current output. Invalid marker, missing marker and additional string all fail the native owned-only classification. Before this change the basic Preserve-admission assertion failed.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target-top11-nested`, `-j 2`: 54 real-native `om9-app --test l2_01_13` cases passed, and the two Preserve short-line cases passed again after adding Undo/Redo and `.om9` checks. Four real-native `om9-exchange --test retained_native_write` cases and all non-ignored `om9-exchange` tests passed. The separately built native adapter is `L:\om9-native-short-preserve-v1\om9-exchange-native.exe`, SHA-256 `130739474bce0b012fb6be6b8fd60ebc73dfe060185baa2ce144b0ec80a13e05`; the source fixture was built with the pinned SDK and `/W4 /WX`.

The normal GUI import currently selects Geometry mode and its export remains geometry-only; this test calls the Preserve import and retained-current API directly, and does not establish a GUI preservation flow. Compound-curve marker editing, shortening children through parent placement, arbitrary external edits, independent editor compatibility and desktop acceptance remain open. C++ changes are restricted to the openNURBS adapter and authored SDK fixture; Rust owns the document and publication. No openNURBS measurement batch was performed.
