# Shared viewport world lines, 2026-11-04

Unselected world-space mesh edges, curves and shape guides are now prepared once per shared scene/selection/visibility signature and MSAA sample count and reused by the four viewport renderers. Per-view CPlane grid and screen-sized point markers remain separate; selected geometry, Gumball preview, ghost and selected guides retain their existing per-view paths. The shared batch uses the existing upload pacing and its buffers participate in the deduplicated window and in-flight GPU inventory. Scene/document, selection and hidden-source changes invalidate the shared owner. This is a display-cache change; canonical geometry and export do not use it.

## Controlled debug evidence

A four-viewport offscreen UI test verifies the same shared allocation is used in all views, the window inventory counts it once, and selecting one of two meshes replaces the shared batch and removes the selected mesh from it. Twenty-three serial GPU/egui Gumball and 28 serial GPU viewport tests passed, including camera-only reuse, selection, Undo/Redo, visibility, resize, stale publication and pixel checks. A direct pixel-for-pixel comparison of three stationary orthographic interior regions, 144,300 pixels each, between the before/after hidden replays found zero differing pixels. Perspective final cameras differed between replays; their images are not comparable and this is not a general image-equivalence proof.

The same 729-object fixture, hash `9c0f2289c57792693a9dc67b0281d9a5131f9e93c7dc0e12943a8706543b3828`, was replayed in two separate default-feature debug builds using Vulkan RTX 3060 / NVIDIA 610.88, four viewports, simulated 100% DPI and 90 scripted steps. Each run completed, kept the fixture unchanged, reported no viewport errors and dropped no log records. The maximum sampled deduplicated window overlay inventory fell from **1,490,910,976 bytes (1,421.84 MiB)** to **372,741,744 bytes (355.47 MiB)**, a reduction of 1,118,169,232 logical bytes (approximately 75.0%) for this fixture. Counts include known live and in-flight overlay buffers and are not measured physical VRAM or a universal reduction guarantee. Baseline executable SHA-256 `a0d0f49d2310c1e7a5ef1e34c57414d9368825325d5c3c965a134d00c624242b`; new `d8367389f33f1407eb671b2abdc263e1743be151b581a83793f29395f0c51fc4`.

Raw local runs: `build/standalone-validation/ui-artifacts/gpu-luid-debug-729-20261104` and `build/standalone-validation/ui-artifacts/gpu-shared-world-debug-729-20261104`. The screenshot regions compared were x=430..819/y=200..569, x=430..819/y=600..969 and x=1080..1469/y=600..969 in 1600×1000 images. Debug frame times are not a release benchmark. Actual VRAM/process peaks, precise Perspective equivalence, other scene types and selection combinations, desktop latency and complete GPU budget/batching remain open.

## Controlled Perspective image comparison

A subsequent offscreen GPU test runs the reconstructed original per-viewport line path and shared-line path in the same build, with identical document, viewport dimensions, GPU and Perspective camera. The mixed fixture contains a quad mesh, line and point. It compares every RGBA pixel in Wireframe and Shaded, with no selection and a selected mesh; it also compares selected line and point, visibility change with Undo/Redo, and the final images after orbit, pan and zoom. The test checks that the displayed source, selection, display mode and camera are current; it also verifies mesh selection changes the image. All compared images matched exactly. This is one controlled fixture and does not prove equivalent output for all geometry, transparency, placements or interactive drag frames. Existing Gumball/preview tests cover their own narrower fixtures.

The first compilation of the new fixture failed with Rust E0716 due to a temporary selection array; the fixture was fixed and rerun. The final default-feature E: debug batch with `-j 2` passed 24 serial GPU/egui Gumball tests and 28 serial GPU viewport tests, with no adapter skip. The previous release measurements predate adding the test-only legacy-path switch and are not an exact source-fingerprint match to this follow-up; the production branch still selects the shared path. No new release/desktop performance claim follows from this comparison.
