# Top11 Split Point: endpoint, joint and seam precision

The point-split path rejected fractions within `1e-7` of either endpoint even when the world-space cut was well separated from the endpoint. A one-million-mm line cut 0.05 mm from its start reproduced the failure. The point path now accepts representable strictly interior fractions; the shared explicit-fraction split no longer discards a nonzero interval solely because its normalized width or local length is below a fixed epsilon. Exact endpoints still produce a visible error and no mutation.

Two related errors were reproduced. A polycurve trim snapped a cut near a segment joint to that joint using a `1e-12` fraction threshold; trimming now preserves strictly interior endpoints. A closed point split mapped every fraction within `1e-7` of its seam to the seam; it now maps only the actual endpoint and retains distinct selected fractions. Duplicate selected points remain checked in world space against document tolerance by the controller. Finite precision, degenerate spans and other curve types still require independent validation.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target`, `-j 2`: 114 app Top11 and 32 core Top11 tests passed, as did 204 core library tests and 114 app Top11 tests without default features. The new regressions cover CMD and toolbar entry near either end of a long line, an exact endpoint refusal followed by retry, a near-joint polycurve cut, a distinct large-circle seam-adjacent cut, `.om9` persistence and Undo/Redo. A real-native 3DM test exports and imports both pieces of the long line through CMD and toolbar routes and checks the 0.05-mm boundary; native adapter SHA-256 `bddca46577747333f9377b379351a077b710158f47ce6e279d7b6e21e6439615`. This is an interoperability test, not an openNURBS measurement batch.

This change does not remove separate fixed-fraction filtering in cutter-intersection Split/Trim paths, nor prove general projection, tiny local geometries under arbitrary placement, extreme coordinates, native desktop input or GPU display. Existing no-default unused-code/import warnings remain.
