# Captured tolerance for editable B-rep conversion to 3DM

The `OcctBrepBridge` previously passed a hard-coded 0.001 mm to `om9_kernel::brep::to_3dm`. `ExportCapture::convert_breps` now reads the captured source document's tolerance and supplies its validated absolute millimetre value for every editable B-rep, including definition members, through the `BrepExport` interface. An editable B-rep without a valid document tolerance is refused before invoking the bridge. Other geometry does not acquire a new tolerance requirement. Conversion is still performed on a private export projection; the source and existing publication revalidation are unchanged.

A mock bridge observed two non-default values, 0.02 mm and 0.00001 mm, from captured documents, and verified refusal without invoking the bridge when tolerance was absent. It also verified that the source document remains an editable B-rep. The real OCCT adapter test rejected zero and produced a nonempty native sphere payload with 0.02 mm. On E: default features with `-j 2`, the exchange capture test, the real adapter test, three export-authority tests and 18 clipboard tests passed; two clipboard and ten staged native-exchange tests remained ignored because the separate native exchange executable was not configured for this batch.

This proves propagation to the adapter and a basic native conversion, not geometric deviation or trim/cavity preservation. The 3DM model's absolute/angular tolerance metadata and unit handling are not established by this change. The complete P3c cold-open, source/reimport comparison, publication and representation-preservation matrix remains open. A missing tolerance can now refuse editable B-rep conversion where the fixed value previously allowed an attempt; no reusable skill business rule has been changed.

## Model tolerance metadata and cold inspection

The current geometry packet now includes the captured document's optional tolerance. The paired native writer stores its absolute tolerance in model millimetres, relative tolerance and angular tolerance in radians in 3DM model settings. For declared settings, it refuses angular values outside `(0, pi]` or relative values outside `(0, 1)`, rather than letting openNURBS substitute defaults; absolute tolerance remains finite and positive. The Rust preflight also refuses these unsupported settings. When the document has no tolerance, existing exports remain possible, the native default applies, and the receipt explicitly reports that no OM9 tolerance was specified. Editable B-rep conversion independently still requires a document tolerance.

The inspection process reads the actual temporary 3DM and reports these model settings; Rust checks valid ranges and, when a document tolerance was declared, requires all three values to match before publication. A targeted unit test rejects missing or changed metadata. An actual native integration fixture uses two non-default tolerances and confirms cold validation and publication, then tests zero/out-of-range relative and angular settings with an existing destination and confirms refusal preserves it. This proves the stored model metadata for those cases, not the geometric deviation of the exported B-rep. A document with no tolerance cannot claim its 3DM defaults reflect a source tolerance. Older native executables do not accept the expanded writer packet; deploy the matching native adapter and Rust host together.
