# Detached STL shared reservation, 2026-11-04

`StlExportCapture::export_with_cancellation` previously used the shared single-export permit but performed its work without a shared RAM reservation. A capture now owns an empty coordinator peer joined to the existing document/version and reservation registry. At direct export invocation it validates the profile and session, obtains the permit, samples physical memory, reserves the available managed headroom in that account, applies the lease as the export's byte limit, and holds it through staging and atomic publication. Missing physical-memory information returns an explicit unsupported error before writing. The captured source and selection remain immutable; the Controller and experimental worker routes retain their existing reservations and permit behavior.

In a controlled 32 MiB fixture, a capture of an authored mesh observes a subsequently edited document version through the peer's retained-owner inventory. A competing shared reservation makes direct export fail with the existing target unchanged. An injected post-admission cancellation observes the export lease from the Controller account and prevents a competing reservation; the lease and permit are released and the destination stays unchanged. Retry writes the original one-triangle captured source despite the later edit. A missing-sample case also preserves the target and releases the permit. This is a managed-account fixture, not OS-wide exhaustion or native-memory measurement.

With default features, E: debug target, `-j 2`, OCCT runtime: 43 STL cancellation/admission tests passed (28.99 s build, 0.30 s tests); 60 STL integration tests passed (25.14 s build, 126.01 s tests); same-file reopen and Windows close UI fixtures passed; `cargo check -p om9-app -j 2` passed. The final `#[cfg(test)]` annotation only removed a non-test unused-helper warning after the integration binary had been built; the subsequent UI test build and normal cargo check include it.

## Remaining limitations

The peer follows registered immutable document allocations, not every live owner. Scene and auxiliary usage are sampled once at capture, so a later larger scene or newly grown auxiliary cache can be underestimated; conversely, a scene that shrinks remains conservatively charged. Undo/coordinator metadata, allocator excess, staging, driver memory and native OCCT temporaries are not fully represented. The reservation occupies all currently available managed headroom while this synchronous detached export runs, so other concurrent managed work may be refused. Registering retained document versions and the extra peer have not been benchmarked on large histories. A stale physical sample cannot guarantee free RAM remains available. These results do not establish a 60% process/RSS cap, a complete direct-export budget, background UI readiness or STL global error certification.
