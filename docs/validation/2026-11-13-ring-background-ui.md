# Ring Builder background UI

2026-11-13. In the OCCT-enabled MatrixApp, the ring-family Builder starts and refreshes its preview through a single cancellable worker. New edits replace pending work; a later request waits for the previous worker to retire. Apply while preview work is pending is queued, and a subsequent edit cancels that older Apply request. The frame loop services admission and publication without disabling the whole UI. A B-Rep preview paints its display boundary over the viewport; a document-context change hides its stale boundary and handles. Standalone `Controller` clients that do not enable the UI mode retain the synchronous path.

The OCCT sewing adapter now polls a Rust-owned cancellation flag while constructing faces and through `Message_ProgressIndicator` during sewing, then checks before and after selected native stages. The callback is thread-safe and prevents a canceled result from being published. It cannot interrupt native stages that do not report progress; OCCT internal allocation is not covered by the Rust reservation.

The first tab-switch headless attempts failed: an egui slider repeatedly reported the same quantized `raised_width_mm` value, canceling and restarting the queued worker every frame. Idempotent field edits and a slider equality check removed the repeated scheduling. With `L:\om9-target`, `-j 2`, OCCT 8.0.1 runtime and `3dm-brep`, the kernel ring suite passed 10 tests, including native face-loop cancellation. Three headless UI fixtures passed: Signet CMD with successive edits and boundary paint plus Apply/Undo/Redo; queued CMD Apply; and a real Raised Band tab click followed by preview and Cancel. The 15 worker/controller fixtures, 28 core Builder/control/ring fixtures and 5 synchronous panel fixtures passed. The `om9` debug executable built and workspace check passed with 2 existing warnings; no-default-features app check passed with 21 warnings.

These fixtures do not prove a desktop latency bound, GPU rendering fidelity, all four ring modes end-to-end, or the feature-toolbar menu route. The overlay paints boundary lines rather than a shaded GPU preview. Apply and candidate-scene preparation still run on the UI thread; concurrent preview and document owners can be conservatively double charged. Topology signatures remain display-derived, and source-only Document/Undo, independent representation eviction/cold restore, NativeBrep and v5 remain open.
