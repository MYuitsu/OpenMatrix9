# Top11 Trim: preserve authored BRep face boundaries

The single-BRep plus curve Trim session now permits a multi-face open BRep and curve edits. Before publishing a surface removal, it removes temporary same-domain dividers while protecting edges that overlap edges of the original BRep. The original world-space BRep is held as immutable session input; prospective curve edits repartition the current committed surface before mutation. Per-pick Undo/Redo remains in Rust document ownership.

The native OCCT adapter reads two bounded snapshots, compares current edges with original edges using exact OCCT common operations, marks overlaps as protected for `ShapeUpgrade_UnifySameDomain`, validates the result and emits a bounded snapshot. Edge-pair comparisons are budgeted. Rust checks face count, open result and area; this is a selected OCCT exception and does not transfer handles or document ownership across the ABI.

The kernel fixture uses two sewn, coplanar faces, splits both, then verifies the authored shared edge survives while temporary dividers disappear. It checks total and per-face areas, a removed region and translated original/cutters. The controller fixture removes a region, edits a cutter, removes another region and verifies two retained authored faces of 30 and 100 mm² and three Undo/Redo operations. A simulated egui viewport fixture repeats the mixed edits and Undo.

Windows MSVC, pinned OCCT 8.0.1 SDK/runtime and `CARGO_TARGET_DIR=L:\om9-target`: kernel editing/transform suites passed 79 tests; the subsequently expanded translated kernel fixture passed separately; app Top11/options/BRep suites passed 96 tests; the simulated multiface viewport fixture passed; no-default Top11/options passed 65 tests; public source audit reported zero errors.
