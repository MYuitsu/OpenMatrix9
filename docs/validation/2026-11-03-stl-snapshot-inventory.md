# Retained STL tessellation snapshot inventory

The OCCT export snapshot now exposes a checked Rust-owned storage inventory: the snapshot value, owned B-rep source/display buffers, face/shell group buffer and edge-binding buffer are counted using their capacities. Core B-rep storage inventory is exposed for this validated-owner use; it inventories memory and does not certify geometry validity. The inventory does not cover allocator overhead, native tessellation, topology-remap maps/vectors, output soup, staging, GPU memory or other simultaneous owners. It is not an allocation reservation and cannot prevent the native mesher from exceeding a budget before it returns.

A real OCCT box fixture expands unused capacity in three buffers and verifies that the reported bytes increase by their actual capacity changes while point/node counts remain unchanged; a limit one byte below the resulting inventory is refused. Five kernel edge-site tests and one core B-rep inventory test passed on E: with `-j 2`. A separate debug, fresh-process radius 12 mm sphere snapshot at requested tolerance 0.005 mm produced 48,070 intermediate triangles and reported 1,358,249 retained snapshot bytes, 24,226 points and 6 topology nodes. The process's `PeakPagefileUsage` counter rose from 57,253,888 to 80,666,624 bytes; these are process-lifetime commit high-water values, not memory attributable solely to the snapshot. The probe took 282.365 ms in one uncontrolled debug run, not a release benchmark.

The API is wired to the opt-in measurement fixture, not to an export cache or global session admission. A future cache must reserve before construction and keep its reservation through the last use, accounting for native and Rust peaks and concurrent output; measuring retained capacity after creation is insufficient. The 256 MiB interactive limit, aggregate 60% policy, cache lifetime integration and actual large-model safety remain open.
