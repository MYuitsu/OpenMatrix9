# Object extension slots through SDK v1 — 2026-10-21

A plugin can now read and write the document's named extension slots (jewelry weight,
provenance, plugin metadata) as verbatim JSON-object payloads. The slice belongs to
`OM9-L2-01-03` (`OM9-L3-01-03-009`).

## Changed

| Layer | Change |
|---|---|
| Public SDK | `ObjectExtension { version, payload }`, `Host::object_extensions`, `Host::set_object_extension`, `Host::clear_object_extension`; three requests and capability entries. |
| Host | Slots are validated by the core record (`Extension::new`: positive version, non-empty JSON object payload, size budget); the slot name is bounded to 64 bytes. Reads merge base slots with the command's staged overrides, and writes stage one `Mutation::Extension` per slot under the existing one-source-write-per-object rule. |
| Example plugin | `ExtensionDemo` tags an existing object with `org.openmatrix9.demo` = `{"weight_g":4.2}` and reads it back. |
| Tests | Host test for set/read/clear, duplicate-slot overwrite, undo restoration, invalid payload/version/slot and the attribute-conflict refusal; native DLL test that tags a profile object, verifies the persisted slot, and checks Undo/Redo. |

## Semantics fixed by this slice

- A slot payload is the document's verbatim JSON-object text with a positive version; a
  malformed payload, empty object or zero version is an `extension` refusal, and the size is
  bounded by the document budget.
- Reading merges the base slots with the values staged by the current command, and a cleared
  slot is absent rather than null.
- Writing a slot is a source write like placement/attributes/label/layer, so two different
  write kinds on one object in one command are a `conflict` refusal.
- An object created by the same command cannot be tagged yet: its inserted record is stamped
  once, so the plugin must tag it in a following command.
- Undo restores the previous slot value or removes the slot as appropriate.

## Not proved here

- Extension schemas are not interpreted: the SDK returns the stored text, so a plugin must
  parse and version its own payload.
- An object created in the same command cannot be tagged yet; a following command is needed.
- macOS host and plugin execution are unverified; interactive UI acceptance was not
  performed. No manual or M09 gate was promoted.
