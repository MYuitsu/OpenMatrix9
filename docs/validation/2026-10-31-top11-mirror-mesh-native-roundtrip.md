# Top11 mirrored mesh: native 3DM roundtrip

The authored triangle-plus-quad fixture has shared vertices, vertex normals and colors, and no UV channel. It passes four distinct paths: CMD and sidebar controller invocation, each with Mirror Copy=Yes and Copy=No. Each path reflects a translated mesh about the Y axis, publishes through the pinned native 3DM adapter, cold imports the resulting 3DM and independently compares world-space vertex positions, face indices and winding, vertex colors and normals. The test does not cover UV-bearing meshes, alternate mirror planes, all transforms, external Rhino behavior or real desktop interaction.

A second authored fixture starts as two disconnected colored triangles, applies CMD Mirror Copy=No followed by toolbar Explode, and exports and imports both resulting pieces through real 3DM. It verifies the two world-space meshes' vertices, faces, normals and colors against the pre-export document. This checks that this specific Mirror-to-Explode workflow survives the interchange boundary, not all possible mesh topology.

Inspection of the pinned openNURBS `opennurbs_mesh.h` documents vertex-indexed texture coordinates and surface parameters. Therefore a shared vertex with different corner UVs cannot be represented by a single per-vertex coordinate without a seam strategy. Splitting vertices without a verified reconstruction strategy would change the input mesh's index connectivity, which is relevant to Top11 Explode. The writer continues to reject populated UVs before publication; both UV accuracy and mesh connectivity remain open for a general solution.
