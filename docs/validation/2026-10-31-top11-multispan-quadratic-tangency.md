# Top11 Split/Trim: multi-span quadratic NURBS tangency

The sampled line/NURBS solver returned five near-duplicate hits for one tangent within a span of a two-span quadratic NURBS. The Rust intersection path now separates eligible nonperiodic, unseamed quadratic NURBS at active knot fractions, intersects each trimmed span using the existing quadratic solver where applicable, and maps the resulting fractions to the original curve. It checks the mapped points against the original geometry and model tolerance, merges the same shared-knot hit, retains different visits to the same point, and enforces output limits. Spans the algebraic branch cannot handle still use numerical refinement; ambiguous precision is refused by that branch.

The core regression checks reversed input and both operand orders. Additional fixtures check one hit at a shared knot, two distinct parameters visiting the same point, a rational tangent and output-budget refusal. CMD and toolbar Split/Trim tests check the tangent boundary, correct piece counts, reversed input, `.om9` roundtrip and Undo/Redo. A real 3DM export/import retains both Split pieces and their tangent boundary, using admitted native adapter SHA-256 `bddca46577747333f9377b379351a077b710158f47ce6e279d7b6e21e6439615`. This interoperability test is not an openNURBS measurement batch.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target`, `-j 2`: 204 core library, 34 core Top11, 25 curve/surface, 124 app Top11 and 83 app Top11 BRep tests passed; 124 no-default app Top11 tests passed with existing warnings. Core curve/surface and the full app suites were rerun after adding the original-geometry check; the no-default targeted multi-span test was also rerun. One native 3DM roundtrip passed.

Periodic or reseamed quadratic curves, higher degrees, overlapping curves, extreme precision and spans that require general sampling remain open, as do performance for very large knot counts and physical desktop acceptance. These tests do not establish completion of Top11.
