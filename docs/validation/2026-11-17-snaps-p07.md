### Rhino 5 native Int and Project point path

The Matrix90 event trace reaches the host's ordinary point resolver.

implementation gap.

### Rhino 5 native Grid Snap and Ortho composition

The Matrix90 Grid step button delegates `SetGridSnap`. In the Rhino 5
ordinary free Line point path, the binary calls the plane-pick helper
at `0x140334e69`, then the Ortho helper at `0x140334f04`. The first
helper saves both the raw point and the grid-quantized point. The Ortho
helper uses the grid point to choose the direction. For the 45° diagonal
case it projects the raw point onto that direction and calls the grid
refinement helper at `0x14032e3bf`. That helper intersects the Ortho line
with the candidate X and Y grid lines and picks the closer result.

The comparison fixture uses CPlane World Top, Line base `(0,0,0)`, raw
pick `(3.22,1.29,0)` and a 0.5 mm step. The source-derived calculations
give `(3,1.5,0)` for direction selection, `(2.255,2.255,0)` after
projection, and `(2.5,2.5,0)` after selecting the grid crossing. OM9
currently projects the grid-quantized point directly, which predicts
`(2.25,2.25,0)` for that same raw input. A single desktop click that
lands at the same result in both apps does not verify this distinction.

The call targets and argument slots were checked against the installed
Rhino 5 executable from the preceding receipt. A separate arithmetic
check verified the three coordinates with the exact input above.
The native calculation also uses `floor(local/step + 0.5)` for grid
rounding, whereas the OM9 implementation at the time used Rust `round()`. Negative half-step
ties therefore differ. The actual Matrix9 endpoint and human UI gate
remain pending.
