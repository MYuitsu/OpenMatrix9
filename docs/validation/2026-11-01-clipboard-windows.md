# Windows clipboard and shortcuts — 2026-11-01

Standalone debug OM9 now routes Ctrl+C to OM9 object payload, Ctrl+Shift+C to Rhino 5 3DM payload, and Ctrl+V according to the available geometry format. Edit has separate Copy, Copy as 3DM and Paste entries; Standard toolbar Copy/Paste share those actions. A native window subclass captures these keydowns because egui-winit otherwise converts Ctrl+C to a text event and may emit no Ctrl+V event for non-text clipboard formats. Text selection, nonempty Command drafts, other text editors, IME, active commands and modal dialogs retain their input. Plain text paste into an empty Command field is left to the editor.

The Windows adapter materializes the prior OLE clipboard's supported memory formats before publishing, refuses unsupported/unbounded prior formats, and attempts to restore the detached prior object if flush fails without overwriting a newer clipboard owner. OM9 uses a versioned length envelope; Rhino uses `Rhino 5.0 3DM Clip global mem`. A paired OM9 layer-metadata format is read and validated but paste currently rejects it rather than silently dropping it.

On Windows, `cargo test -j 2 -p om9-native-owner --lib clipboard::tests -- --include-ignored` passed three tests: envelope validation, actual OLE copy/read with injected flush failure and restored text, and native window keydown distinction. `cargo test -j 2 -p om9-app --test clipboard_om9 --test pinned_command -- --include-ignored` passed 16 tests, including an actual native 3DM line import/export and Undo, block and group remapping, nested layer cross-document paste, and text editor regressions. `cargo test -j 2 -p om9-core --test lazy_layer_assignment --test layer_transactions` passed 18 tests, including cycle and locked-layer rejection. The source audit passed with zero errors. All Cargo runs used `CARGO_TARGET_DIR=L:/om9-target`.
