# Launcher r2: Start Menu and background update check

The user approved adding a Start Menu icon and an automatic release check to
the existing launcher. Desktop and Start Menu → OpenMatrix9 use the same cached
PowerShell bootstrap and supplied OM9 icon. Download/extract a new bundle and
run its Start-OM9.cmd to update; the launcher never downloads/installs a plugin.

After starting FreeCAD, a separate hidden Windows PowerShell process queries
the public MYuitsu/OpenMatrix9 releases API anonymously. It accepts exact
versioned Windows x64 setup asset names and the repository's release/download
URLs. Numeric version comparison prevents downgrades; launcher revisions allow
updates within the same application version. Published experimental releases
are labeled in the notification; drafts are ignored. A notification appears
once per offered version/revision, with an optional download-page link.

HTTP/read timeouts and response size are bounded; connectivity, rate-limit or
parse errors are recorded in OM9-launcher/update-check.json. The check runs
after GUI launch and cannot prevent startup. -SkipUpdateCheck skips it for a
single launch; -NoDialogs records availability without showing a notification.

This is Windows deployment bootstrap only: .NET HTTP/version/file APIs and
Windows Shell shortcut/notification adapters stay in PowerShell. No portable
CAD/model logic moved from Rust, and no native module, worker or FreeCAD rebuild
was needed. Updating bootstrap metadata alone verifies the full unchanged
payload and avoids replacing a loaded module. True payload changes still require
closing the host using an existing installation; a fresh isolated installation
is allowed while an unrelated host is open.

Fresh [installer tests](launcher-r2-0.0.2/installer.json) passed 26 checks.
[Updater/shortcut tests](launcher-r2-0.0.2/updater.json) passed 17 checks, including
new/old versions, same-version revisions, drafts, foreign URLs, unsupported
platforms, numeric ordering, offline handling, silent checks, notification
deduplication, both icons and a redirected Programs junction.
[Native integration](launcher-r2-0.0.2/native.json) passed 21 checks on official
FreeCAD 1.1.4: initial/cached/repeated startup, actual Start Menu .lnk activation,
unchanged native file timestamp, icons and live GitHub background checking.
The actual Start-OM9.cmd wrapper also passed installation and Start Menu creation
with a profile path containing spaces, using the Windows-provided PowerShell.

Independent review caught incomplete payload-set comparison and rejection of
redirected Programs folders. Complete payload fingerprints, legacy manifest
inventory fallback and regression checks now detect removed helpers and preserve
the native guard. Windows Known Folder Programs supports redirected paths without
recursive operations; custom shortcut paths retain the plain-path check.

Both icons were installed in the user's actual OneDrive Desktop and Start Menu
while the existing OM9 GUI remained open. Its live check returned current.
Physical-volume reads matched 541 plugin files, four launcher files and confirmed
the physical Start Menu shortcut. See [summary](launcher-r2-0.0.2/summary.json).
