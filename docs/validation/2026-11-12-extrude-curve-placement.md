# Extrude Curve Straight: placed curves after reopening

Before the fix, a saved/reopened 4 × 2 mm rectangle with placement scale (2, 3, 2) and translation (10, 20, 30) extruded with `ExtrudeCrv 5` at the origin: measured world bounds were `[0, 0, 0, 4, 2, 5]`, rather than `[10, 20, 30, 18, 26, 35]`. The regression failed through the product Controller before the fix.

`solid_extrude` now transforms the world construction-plane direction into each source curve's local coordinates using the inverse placement's linear part and applies the source placement to the resulting B-rep. This preserves the intended world-space direction and height, including non-uniform scaling, without replacing the source curve or splitting the existing transaction.

`extrude_reopened_curve_respects_affine_placement_and_world_height` passed for the saved/reopened rectangle with non-uniform scale, in-plane rotation and shear, with CMD and menu dispatcher routes. It compares OCCT source world bounds against independently calculated bounds and checks full document Undo/Redo. `extrude_all_uses_each_curve_placement_in_one_transaction` passed for two translated rectangles and verifies each result's bounds and one full Undo/Redo. The existing Solid workflow suite passed 114 tests with one native UI fixture ignored; the Solid integration suite passed 198 with one ignored. Its existing `extrude_all_is_one_atomic_transaction` also verifies a late invalid curve retains document and Redo. Debug executable build and public source audit passed.

These tests cover the stated rectangle placements, not all affine transforms, circle/NURBS varieties, construction planes, imported files, native peak allocations or desktop clicks. Menu dispatcher invocation is not a GUI click. Source git objects: `solid.rs` e13f938d60cfc4d644382e69ee6d70c286459774; `solid_input_regressions.rs` 5197a392fee54e107bee699d9269fd06c0e7b61d.

Follow-up: `extrude_reopened_reflected_circle_uses_active_cplane_direction` passed for a radius-2 mm circle in the YZ plane after save/reopen, with reflected non-uniform placement and an active construction plane whose normal is +X. The 5 mm extrusion matched independently calculated world bounds and analytic volume 120π mm³, and full document Undo/Redo passed. The focused `extrude_` batch passed three tests. This adds only the described circle, placement and construction plane, not all curves, placements or planes. The current `solid_input_regressions.rs` git object is 7d20290b1b33ca713349f68ef0ab03de59d30344; the production `solid.rs` remains the object listed above.

The user approved recording the earlier tested rectangle behavior in the feature-port skill; the repository and installed copies were synchronized and their skill validator passed. That approval does not assert general Matrix behavior or expand the listed test coverage.

## Document units

In a centimetre document, `ExtrudeCrv 2` previously used 2 mm instead of the contract's 20 mm. The shared Solid dispatcher now converts the bare numeric height from document units to millimetres once, for both ExtrudeCrv and ExtrudeAll. Controller tests exercise command and menu input, positive and negative heights for a translated saved/reopened rectangle, and two separately placed ExtrudeAll sources; independent world bounds and complete Undo/Redo snapshots match. The Solid input regression group passed all 97 tests. These tests do not establish support for explicit unit suffixes, every curve type or desktop clicks.

An additional case in `extrude_reopened_curve_respects_affine_placement_and_world_height` used the reopened rectangle with non-uniform scale and `ExtrudeCrv -5`. OCCT source world bounds were checked against `[10, 20, 25, 18, 26, 30]`, and full document Undo/Redo passed. The focused `cargo test -p om9-app --lib extrude_ --target-dir L:/om9-target -j 2` batch passed three tests. This verifies one negative-height placement, not every input mode or viewport preview.
