# Boolean in the scaled object's local frame: downstream check

The existing sphere/box fixture was retested by mapping the world sphere into the local frame of the nonuniformly scaled box, retaining the box's placement instead of baking the result back into world coordinates. At output profiles 0.5 and 0.01 mm, checked Union and sphere-minus-box pass independent analytic local volume and local/world bounds assertions. This confirms more than the earlier single Union volume measurement for these two operations, but does not establish general affine correctness.

In the same fixture, checked box-minus-sphere and Intersection are rejected by `BRepAlgoAPI_Check`. The unchecked kernel API produces shapes whose volumes and local bounds match the analytic values at both profiles, with one closed solid and no naked edges. These measurements do not prove that those shapes are valid or that relaxing the checker is safe. The unchecked test does not change the product's checked path.

A controller test constructs the checked local Union result, saves and reopens it with the original scale placement, then attempts another Union with the local box. The checked downstream operation is rejected by OCCT result validation; the document and a pre-existing Redo are preserved. This demonstrates that merely retaining the local result is insufficient to deliver the fixture as a generally reusable product workflow. No product code or business behavior changed in this follow-up.

Verification: kernel Boolean 85 passed/1 ignored; Solid controller 91 passed; the explicitly run exploratory all-modes check failed on checked reverse Difference and Intersection at both profiles. The checked Union and forward Difference and the unchecked measurement controls are permanent regressions. No desktop, native peak, arbitrary imported topology, global geometric error or world-space tolerance evidence was obtained. Next work must establish why OCCT's result check rejects these outputs and whether an exact repair can preserve topology and small valid features; do not bypass the check based only on volume and bounds.

## OCCT rejection diagnostics

Temporary native diagnostics examined the raw checked result at the actual Boolean bridge. The local-frame reverse Difference and Intersection produced `BOPAlgo_OperationAborted`; the small-edge-only check passed, whereas the self-interference-only check did not complete successfully. A direct `BOPAlgo_CheckerSI` run with the same result reported `BOPAlgo_AlertIntersectionFailed` at both profiles. This means the self-interference verification failed; it does not establish either self-intersection or a valid shape. In contrast, the earlier wrong baked-affine Union produced `BOPAlgo_TooSmallEdge` in both input orders and both profiles. The [OCCT 8.0.1 argument analyzer source](https://github.com/Open-Cascade-SAS/OCCT/blob/V8_0_1/src/ModelingAlgorithms/TKBO/BOPAlgo/BOPAlgo_ArgumentAnalyzer.cxx) maps errors from `BOPAlgo_CheckerSI` to the aborted status.

The temporary diagnostic calls and logging were removed. The product bridge continues refusing the same results but now distinguishes an aborted self-interference check and a detected small edge in the error text; other OCCT statuses retain the generic message. The saved/reopened downstream Union fixture still gives the generic status, so it is not claimed to have the same cause as the two local-frame operations. Kernel Boolean 85 passed/1 ignored and Solid controller 91 passed after this change. These fixture-specific diagnostics are not evidence that disabling self-interference checks is safe or that the underlying Boolean defect is fixed.

## Face-level investigation

Temporary `BOPAlgo_CheckerSI` instrumentation ran check levels 0 through 9 on the rejected local-frame reverse Difference and Intersection results. At both output profiles, levels 0–4 reported no algorithm error; level 5 and higher did. OCCT's `BOPAlgo_CheckerSI.hxx` defines level 5 as adding face/face checks, including the algorithm's face self-intersection phase. On the first profile only, each result was decomposed into single-face and two-face diagnostic compounds. A single face with `GeomAbs_BSplineSurface` was sufficient to reproduce the checker error in each operation; combinations containing that face also reported errors. These are diagnostic compounds, not independent proof that the original face self-intersects, and face indices are not persistent identities.

On the first profile, temporary `ShapeUpgrade_ShapeDivideClosed` with one split point and `ShapeUpgrade_ShapeDivideArea` in splitting-by-number mode with one U and one V split were tried on each rejected result. In these exact configurations both reported no change, and the result check still failed. This is not an evaluation of every split setting or proof that no exact topology repair exists. All instrumentation and repair trials were removed. The final native bridge's git object is `f0211b31b062473f0d7c705742987a68ed68ea90`; the configured kernel Boolean suite then passed 85 tests with the original affine Union reproducer ignored. No product behavior changed and native peak and desktop remain unmeasured. Next investigate the failing BSpline face's parameterization and the OCCT face/self-intersection error before attempting a constrained exact repair.

## Segmentation and topology repair experiment

On the first profile, the isolated failing surface was a rational degree-2 B-spline, periodic in U, with face U bounds approximately 0–1.5332 and underlying surface U bounds 0–2π. A copied surface was made nonperiodic and segmented to its face UV bounds; a newly constructed rectangular patch passed the B-rep and isolated level-5 checks. A 9×9 grid comparison found a maximum point difference of approximately 2.81e-15 mm. The patch did not preserve the original trimmed face topology, and the sampled comparison does not prove global equivalence.

In a separate temporary experiment, a custom OCCT splitter split periodic B-spline surfaces at their U midpoint and then ran `ShapeFix_Shape`. Splitting alone failed result validation; the fixed output passed both B-rep and Boolean result checks for this fixture. Face counts changed from 8 to 10 for reverse Difference and from 3 to 5 for Intersection. At both profiles, the resulting checked shapes matched the independent analytic volume and bounds within 1e-5, with one closed solid and no naked edges. This does not prove preservation of all geometry, trim boundaries, topology identities, tolerances, or small features.

With additional temporary changes choosing the scaled operand's local frame and enabling this unconstrained repair, the saved/reopened sphere–box fixture exercised all five Boolean Two preview modes at both profiles, through menu and command invocation, with Undo/Redo. A separate saved/reopened local Union result could also be used in another Union, with expected volume and Undo/Redo. The known wrong baked-world Union control remained refused in both operand orders, but a single control does not establish a safe general repair. The experimental frame selection, automatic repair, logging, and temporarily altered controller expectations were removed; the bridge is again git object `f0211b31b062473f0d7c705742987a68ed68ea90`. The shipped path still refuses the affected case.

Next, determine whether a narrowly bounded repair can preserve the actual trimmed geometry and tolerances, topology identity and small features, with safe failure and resource admission. Include operand ordering, imported geometry, later operations, Undo/Redo and desktop evidence before enabling it. Neither native peak memory nor general geometric equivalence was measured here.

## Interior oracle and tolerance investigation

The same temporary periodic-surface split and shape fix were repeated inside the checked bridge for the local-frame reverse Difference and Intersection fixture. An independent analytic ellipsoid/box membership formula was compared with OCCT point classification on a 13×13×13 grid for each operation and each display profile: 2,197 points per case, 8,788 classifications of the repaired solids in total, with no mismatches or inconclusive states. The same points also matched on the original raw results. This is a sampled interior oracle; it does not establish trim-boundary equivalence, small-feature preservation, or global correctness.

Serialized input A, input B, and raw Boolean result were byte-identical before and after the splitter/fixer in these four diagnostic cases. This does not prove non-mutation for other shapes or shared ownership scenarios. The maximum OCCT tolerance over vertices, edges and faces was approximately 5.000001e-6 mm on the original result and 1e-5 mm after repair in all four cases. A further run measured the maximum immediately after splitting, before `ShapeFix_Shape`: it was already 1e-5 mm. Setting the fixer's precision to 1e-7 mm and maximum tolerance to 5.000001e-6 mm did not reduce it; a 5×5×5 membership sample still matched in each case. These are stored topology tolerances, not a measured geometric displacement or proof that every individual tolerance increased. The configured bound was on the fixer, not on the preceding divider.

Consequently, a product repair must control or explicitly validate the splitting stage's tolerance against the document contract as well as verify its geometry; the earlier default split-and-fix is not suitable for unconditional publication. Diagnostic code was removed and the original native bridge restored. The independent grid and mutation checks are fixture-specific; imported shapes, near-boundary accuracy, native peak and desktop remain untested.

## Divider limit and near-surface samples

An additional temporary diagnostic set `ShapeUpgrade_ShapeDivide` precision and minimum tolerance to 1e-7 mm, and its maximum to the original result's maximum topology tolerance (approximately 5.000001e-6 mm). The subsequent fixer used the same precision and maximum. For reverse Difference and Intersection at both profiles, the divided and fixed shapes still had a maximum tolerance of 1e-5 mm. The repaired shapes passed `BRepCheck_Analyzer` and `BRepAlgoAPI_Check`, and serialized inputs and raw result were unchanged in each case. The [OCCT 8.0.1 divider source](https://github.com/Open-Cascade-SAS/OCCT/blob/V8_0_1/src/ModelingAlgorithms/TKShHealing/ShapeUpgrade/ShapeUpgrade_ShapeDivide.cxx) passes its configured maximum to the face tool, and the [face divider source](https://github.com/Open-Cascade-SAS/OCCT/blob/V8_0_1/src/ModelingAlgorithms/TKShHealing/ShapeUpgrade/ShapeUpgrade_FaceDivide.cxx) in turn passes it to the shell composer. This experiment does not determine which internal operation produced the greater recorded tolerance; a caller cannot assume that the setter alone is a postcondition.

An analytic sample used nine locations on the upper ellipsoid surface, offset along local Y to either side by 0.001, 0.0001 and 0.00001 mm. All 54 points per operation and profile, 216 classifications in total, agreed with the expected region and none was inconclusive. These are directional samples, not a shortest-distance or global boundary error bound; the fixed geometry's stored tolerance is not itself a measured displacement. The diagnostic was removed, and the shipping path remains unchanged.

The original raw result's maximum is a useful experimental reference, not automatically the document's limit. OM9's template absolute tolerance is 0.001 mm, while `Document::new` can represent a document with no tolerance and documents may override it. A future repair must use the actual document policy, account for how a nonuniform placement maps local to world tolerances, and reject unsupported or excessive cases; it cannot invent a policy for a document that lacks one. The fixture has no controller document tolerance and does not establish that its 1e-5 mm local topology tolerance meets any particular document's contract. The next product step is to trace document tolerance and placement through the actual Boolean path and define a bounded, fail-safe repair before considering publication.

Tracing the current controller shows that grouped Boolean, Boolean Two preview, and Union pass output display deflection and resource limits to `editing::boolean_checked`, but not the document tolerance. Common affine placement may retain the result in the selected frame; an optional repair therefore cannot compare a local topology tolerance directly to a world-space document tolerance without accounting for the frame. This observation describes the current call path; it does not establish that ordinary Boolean already enforces the document tolerance, or authorize treating display deflection as a substitute.

## Baked affine intersection regressions

Permanent kernel tests cover intersection between a radius-3 sphere and the box with scale baked into its source. For a sphere centered on the box boundary plane, both operand orders at both profiles are refused by the existing OCCT validity guard; the test also allows a future nonempty result only if its volume matches the analytic hemisphere. For centers at x = -0.5, 0.2, 0.5 and 1 mm, both orders and both profiles produced nonempty results matching the analytic spherical-cap volume within 1e-5 mm³ (16 combinations). These observations do not prove all output faces or arbitrary transformed input are correct.

Controller regressions save and reopen the input first. Two offset fixtures, one per profile and one each via menu dispatcher and command invocation, produced the expected analytic volume and restored the document through Undo/Redo. Two centered fixtures, likewise across the profiles and invocation routes, were refused while preserving the document and an existing Redo. The tests establish existing behavior; they do not change production Boolean or fix the centered fixture. A menu dispatcher is not a desktop click, and imported topology, peak native memory and desktop remain untested.

## Near-centered false-empty intersection

**Update:** the checked Intersection witness guard was subsequently implemented and the previously ignored kernel regression is active and passes. See [the follow-up validation](2026-11-12-intersection-false-empty-witness.md) for its scope and limits. The paragraphs below record the earlier observed state.

A follow-up kernel regression tested sphere centers at ±0.001, ±0.0001 and ±0.000001 mm, both operand orders and both output profiles: 24 combinations. All 12 negative offsets returned `Empty` despite the analytic spherical cap being nonempty; all 12 positive offsets returned errors. None produced an accepted body in this sample. The regression intentionally fails on false Empty and is temporarily ignored until addressed; error returns are counted without asserting a particular error. This result is not a proof about arbitrary topology or all offset values.

The grouped Intersection controller rejects an `Empty` outcome before deleting inputs; Boolean Two preview can show an empty result, but its commit requires a body. These call paths should not be read as a guarantee for other callers. A potential follow-up is a bounded numerical interior witness in both solids, analogous to the existing Difference diagnostic: finding such a point disproves an empty intersection, while failure to find one does not prove emptiness. This remains unimplemented and awaits the user's decision; native resource use, topology and numeric limits still require validation. The first attempted kernel command omitted the `3dm-brep` feature and failed linking; the configured feature-enabled command ran the diagnostic.

The reopened controller regression additionally checks offset -0.001 mm at both profiles through menu dispatcher and CMD: each rejects the empty body and preserves the complete document and Redo. The kernel suite then passed 87 tests with two known issues ignored.
