# Object bounds through SDK v1 — 2026-10-21

A plugin can now read one object's object-local bounding box, size and center: a point's
position, a curve's 33-sampled points, or a mesh's vertices. Owner: `OM9-L2-03-20`
(`OM9-L3-03-20-003`).

## Changed

| Layer | Change |
|---|---|
| Public SDK | `ObjectBounds { min, max, size, center }` and `Host::object_bounds(id)`; one request and capability entry. |
| Host | Matches the geometry: point position, `surface_kernel::sample_curve(curve, 33, limits)` for a curve, mesh vertices (bounded to 100k); other kinds are `unsupported`, and an empty point set is `bounds`. The placement is not applied. |
| Example plugin | `BoundsDemo {"id": …}` returns the bounds. |
| Tests | Host test for point/line/mesh bounds; native DLL test that a profile line reports min `[0,0,0]`, max `[10,0,0]`, center `[5,0,0]` without changing Undo. |

## Semantics fixed by this slice

- Coordinates are object-local millimetres; the placement matrix is not applied, so a plugin
  composes it exactly once.
- A curve uses the owner's fixed 33-sample sweep (the same one `curve_semantics` uses), so
  bounds are a sampled measurement, not an analytic bound.
- Unsupported geometry kinds are refused instead of returning an empty box; an object with
  no sampled point is `bounds` rather than `[inf, inf, inf]`.
- Reading stages no mutation.

## Not proved here

- Bounds are sampled for curves (33 points), not an exact analytic box.
- B-Rep/surface/cloud bounds are not exposed; grouping bounds and jewelry count summaries
  remain open.
- macOS host and plugin execution are unverified; interactive UI acceptance was not
  performed. No manual or M09 gate was promoted.
