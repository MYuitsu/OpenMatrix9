# Cap Planar: reopened cylinder at two display profiles

On 2026-11-12 the default-feature standalone controller test `cap_planar_cylinder_source_is_independent_of_display_profile` created a radius-2 mm, height-5 mm OCCT cylinder, removed its top face and tessellated the same open-shell source at deflections 0.5 and 0.01 mm. It asserted that the two displays have different triangle counts, saved each translated shell in OM9 v4, reopened it, and invoked Cap Planar via the menu dispatcher for one profile and CMD for the other. Each result retained placement, was a closed solid without naked edges, matched the analytic volume 20π mm³ within 1e-6 mm³, and restored the full before/after documents with one Undo/Redo.

Command: `cargo test -p om9-app --lib cap_planar_ --target-dir L:/om9-target -j 2`. Six tests passed, including existing multiple-shell atomicity, late invalid input, multiple loops, annular hole and partial shell fixtures. Current git object hashes: `solid_input_regressions.rs` e914ca366602db09ea119c5a1a5585e04cf194bd; `solid.rs` 2dc87c0505ff248f9b293b81a18ad119b76a800c. Public source audit passed.

The source-first controller path uses `editing::cap_planar`; its output display deflection comes from the input display. This fixture proves the listed cylinder and two profiles, not invariance for arbitrary surfaces, curved or intersecting openings, imported models, native peak memory, actual menu clicks or desktop interaction. Menu dispatcher invocation is not a GUI click. The hardcoded 1e-7 mm cap tolerance and existing feature limits remain as documented; no product behavior changed in this batch.
