# STL document-derived deflection: partial P3a

The existing STL path no longer selects OCCT tessellation deflection from the editable B-rep's display mesh. It takes the captured document's absolute tolerance as a requested world-space quality target, reserves half for tessellation and divides by `sqrt(||A||_1 * ||A||_inf)` for the placement's linear part. This is an upper bound on the Euclidean transform norm; it is not proof that OCCT or the whole conversion chain satisfies the target. NativeBrep import uses the same local request. The current sampled NURBS surface grid now uses the document tolerance in world coordinates rather than the previous 0.01 mm constant. Receipts explicitly state that global deviation is unverified for both OCCT tessellation and sampled surfaces.

Windows default features including OCCT, `CARGO_TARGET_DIR=L:/om9-target`, Cargo `-j 2`: `cargo test -p om9-app -j 2 --test stl_export` passed 16 tests. One test creates the same canonical sphere with display deflections 0.1 mm and 0.02 mm and verifies byte-identical STL output with the same document tolerance. Another exports a 5 mm radius sphere with nonuniform placement `(3,1,0.5)` and checks each encoded triangle centroid against its corresponding analytic sphere point after inverse scaling; the maximum of those sampled distances was no greater than 0.001 mm. This correspondence distance is an upper bound on point-to-ellipsoid distance at those sampled points, not a global surface/coverage bound.

The first attempted version allocated the entire requested tolerance to local OCCT deflection. The nonuniform test's largest radial-correspondence distance was 0.0013556664669909888 mm, so it did not satisfy this test's conservative oracle. The final version uses half the target for the deflection request and passed that fixture. The factor is a budget allocation, not a proven OCCT error multiplier; different shapes, shape tolerances, weld effects or placements may still exceed the requested target.

The export UI does not yet expose independent linear/angular settings, no certified deviation or total error budget has been implemented, and standalone NURBS still uses a bounded sampled grid rather than the planned exact kernel path. Weld quantized keys, native-transient reservations, profile capture/background execution, GPU budgeting, checkpoints and desktop/release performance remain open. No existing live OM9 window was manipulated. Next: implement and validate weld range/distance handling, export profile UI/worker and independent source-to-mesh coverage against the remaining plan.
