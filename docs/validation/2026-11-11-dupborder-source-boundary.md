# DupBorder: source boundary after v4 reopen

A product regression constructs a cylinder shell whose valid stored topology and display edge order are consistently permuted, saves it as v4 and reopens it. Before the change, `DupBorder` used persisted face/edge adjacency and then treated its edge indices as positions in a newly read OCCT map. It returned the cylinder's longitudinal seam instead of one circular boundary: the analytic oracle observed `[2, 0, 1.25]` on the wrong output.

The product now asks the OCCT adapter to count edge occurrences in source faces and emit edges occurring once from the same source read and native map. The seam occurring twice in the cylinder's face is excluded. Rust owns the reservation, placement, output and one transaction; native OCCT and the bounded native incidence/index vectors remain outside the Rust allocation accounting. This is a correctness fix for the existing boundary contract, not proof of arbitrary legacy files, non-manifold topology, standalone wires, all seams or all imported representations.

The reopened regression checks both circles at five parameters, source preservation and one Undo/Redo. Six `dup_border` tests passed, including object-count refusal and a simulated managed-memory refusal that preserves the document/Redo and succeeds after pressure is released. In the shared-adapter batch, `wireframe` passed 36 with three diagnostics ignored and `curve_menu` passed 6. The debug executable was built with `-j 2` at `L:/om9-target/debug/om9.exe`; it was not exercised on desktop. Public source audit passed and `git diff --check` passed. Native/process peak is not measured.

Follow-up: the first implementation incorrectly applied `max_outputs` to all three source edges, including the seam that is not output. A kernel regression with a two-output limit reproduced the refusal; after correction it returns the two boundaries and rejects a one-output limit. The seven-test `dup_border` group and the shared `wireframe` group passed; the final one-output assertion was rerun separately. Source topology remains bounded by `max_nodes`.

Further controller validation: a reopened four-face rectangular shell produced exactly eight distinct analytic open boundary edges, excluding the four edges shared by adjacent faces; one Undo removed all eight and Redo restored them. A closed Box returned an error with document and existing Redo unchanged. The full `dup_border` group then passed 9/9. This extends the tested topology to this particular multi-face shell; non-manifold and general imported topology remain open.
