# Background history scene preparation

Follow-up: candidate validation subsequently moved to the worker; see [background history candidate validation](2026-11-13-background-history-validation.md). This record describes the earlier verified build.

2026-11-13. UI Undo/Redo through the Edit menu, history/standard toolbar, CMD `Undo`/`Redo`, and Ctrl+Z for Undo now request a worker to construct the candidate scene. The existing current world and scene remain published while it runs. A coordinator guard prevents document/history mutation until the worker has returned; concurrent UI commands are refused, and the UI is disabled while waiting. Escape requests cancellation. The guard remains until the worker returns, because the current scene build is not interruptible within a scene-capture call. Before publication the controller checks scene publication and root/subselection revisions; the coordinator checks candidate context, stack head, memory account and retained-owner budget. Failure, cancellation or stale context discard the candidate and keep the previously published world/stacks. Changes independently made to selection are not overwritten.

The worker uses a shared-account admission peer. Explicit reservations cover the current scene/auxiliary usage and the primary coordinator's full unshared metadata while the peer constructs the candidate, in addition to the candidate map and scene reservations. A further 4 KiB allowance is used for the worker envelope; it is not a measured bound for the OS thread stack or channel internals. This accounting is conservative in some places and may reject work earlier than an exact shared-owner model. On completion the temporary metadata charge is released before publication. The worker uses the display already retained in the candidate document; candidate creation and validation still run on the UI caller, so large-history responsiveness is not established. Programmatic `Controller::undo`/`redo` remain synchronous, as do Open and cache-miss restoration. Native allocations, process/GPU peak and physical out-of-memory behavior were not measured.
