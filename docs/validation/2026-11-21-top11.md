# Top11 command routes and geometry

The eleven buttons in the left Main Menu use the standalone command controller. A published feature ID and its TopIcon catalog key resolve to the same action. The Ring Rail entry uses the Tools session when Matrix supplies it and the existing Ring Rail builder in the standalone profile.

## Source mapping

The recovered Matrix command registry identifies the actions bound to each mouse button. The M03 L2-03-08 records identify the manual pages and the expected CAD behavior. Book 1 printed pages 71-78 cover the Top Icons. The normalized command references supply the curve and surface operations. The original exports and manuals stay in the private reference tree. [Matrix command registry](../analysis/matrix-command-layers.md#top-icons)

| Button | Reused implementation and verified behavior |
| --- | --- |
| Duplicate | Existing interactive Copy controller. The source and duplicate have independent object identities. |
| Edit Points On | Existing edit-point controller for curves and surfaces. Selecting grips and editing the surface use the source geometry. |
| Control Points On | Existing control-point controller. Shared polycurve joints retain their incident endpoints. |
| Mirror | Existing reflection and copy transaction. Secondary click supplies the world origin as the first point. |
| Move | Existing placed-object transform and viewport point input. |
| Rotate | Existing rotation controller. Primary click moves the input. Secondary click enables Copy, including when selection follows invocation. |
| Explode | Existing polycurve, mesh and BRep decomposition. Dimensions produce linework and editable text. Text preserves glyph lines, quadratic or cubic curves and holes. The eight-pole OM9 cage produces six boundary surfaces and twelve edges and releases linked objects. |
| Join | Existing curve join and surface sewing. Retained 3DM inputs are converted from source. |
| Split | Existing exact cutters and surface partitions. Secondary click starts point splitting for a curve. |
| Trim | Existing portion selection and source partitions. ExtendLines extends a line cutter over the target. ApparentIntersections uses the command camera to compute curve parameters on the original target. |
| Ring Rail | Shared Tools builder or standalone entry. Apply and Enter confirm the rail in the active session. |

## Windows checks

Two disposable desktop sessions each ran all eleven published feature IDs through the live application. One profile used safe mode and the other loaded the Matrix native add-on. On the three-line fixture, Move and Rotate kept three objects, Duplicate and Mirror produced four, Join produced two, and Explode restored three. Split produced four. A Trim pick added one history entry. Ring Rail produced a fourth object with one additional history entry. Grips left history unchanged. These counts describe separate cases with Undo between edits. A second comparison applied the stored placements and matched the world endpoints, joined segment sets and final ring circle in both profiles. The ring radius was 9 mm at the origin.

Physical mouse input on a separate scratch drawing exercised secondary Rotate before selection, secondary Mirror and secondary Split. Rotate created a second circle and Mirror reflected that copy. Split entered point mode on the selected circle. A primary Ring Rail click opened the builder and Apply created an 18 mm rail in the viewports. The source and Undo checks for completed splits ran through the live controller and integration tests.

Native tests used a retained 3DM face for Join, Split and Trim and checked face counts, area and Undo. Archive tests use canonical sources, topology evidence, the packaged workers and reopened geometry. Other cases cover a dimension with a counter in its label, cage release, recovery from refusals, interactive options, mixed selection and unchanged geometry on cancel. The 96 by 96 surface grip test keeps its existing 500 ms move threshold.

The headless command interface also created an 8 by 6 by 5 mm box, exploded it into six BRep faces, saved archive version 6 and reopened the same six source objects. The four-camera render of the reopened archive is available in the [Windows capture](../../build/standalone-validation/ui-artifacts/2026-11-21-top11/exploded-box-four-views.png).

## Reproduction

The validation manifest under build/standalone-validation/ui-artifacts/2026-11-21-top11 points at the repository's test files and production application. Cargo used the existing external target with two build jobs. The manifest used the production application with OCCT and test-fixture worker discovery. The desktop executable used the normal application entry point under a separate executable name so the open user drawing could remain in its original process. The production archive workers were identified by their SHA-256 fingerprints at compile time. The profile replay and its per-action receipts, object counts and Undo depths are in the same run directory. A standalone check without OCCT exercises the portable build.

The scoped Cargo run passed 376 cases. These comprise 152 application command cases, 44 core cases, 88 BRep cases, 14 command options cases, 10 Builder cases, 50 Transform menu cases and 18 selection, gesture and layer cases. The Top11, Tools, Transform and Matrix add-on packages passed 31 more cases. The Matrix package's existing cross-menu silent-finish inventory is marked ignored. Logs for the four commands are stored beside the capture.

Run these commands from the repository root with the external target and worker environment described above. The application tests use a scoped manifest to avoid the workspace's unrelated Gem Tools dev-dependency conflict.

```powershell
cargo test --manifest-path build/standalone-validation/ui-artifacts/2026-11-21-top11/Cargo.toml --offline -j 2 --tests -- --test-threads=1
cargo test -p om9-addon-top11 -p om9-addon-tools -p om9-addon-transform --offline -j 2
cargo test -p om9-addon-matrix --offline -j 2
cargo check -p om9-app --no-default-features --offline -j 2
```

The native fixture covers supported boundary representations. ApparentIntersections evidence covers projected curves. Tests used the packaged font for text and the current eight-pole OM9 cage. This run did not reopen results in commercial Rhino or certify every imported font, cage type, graphics driver or display mode.
