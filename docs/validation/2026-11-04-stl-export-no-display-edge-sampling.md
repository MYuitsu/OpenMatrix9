# STL export snapshot without display edge sampling

The OCCT grouped export snapshot used for STL edge-node bindings no longer runs `GCPnts_QuasiUniformDeflection` to build viewport edge polylines. Face triangulation, face/edge ownership, canonical vertex points and native edge-to-mesh bindings remain. Ordinary display snapshots and grouped snapshots without export bindings still sample their edges. The Rust `EdgeTopologySnapshot` documents that the export-only mesh lacks viewport edge polylines. This is a scoped native adapter exception: Rust still owns copied data and the native objects remain local to the operation.

A real OCCT box fixture compares the ordinary grouped snapshot to the export snapshot at the same deflection and angle. The ordinary snapshot had 56 points and 12 edge segments; the export snapshot had 32 points and no segments. Both had the same 12 triangle records and identical triangle-point coordinates and shell owners; export bindings were nonempty and pointed to mesh vertices. This is a count for one box, not a process memory or speed benchmark. The output still contains canonical vertex points, topology metadata and other buffers; neither native OCCT meshing allocations nor all export allocations are bounded by this change.

Default-feature debug tests used the pinned OCCT/openNURBS adapter, target `E:\om9-surface-snap-validation`, and Cargo `-j 2` with OCCT/TBB/jemalloc runtime paths. Ten kernel edge-site tests passed (including the new comparison), 60 serial STL integration tests passed in 110.21 seconds including source/display separation, sphere sampled-error probes, thin gaps, cavities, NURBS and repeated instances, and 48 STL session tests passed. One focused rerun printed the counts above. No release A/B memory measurement, physical desktop test, global tolerance certificate, general topology equivalence or complete GPU/RAM admission was established.
