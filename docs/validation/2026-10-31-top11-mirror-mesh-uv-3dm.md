# Top11 Mirror mesh and staged 3DM regression

On Windows x64, a triangle plus quad mesh with distinct per-corner UVs reproduced Mirror's incorrect quad winding before the fix. The Rust implementation now reverses each face boundary and its matching UV corners together. The regression exercises CMD and toolbar entry, Copy=Yes/No, translated placement, `.om9` save/open and Undo/Redo. It does not establish full desktop input or rendering acceptance.

The native 3DM writer had rejected every current serialized mesh because it did not admit the `corner_uvs` field. It now admits an empty channel and explicitly rejects a populated one before publication; UV-preserving 3DM conversion remains open. A second pre-existing defect projected every line-only polycurve as a normalized polyline even when its segment domains differed. The writer now uses the normalized projection only for normalized segment domains, and otherwise uses a polycurve subject to its existing contiguous-domain admission. This keeps the tested contiguous domains through cold validation; arbitrary polycurve domain mappings remain open.

Validation: `om9-app` Top11 104 passed, `om9-core` Top11 30 passed; all 9 explicitly invoked real-native staged export tests passed, including populated UV refusal without destination replacement and the previously failing mixed-kind fixture. Three explicitly invoked authored-fixture tests passed for mirrored nested blocks, mirrored retained BRep and placed editable BRep. The first attempted mirrored-fixture run failed before starting the native process because the SHA-256 admission environment variable was absent; the correctly configured rerun passed. Public source audit returned no errors. Artifact pruning removed no runs; 116 older cited runs remain protected by the pruning tool.

The four previously reproduced cold-retained failures came from test fixtures expecting layer color while newly created entities now default to an explicit color. The fixtures explicitly select layer color to match the independently constructed native reports; all nine cold-retained tests then pass without changing the correspondence checks. The complete default `om9-exchange` suite also passed; its native-dependent ignored tests are excluded from that statement. This does not establish that the real retained-file pipeline is fully verified.

The selected native adapter exception is limited to openNURBS serialization. The Windows native executable was rebuilt with the pinned openNURBS revision `eb92af3ba1806b0a34a99aba0d3bda83e3d46083`; SHA-256 `d2e2ae9501a23b0568c28359f8d25058f249c85636598b8a76ba2c07bc98b1ab`. These are interoperability checks, not openNURBS measurement batches. Wider meshes and transforms, exact UV-preserving 3DM transfer, the real retained-file pipeline, Rhino review and real desktop UI remain unverified.
