# Direct Solid dimensions use document units — 2026-11-12

The existing document contract interprets bare command numbers as lengths in the document's units. Before this fix, with a centimetre document `Ellipsoid 2 3 4` produced volume 100.530964914874 mm³, corresponding to semiaxes 2, 3 and 4 mm, instead of 100530.964914873 mm³ for semiaxes 20, 30 and 40 mm. The new regression failed before the fix.

The shared Solid argument dispatcher now converts length arguments once for the direct Ellipsoid, Torus, Cylinder, Tube, Pyramid, Cone and TCone forms. The Pyramid side count stays a dimensionless integer. The specialized point and staged-input routines still own their existing conversion; the dispatcher receives the raw numbers only for their direct multi-number form. Pipe, Fillet and Shell have other paths and are not changed here.

`direct_solid_dimensions_follow_centimeter_document_units` checks all seven command forms through CMD and menu dispatch, each against an independently calculated volume, one solid and closure; it begins from a saved/reopened centimetre document and verifies full document Undo/Redo and volume after saving/reopening the result. `direct_cylinder_inches_and_unit_overflow_preserve_redo` checks the two Cylinder invocation routes in inches and verifies that a length which overflows unit conversion is rejected without changing the document or Redo. These are 16 scoped command-route fixtures in two test functions. They do not establish explicit unit suffix support, all interactive point stages, other Solid commands, physical menu clicks or native peak memory.

Validation on the existing `L:/om9-target` target: the Solid integration suite passed 200 tests with one ignored; the Solid input regression group passed 97 tests; the Solid workflow suite passed 114 with one ignored. The debug executable built successfully with `-j 2`, and the public source audit reported no errors. These are automated/controller results; no physical desktop interaction was performed for this change.
