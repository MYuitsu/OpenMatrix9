# Shell: source face after v4 reopen

A reordered v4 Box fixture reproduced an incorrect Shell opening: the product produced volume 50 mm³ while the native oracle for the selected face produced 52.5 mm³. The original controller converted the persisted face offset directly to a native index.

The numeric and picked-face routes now provide display-face triangle witnesses to the native Shell adapter. For every face, the adapter finds a unique source face on the same OCCT shape/map used to construct the Shell, rejects ambiguous, missing or duplicate source faces, then applies the operation. The witness checks are numerical and sampled; they are not a global proof of source/display equivalence. OCCT's native allocations and peak remain outside the Rust reservation bound.

The reopened reordered Box fixture passed for numeric and picked routes, comparing analytic volume to the source-side oracle and checking Undo/Redo. A reopened reordered two-face fixture checks both openings and one transaction; a displaced display face is refused while retaining document and Redo. The `shell_` library filter passed 6 tests, including related cap/fillet tests; the viewport `shell` filter passed 2. Kernel `shell_removes_two_opposite_faces_with_inward_walls` passed with `--features 3dm-brep`. These do not establish all trimmed/imported shapes, arbitrary tolerances, desktop interaction, performance or native/process peak. No automatic display rebuild is provided after refusal.


### Background display verification for large Shell picks

For scene displays with more than 512 triangles, the selected-face prompt, staged numeric pair, and valid inline numeric command now use the face-verification worker before resuming Shell. The receipt binds the original command feature in addition to command generation, selection, source, scene and cancellation. A cylinder fixture tests a cap through all three routes against analytic volume 9.875π mm³ and Undo/Redo; the selected route also refuses a display with a side triangle assigned to the cap, preserving prompt, document and existing Redo. Thickness changes are refused while the worker is pending. An egui fixture types the inline command, polls to completion and checks volume and Undo/Redo. The full Solid suite passed 198 tests with one ignored; the 70 Solid input regressions, five large UI tests, multi-face Extract worker test, four worker lifecycle tests, no-default check and public-source audit passed.

This verifies sampled source/display consistency, not all imported or trimmed geometry. The two-cap cylinder fixture now validates volume 8.75π mm³ and one Undo/Redo; corruption on the second selected face is refused without a partial commit or loss of Redo. Controller fixtures cover cancellation, same-epoch scene replacement and managed admission refusal at both face-selection and thickness-entry stages, followed by retry. The first pressure test exposed that refusal changed the prompt; the controller now restores the prior selection stage. These fixtures do not prove every selection or pressure path. Small displays still verify synchronously. The later worker integration below changes where Shell construction runs; scene preparation and commit still run on the UI thread. This fixture is not a desktop responsiveness or native memory peak measurement.


Shell snapshot copying now exposes a caller admission callback for Rust output and scratch, following the existing snapshot adapter contract. A cylinder fixture refuses the callback and retries with the expected analytic volume while retaining its input. The worker integration below now uses this API; OCCT internal construction and native snapshot allocations remain outside the callback.


### Shell construction on the verification worker

For the large selected-face, staged numeric and valid inline numeric routes, the existing worker now verifies every face and constructs the Shell before returning. The result retains its source/display captures and a Kernel reservation; Rust output and scratch admission is checked before snapshot allocation, and the retained output remains accounted while the controller validates command generation, feature, source, selection, scene publication, thickness and cancellation and attempts one commit. Test-only thread identity checks confirm the construction ran on a different thread from publication. Cancellation is checked between verification steps, in the snapshot admission callback and after construction; an OCCT call already in progress cannot be interrupted.

The one/two-cap cylinder success, corrupt last face, cancellation, stale scene and initial admission refusal tests pass. A new simulated managed-pressure fixture exhausts admission after construction but before publication: commit is refused with document, prompt and prior Redo retained; after releasing the competing reservation, retry and Undo succeed. The 70 Solid input regressions, five large egui tests, no-default check, public-source audit and default debug om9 executable build pass. This does not bound OCCT native allocations or establish desktop/release responsiveness. The initial worker reservation can now grow through controller admission, as described in the Extract Surface growth evidence; scene preparation and commit remain on the UI thread. Large-display Extract Surface construction also runs on the worker.
