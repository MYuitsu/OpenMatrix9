# Native TextDot current fields and screen-text preview

Preservation import now binds ON_TextDot to a class-specific FreeCAD FeaturePython adapter. The source record and included archive remain immutable. Independent current properties store the double millimeter anchor, Unicode primary/secondary strings, font face, integer height in points and bold/italic/on-top/transparent flags. Current properties survive FCStd without the original file. The derived Coin screen-text provider uses current text/anchor/font/height/color and the on-top flag; it never supplies export geometry. A native placement delta and physical parent/proxy matrix compose once. Existing opaque legacy holders remain valid; they are not silently upgraded or given invented edit provenance.

The native writer accepts complete known TextDot fields with its existing Rust native-transform policy gate. It validates the actual native ON_TextDot class, finite double anchor, bounded canonical strings/font, integer height, boolean flags and Rhino5 compatibility. It modifies a native source clone before the explicit transform; unrelated userdata/attributes survive. Unchanged property values do not invoke setters, preserving implicit font representation and other original native fields. Native setters trim text/font and normalize bare CR; inputs whose setter result differs are rejected rather than silently normalized. Nonempty secondary text cannot be represented in Rhino5. Newer source-version compatibility still refuses export as previously specified.

Canonical definition overlays, independent copied members/new definitions, physical shared proxies, top-level duplicates and direct selected-member copies stage their live current fields. Unchanged native payloads use the source clone, avoiding unnecessary serialization changes. Canonical edits feed following copies; independent copies keep their own payload and delta. Output-member overlays are applied after copy refresh. Current metadata and stable UUID/namespace/closure behavior remain intact. Full serialized native geometry/attribute digests and semantic reread still gate atomic destination replacement.

## Preview and coverage limits

This is a native field/editing slice, not class-wide Rhino display parity. Coin rasterization uses float display coordinates while export uses independent double anchors. Fonts can substitute; glyph metrics, bold/italic appearance, opaque/transparent dot background/border, hover secondary text and exact Rhino point-size rasterization are not reproduced or visually accepted. The flags remain authoritative exported native fields. TextDot display inside affine retained compound previews needs its own adapter. Geometry-only mode still uses its existing unsupported annotation guard. No class/category is marked fully supported from these fixtures.

Remaining point-cloud per-point native editing/display, annotation/text/dimension/hatch/page/clipping classes, linked/external resources, appearance, document/history/reference/version semantics and legacy adapters remain pending. Actual Rhino5 application acceptance, final whole-package review and public integration remain pending. The full openNURBS goal remains active. Authoritative development source: build/om9-dev; isolated runtime: build/3dm-preservation-sdk.
