# Top 11 Split/Trim: world-space cutter tolerance (2026-10-30)

Standalone Rust OM9 on Windows, base `89ef2676b597ebc5ab38fa5c6acf0ad47a2f261b` plus working-tree changes. Previously cutter intersection used fixed `1e-6` in the target's local frame. A regression with a nonuniformly scaled target and 0.0005 mm world gap failed, although the document states 0.001 mm tolerance. The new test also rejects a 0.002 mm gap and a document without a tolerance, without altering geometry or history.

The controller now transforms supported curve, NURBS surface and OCCT BRep cutters and the target curve into world space and passes the document's explicit absolute tolerance to the existing intersection owner. It maps intersection fractions back to the source: affine-transformed circles need a parameter conversion because their baked NURBS parameter is not their original angle; polycurves map the corresponding segment, including reversed records. Split and Trim use the shared result. Tests check world-space cut geometry, Undo/Redo, translated surface/BRep fixtures, a scaled arc and a reversed arc/line polycurve. The latter exposed a separate reversed-flag error in parameter trimming: the code now normalizes the flagged record rather than reversing it twice; a core regression checks that flag separately from a geometrically reversed record.

With `CARGO_TARGET_DIR=L:\om9-target` and `-j 2`, four core curve/Top 11 suites passed 57 tests, app Top 11/options/OCCT BRep suites passed 68, the app Top 11/options suites without default features passed 53, and the existing simulated sidebar Split/Undo/Redo test passed with an explicit document tolerance. Tests that intend to cut now create documents with an explicit template tolerance; missing-tolerance refusal has its own negative fixture. The existing solvers are partly numerical, affine-circle parameter recovery uses sampled projection, and fixed fraction deduplication remains; arbitrary NURBS, tangencies/overlaps, non-rigid BRep transformations, varying document tolerance, performance, actual desktop UI and M03-UI human acceptance remain unverified. This is not completion of Top 11.
