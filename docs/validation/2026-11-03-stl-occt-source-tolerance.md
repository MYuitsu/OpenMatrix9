# STL OCCT source topology tolerance

For each exported B-rep, retained NativeBrep converted to OCCT, or NURBS surface converted to an OCCT face, the existing grouped snapshot callback now returns the maximum OCCT face, edge and vertex tolerance from the parsed shape before tessellation. The native adapter scans its existing topology maps; Rust validates the returned scalar, owns the receipt message and transforms the source value to a conservative world-space upper bound using `sqrt(||A||_1 ||A||_inf)` for the occurrence's linear placement. A warning indicates when this *upper bound* exceeds the requested STL tolerance. Both values are recorded as OCCT tolerance metadata, not measured source-to-mesh error. An upper bound above the request does not prove that actual error exceeds it, so this diagnostic alone does not reject export or certify success.

The C++ addition is a capability-scoped OCCT adapter: no native topology object or borrowed array outlives the synchronous callback; Rust validates and owns the scalar. The grouped callback ABI and the isolated memory probe's test-only ABI mirror were updated together. Native OCCT allocation, internal errors and thread safety are not guaranteed by the Rust interface.

An OCCT two-box fixture checks that topology tolerance is finite and at least the known box tolerance. An actual exported box with 20x nonuniform placement verifies the reported source value and its 20x conservative bound; a separate synthetic unit test exercises the exceeds-request wording. The first attempt to make the actual box exceed the request used an OCCT deflection below the mesher's accepted parameter and failed; it was replaced, so a real high-tolerance B-rep crossing the warning threshold is not yet demonstrated. Converted NativeBrep/NURBS metadata describes the resulting OCCT shape, not the original input's pre-conversion tolerance.

On E: default features and `-j 2`, all 50 app STL integration tests passed, as did the grouped OCCT fixture, the synthetic warning test and the `dense_stage` native memory-probe callback. A no-default-features app check passed with 17 existing warnings; public-source audit reported no errors, and artifact pruning removed no runs. No release performance or desktop measurement was made. Source tolerance metadata alone does not bound conversion, tessellation, seam weld, quantization, coverage or geometric self-intersection; the receipt continues to state that global deviation is unverified. Native and topology allocations remain outside a complete reservation.

## High-tolerance OCCT source fixtures

Three additional test cases start from an OCCT-generated 2 mm radius sphere and change only the serialized tolerance scalar of one vertex, edge or face to 0.01 mm. OCCT reads and validates each modified B-rep, and the grouped snapshot returns 0.01. Export with requested tolerance 0.001 mm completes with the exceeds-request metadata warning and the explicit unverified-deviation message. All encoded vertices are independently checked against the analytic sphere radius within 0.000001 mm. This proves the warning path for these three controlled OCCT inputs; vertex-on-sphere checks alone do not bound triangle interior error, coverage or printability, and a metadata tolerance above the request does not prove actual deviation above it.

The focused three-case test passed on E: with `-j 2`; the preceding 50-test batch ran before this new fixture. Public-source audit reported no errors; the temporary generated OCCT source file was removed and pruning removed no runs. No production code or desktop session changed in this batch. Imported 3DM tolerance provenance and broad malformed/trimmed source cases remain open.

## Structured maximum in the receipt

The STL receipt and MCP now expose `max_occt_topology_tolerance_upper_mm` as a number: the maximum of the placement-scaled metadata bounds over the OCCT B-rep, retained NativeBrep and converted surface occurrences included in the export. It is `None`/JSON `null` when no such OCCT source was exported, including authored-mesh-only exports. Per-occurrence text remains in warnings. This is not the document tolerance, actual exported deviation or a global error bound. For imported NativeBrep and NURBS, the number describes the converted OCCT shape; it does not establish the tolerance of the original representation or conversion error.

The 52-test app STL integration suite passed, including two separated occurrences with 1x and 20x placements, mesh-only absence, real high-tolerance vertex/edge/face inputs and encoded STL checks. MCP exposed a numeric value for a box; the no-default-features app check passed with 17 existing warnings. Public source audit found no errors and artifact pruning removed no runs. No release or desktop test was performed for this addition.
