# Top11 Mirror: transformed native BRep 3DM validation — 2026-10-31

Status: partial automated evidence; full Top11 and physical M03-UI remain open. This supersedes the previously red mirrored-retained-BRep fixture in `2026-10-31-top11-mirror-3dm-roundtrip.md` for the tested cases.

The cold verifier formerly compared transformed ON_Brep DataCRC with the untransformed source DataCRC, so a reflected or translated retained BRep was rejected before publication. Rust now hashes and holds the encoded capture packet, checks it before and after a separately launched bounded native fingerprint operation, checks process exit/lifetime and source object IDs/CRCs, and compares the transformed expected CRC and serialized byte length to the cold inspection of the staged 3DM. The returned BTree maps are charged to Rust response budgets; the output file remains fingerprinted before/after cold inspection, and publication remains guarded by snapshot revalidation. The new process statistics are retained in `ExportReceipt.brep_fingerprints`.

Native exception: ON_Brep decoding, transformation and DataCRC require openNURBS. `--expected-brep-fingerprints` independently decodes the bounded source payload and applies the captured matrix directly, with no document, UI, transaction or publication ownership. The held input packet and process response are finite and checked in Rust; the subprocess uses the existing job/process limits and cannot retain native handles in the model. Native dependencies are not claimed memory-safe. DataCRC is 32-bit, not a cryptographic proof against collision; this retains the existing correspondence criterion but fixes its coordinate frame. Equivalent BReps whose native serialization changes size may be conservatively refused. An older packaged native executable without this new protocol fails safely; the Rust host and native binary must be updated together. No release or deployed binary was changed.
