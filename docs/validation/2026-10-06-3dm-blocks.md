## Implementation and root causes

- Resolve embedded definitions and members by UUID, compose nested transforms in parent*child order, omit definition-only geometry from the top-level import, and propagate block-parent color/visibility/lock. Reject missing definitions/members, cyclic blocks, depth over64, invalid/projective/singular transforms and more than1million expanded objects.
- The user file's bottom matrix rows contain affine roundoff around1e-18. Normalize only deviations within1e-12; preserve nonuniform scale and reflection.
- Four small solids were valid before BRep serialization but failed after reload. Using tight1e-7 construction precision for face/edge/pcurve alignment resolves this while retaining source tolerance for sewing and bounding ShapeFix maximum tolerance.
- Avoid redundant NURBS conversion/cropping of existing BSpline surfaces. Export copied BSpline pcurves directly, avoiding segmentation for endpoint differences within scaled1e-10 parameter roundoff. Validate trim endpoints, check physical loop gap against tolerance, then use openNURBS MatchTrimEnds and Compact for strict UV closure.
- FreeCAD's non-adaptive Shape.Volume is not a precise oracle for these NURBS: objects5/6 reported58.964917 ->58.946739, whereas adaptive OCC integration1e-10 reports59.44358501152544 ->59.44359061809373 (delta5.6066e-6 mm³). Runtime tests now use adaptive volume/area through the native staged-BRep measurement helper; previous acceptance thresholds remain unchanged. Measured integration-error estimates across both fixtures were independently checked finite and below1e-7.
- FCStd geometry is counted by actual Part::Feature/Mesh::Feature types, rather than broad attribute discovery that also included restored layer containers.
