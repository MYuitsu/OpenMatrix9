# Rhino 5 and Blender: display, export and history

Analysis only, 2026-11-02. No application code, preferences or geometry changed. This is a source/documentation comparison, not a benchmark or desktop acceptance.

## Rhino 5

- Rhino 5 [mesh properties](https://docs.mcneel.com/rhino/5/help/en-us/documentproperties/mesh.htm) distinguish NURBS geometry from generated render meshes and provide coarse, smooth and custom meshing controls. [STL export](https://docs.mcneel.com/rhino/5/help/en-us/fileio/stereolithography_stl_import_export.htm) exposes its own tolerance and output preview. This supports independent display and export tessellation, not deferring correct modeling until export.
- [History](https://docs.mcneel.com/rhino/5/help/en-us/commands/history.htm) records input/output relationships for supported commands and updates children when parents change. It is not an exhaustive command replay log. [General options](https://docs.mcneel.com/rhino/5/help/en-us/options/general.htm) specify minimum undo count and maximum attempted undo memory.
- Bounded local managed-wrapper review: `ref/rhino5/dnspy/RhinoCommon/RhinoCommon/DocObjects/RhinoObject.cs` exposes `CreateMeshes`, `GetMeshes`, `MeshCount` and per-object render-mesh parameters; `ApplicationSettings/GeneralSettings.cs` documents purging records when both minimum count and memory thresholds are exceeded. These are decompiled wrappers, not original native source, and do not establish the entire native renderer implementation. No reference source was copied into OM9.

## Blender

- Version-pinned [4.5 subdivision modifier](https://github.com/blender/blender/blob/v4.5.0/source/blender/modifiers/intern/MOD_subsurf.cc) chooses `levels` or `renderLevels` according to evaluation context and retains CPU/GPU subdivision runtime state. A finer subdivision is an evaluation of the base cage and modifier, not reconstruction of a lost CAD B-rep.
- [Dependency graph API](https://github.com/blender/blender/blob/v4.5.0/source/blender/depsgraph/DEG_depsgraph.hh) schedules operations tagged for updates according to dependencies and visibility. This graph is separate from undo history.
- [4.5 preferences](https://github.com/blender/blender/blob/v4.5.0/source/blender/makesrna/intern/rna_userdef.cc) constrain `undo_steps` to 0..256 and expose an independent memory budget. [Undo stack trimming](https://github.com/blender/blender/blob/v4.5.0/source/blender/blenkernel/intern/undo_system.cc) removes old steps while preserving necessary memfile state. [Memfile storage](https://github.com/blender/blender/blob/v4.5.0/source/blender/blenloader/intern/undofile.cc) reuses identical chunks and transfers ownership of still-needed buffers when merging/removing an older memfile. This does not run a higher-precision geometry operation.
- Export context must be explicit. The [4.5 STL exporter](https://github.com/blender/blender/blob/v4.5.0/source/blender/io/stl/exporter/stl_export.cc) selects evaluated or pre-modified meshes; its collection-specific path creates a render graph, while the ordinary path uses the context evaluated graph. The [main-branch exporter inspected today](https://github.com/blender/blender/blob/main/source/blender/io/stl/exporter/stl_export.cc) instead creates a graph from `export_params.evaluation_mode`. Its [parameter structure](https://github.com/blender/blender/blob/main/source/blender/io/stl/IO_stl.hh) initializes that field to render. Main is a moving reference, not a version-pinned release guarantee. Do not assume every exporter/version automatically uses final-render subdivision.

## Implication for OM9

### Blender 5 follow-up

At the user's request, the comparison was extended to Blender 5 rather than treating 4.5 as sufficient. The official [release listing](https://www.blender.org/releases/) identifies Blender 5.2.3 LTS as the current supported 5.x update on the inspection date. The [5.2 pipeline release notes](https://developer.blender.org/docs/release_notes/5.2/pipeline_io/) explicitly announce an STL export option choosing Viewport or Render evaluation (PR #157127). This narrows the earlier version caveat: 5.2 has a documented product option for the intended separate export evaluation.

The pinned [5.0.1 STL exporter](https://github.com/blender/blender/blob/v5.0.1/source/blender/io/stl/exporter/stl_export.cc) still follows the earlier collection-render/context-evaluation split. Its [subdivision modifier](https://github.com/blender/blender/blob/v5.0.1/source/blender/modifiers/intern/MOD_subsurf.cc) independently selects viewport/render levels and retains CPU/GPU subdivision runtime state. The pinned [5.2.3 preference definitions](https://github.com/blender/blender/blob/v5.2.3/source/blender/makesrna/intern/rna_userdef.cc) still constrain undo_steps to 0..256 with an independent memory budget, while its [dependency graph API](https://github.com/blender/blender/blob/v5.2.3/source/blender/depsgraph/DEG_depsgraph.hh) separately describes dependency/visibility-driven evaluation and viewport/render modes. Thus the 256 setting remains an undo retention limit, not an export operation limit.

The 5.2.3 STL exporter and subdivision implementation bodies could not be fetched by the browsing tool; the 5.2 STL behavior claim is supported by official release notes, not a claimed inspection of those unavailable bodies. No reference application was executed and no CAD tolerance or OM9 speedup was established. A higher subdivision level is not by itself a physical-unit error guarantee for manufactured CAD geometry.

Keep canonical geometry valid to document tolerance, derived display meshes disposable, and export tessellation independently configured in physical units. Adopt dependency-based invalidation and bounded undo storage without making exports replay the undo stack. If checkpoints are introduced, preserve exact source data and the transitive inputs of retained recipes; baking older recipes changes their editability and needs a separate product decision.

Current OM9 `crates/om9-core/src/brep.rs` already separates owned source and display data, `history.rs` separates recipes from transaction undo, and `crates/om9-app/src/session/stl.rs::append_brep` reads canonical source but passes `brep.display.deflection_mm`. An independent export-quality policy remains the concrete gap identified here. These observations do not prove a performance gain or close the outstanding desktop Gumball report.
