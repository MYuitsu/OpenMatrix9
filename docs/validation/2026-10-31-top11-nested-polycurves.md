# Top11 Split and Trim: nested line polycurves

Valid OM9 polycurves may contain polycurves. Before this change, point evaluation, nearest-point lookup and curve intersections refused nested segments, while the scene could not display/select even a connected nested line polycurve. Fraction derivatives now recurse through the admitted geometry and apply each level's segment scale and reversal. Closest-point and intersection mapping likewise recurse, keeping each level's segment-uniform fraction and reversal. Validation retains the existing maximum-depth and resource budgets.

Scene admission and rendering now walk connected nested line segments without flattening allocations. They honor reversal at every level, reserve and charge the exact display vertex count, and reject gaps rather than drawing invented connectors. Nested arcs and NURBS are not yet admitted by this new display path. The mathematical intersection solver still has its existing numerical, overlap and resource limits.

Core fixtures check nested intersections in both operand orders, a reversed nested segment, an additional reversed enclosing curve, nearest-point and derivative values, and depth refusal. An application fixture runs Split and Trim on one connected nested line target and a line cutter using both command and toolbar dispatch; it checks exact end coordinates, `.om9` save/open and Undo/Redo. A scene fixture checks nested reversals, gap refusal and exact point-budget admission. This does not prove physical pointer/UI acceptance or native 3DM interchange.

Windows x64, Rust `-j 2`: 204 core library tests and the core Top11, curve-operation and curve/surface suites passed; 129 app Top11, 84 app BRep, 10 Top11 options and three command snapshot tests passed; the complete scene suite passed. The no-default-feature app Top11 suite also passed 129 tests with existing warnings. The separate build directory `L:\om9-target-top11-nested` was used because an existing test application held `L:\om9-target\debug\om9.exe` open. Its first executable run reported `STATUS_DLL_NOT_FOUND`; adding the existing admitted runtime DLL directory to `PATH` allowed the tests to run. This work did not perform an openNURBS measurement batch.
