# Distance and angle measurement through SDK v1 — 2026-10-21

Plugins can now measure a distance and an undirected angle, reusing the analysis owner's
service and admission rules (`measure::distance_mm`, `measure::angle_degrees`). The slice
belongs to the M03 measurement owner (`OM9-L2-03-20`, L3-001 and L3-002).

## Changed

| Layer | Change |
|---|---|
| Public SDK | `MeasuredDistance { millimeters }`, `MeasuredAngle { degrees }`, `Host::measure_distance`, `Host::measure_angle`; two requests and capability entries. |
| Host | Calls the core analysis functions directly, so the 1e9 coordinate bound, non-zero direction rule, `atan2` range and typed refusals stay with the command the UI uses. Measuring stages no mutation. |
| Example plugin | `MeasureDemo` returns a 5 mm distance and a 90° angle. |
| Tests | Host test for 3-4-5 distance, 90/0/180/45° angles and the coordinate-bound and zero-direction refusals; a native DLL test asserting the values and that the document and Undo are untouched. |

## Semantics fixed by this slice

- Distances are canonical millimetres (the display unit only scales the answer).
- Angles are undirected and in `[0, 180]` degrees, computed with `atan2(|a x b|, a . b)` so
  values near 0 and 180 stay stable.
- A coordinate whose magnitude exceeds the analysis bound (1e9) or a zero-length direction
  is a `measure` refusal; no value is invented.
- Measuring stages no mutation: the document, scene and Undo are untouched.

## Not proved here

- Only point-to-point distance and line-to-line angle are exposed. Curve length, radius,
  area, volume, bounding size/center and measurement labels remain at their owners.
- Distances are canonical millimetres; a plugin must convert for display itself.
- macOS host and plugin execution are unverified; interactive UI acceptance was not
  performed. No manual or M09 gate was promoted.
