# Viewport-point memory recovery with an edited draft

Sphere and Box can retain a point selected in the viewport when committing the point is refused by simulated managed-memory pressure. Their recovery targets previously checked the pending command state but not the text in the command input. In a focused Sphere test, changing the draft after the offer did not produce a stale refusal; the retry could therefore proceed toward removing Undo. This was a simulated UI/controller condition, not an observed desktop incident. The focused test failed before the fix at the Sphere case, so it did not independently establish the prior Box outcome.

Both viewport-point recovery targets now capture the command draft and verify it before retrying or pruning Undo. The focused test passed for Sphere and Box Cube with the edited draft, document, pending command, Undo and an existing Redo retained. The full `ui::undo_settings::tests` group passed 76 tests before the final test-only additions of explicit Redo and pending-state assertions; the strengthened focused test then passed. No-default cargo check and the second-target debug application build succeeded with existing compiler warnings. Tests use simulated managed pressure and call the viewport-point handler directly, not a desktop mouse or physical RAM exhaustion. The running first-target app was left untouched.
