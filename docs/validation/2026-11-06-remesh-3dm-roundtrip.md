# 3DM round-trip around a remeshed viewport

- Fixture: one editable OCCT box, 4 × 5 × 6 mm, document tolerance from the OM9 template. Export to two 3DM files before and after the experimental CPU-scene remesh; import each into a fresh document.
- Test: `topology_remesh_keeps_3dm_source_and_topology` in `crates/om9-app/src/session.rs`, ignored unless the native exchange is explicitly configured. It passed once on Windows with `-j 2` and the configured native process admitted by SHA-256.
- Both imports were editable OCCT B-reps. Face, edge, vertex, solid, shell counts and closedness matched the source; volume, area and each bound differed by less than `1e-6` in their respective units. The original document, including stored geometry and IDs, remained equal before/after viewport remesh.
- The initially available `build/native-exchange/Release` executable rejected the current packet schema; it is not evidence of a successful round-trip. The passing test used a separate native exchange built from current `native/native_exchange.cpp`, MSVC 19.44 release, the existing pinned openNURBS static library and zlib. Runtime SHA-256: `3363dc46cf420db81b44d703efadf5b9885a34834c932de8f28225c033889c9e`; source SHA-256: `56c7e79984b526ff9c1c7f28d1245d64cb284da7e895c30a8ad3b6174cd214f0`; static library SHA-256: `ed95cc3e841364d12c1db174f76e1942b15646f2370209696c49eb4f50d73dd6`.
- The fixture does not cover 3DM topology IDs across conversion, NURBS parameterization, curved faces, instances, multiple objects or general geometric deviation. It does not test desktop use or v5 migration. The new native executable is a test artifact, not a packaged release.
