# Boolean common affine frame with relative rigid rotation

The common-frame Boolean path now accepts a relative rigid transformation when the OCCT rigid adapter reproduces it coefficient-for-coefficient and composing it with the chosen affine frame reproduces the other input placement exactly. The existing identical-linear-map translation route remains. The relative transform is applied to the local source; output geometry remains in the first input's frame. When classification or reconstruction fails, the existing world-space path and conservative non-rigid restriction remain. Exact coefficient comparisons do not prove pointwise floating-point equivalence for every coordinate or bound tolerance under extreme affine maps.

Thirty saved/reopened two-box combinations cover Union, Boolean Two (Union mode), Difference, Intersection and Split, with relative 90° rotation plus translation; the shared frame is nonuniform scale, shear, or reflection, each tested at two display profiles through menu dispatch or CMD. The fixtures assert local analytic volumes, expected output counts, retained output placement and document equality across Undo/Redo.

A second set of 30 saved/reopened sphere-and-box combinations exercises the same three frames and two profiles. Each run cycles to one of the five Boolean Two modes, commits it, checks its local volume against analytic hemisphere/box values and verifies Undo/Redo. Thus each Boolean Two mode is committed in these fixtures. These checks do not establish all rotations, arbitrary imported geometry, pointwise error at large coordinates, extreme affine tolerance, native peak memory or interactive desktop. The unrelated case in which nonuniform scaling is baked into one source still fails and its protection remains.

Verification: Solid controller 88 passed; Solid integration 198 passed/1 ignored; Solid workflows 114 passed/1 ignored; two Boolean Two viewport tests passed. No new desktop executable was built or tested.
