# ExtractWireframe: multiple reopened roots

Previously `ExtractWireframe` rejected any selection of more than one root. The controller now validates all selected root OCCT B-reps and their permissions and rigid placements, extracts source edges for every root, and prepares all output curves before one transaction. Each root uses the existing source-edge adapter without assuming persisted edge indices or requiring session topology proof. Rust retains an admission reservation across extraction and commit, including previously prepared outputs; OCCT parsing and conversion allocations are not covered by that reservation.

The initial two-box regression failed with `ExtractWireframe requires one selected B-Rep`. After the change, two reopened boxes, one translated by 20 mm, yielded 12 curves each in their correct positions and on the current layer. Both command invocation and menu dispatcher were checked, and a single Undo/Redo restored the before/after entity sets. A reopened box plus sphere with a degenerate source edge, a two-box output-object limit, and managed-memory pressure each refused without changing the coordinator snapshot or preexisting Redo; the memory fixture succeeded on retry after pressure was released. The sphere test assigns IDs so the controller's ordered set visits the box first, and a separate call to the same adapter on the reopened box yields 12 edges. Controller source processes each root sequentially before the single commit; this supports the late-failure case, although the adapter was not instrumented inside the controller invocation.

A further mixed-source test opens a box and a translated cylindrical shell with two display profiles. In each, menu dispatcher or CMD produces 12 box edges, two circular boundary curves and one seam with sampled geometric checks. Undo/Redo restores the entity sets, and another save/reopen preserves each entity's geometry and placement. These are specific fixture results, not certification of all mixed shapes or seam representations.

`cargo test -p om9-app --test wireframe --test curve_menu --test dup_border --target-dir L:/om9-target -j 2 -- --test-threads=1`: wireframe 40 passed, 3 ignored; curve menu 6 passed; DupBorder 9 passed. Existing unreachable-pattern and unused-method warnings remain. The user approved recording the two-box multi-root behavior in the feature guidance on 2026-11-12.

This change remains synchronous and has not been measured on desktop or for native process peak. It does not establish support for every topology, nested block, NativeBrep, non-rigid placement, isocurve, large selection, or every display profile. Source-only history and display eviction remain separate work.
