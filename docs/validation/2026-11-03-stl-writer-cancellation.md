# STL writer cancellation during preflight

The binary STL writer previously only exposed `Write` calls for cancellation to the background exporter. Its finite-coordinate and index-validation passes (and its optional strict topology pass) ran before the first write, so an already requested cancellation could wait for those scans. The writer now has a cancellable entry point, checking before work and periodically during vertex/index preflight, strict topology and encoding. The existing writer remains a wrapper with no cancellation callback. The background export supplies its cancellation token; the existing cancellable writer, staging verification and publication guard remain in place.

Two deterministic `om9-exchange` unit fixtures inject cancellation during vertex preflight and strict topology respectively, verify an I/O cancellation signal and assert no bytes have been emitted. Thirteen STL writer unit tests, 42 application STL integration tests and 10 application cancellation tests passed on the default-feature E: build with `-j 2`. The latter include preservation of an existing destination during streaming cancellation. This establishes bounded check intervals in these Rust loops, not a wall-clock latency bound: one allocation, OS operation or native tessellation can still take time, and this change does not establish aggregate memory admission. The destination-preservation test does not specifically inject cancellation inside the new preflight callback.
