# Rhino-style selection: per-query mesh vertex reuse

User direction: preserve Rhino-style disambiguation among overlapping curves and objects while improving speed. This change keeps `pick_all`, candidate ordering, exact mesh intersection, selection permissions, and scene ownership unchanged. It reuses each transformed mesh vertex during one face/object pick and its screen-space fallback, with no cross-query cache.

One synthetic debug comparison used the same orthographic view and 120 by 120 mesh grid (14,641 vertices, 28,800 triangles), with 30 repeated `pick_all` calls. Baseline total was 1,939.3 ms (64.6 ms/call); per-query vertex reuse total was 578.4 ms (19.3 ms/call). These are one run per variant, collected in reverse order, not a statistically controlled benchmark, release result, dice measurement, display latency, or a 30 FPS claim. The probe was temporary and removed after measurement.

Scene acceptance and regression suites passed 28 tests. They include a new curve over mesh case requiring both candidates, and existing tests for occluded candidates, stable face IDs, hidden and locked objects, clipped edges, and transformed instances. Five filtered app library tests also passed. This checks the candidate list, not an actual popup click or all possible geometry. Integration app test builds were blocked by Windows locking the open `L:\om9-target\debug\om9.exe`; the live application was left open. The public source audit reported zero errors. GPU selection changes still rebuild scene resources and displayed-frame performance remains unmeasured. Follow-up: profile and address selection publication, then validate repeated physical clicks and viewport responsiveness with the dice in a newly built running application.
