# Top11 small grip drag and press offset

The viewport previously discarded every grip drag of at most `1e-9` mm, even when the movement was visible on screen after zooming in. After removing that absolute world-space threshold, a second regression exposed an offset: pressing within the grip hit radius and returning to the press point could move the grip and create an Undo record. The viewport now uses egui's existing screen-space drag threshold and tracks the projected press point on the grip's construction plane. Preview and commit use the displacement from that point, preserving the relative position of an off-center press. An exact return to the press point makes no document mutation.

An egui viewport fixture failed before each corresponding fix and now passes for Control Points and Edit Points, in positive and negative X and Y directions. It checks a `5e-10` mm displacement, pre-commit preview, unchanged document during preview, final endpoint, off-center dragging, return-to-press without an Undo record, Undo/Redo and `.om9` save/open. An existing normal-scale drag/selection-band regression also passes. These are simulated pointer events in the actual egui view, not OS input or proof of GPU presentation. Other views, rotated CPlanes, surface grips and numerical extremes are not established by this fixture.

Windows x64, `CARGO_TARGET_DIR=L:\om9-target-top11-nested`, `-j 2`: two focused UI tests passed with default and no-default features; five Top11 UI helper tests and 133 app Top11 controller tests passed. The no-default build emitted existing unrelated warnings. No native adapter changed and no openNURBS measurement batch was performed. A Windows app inventory did not show a current OM9 window; no physical desktop or human M03-UI acceptance is claimed.
