# Toolbar icon lookup and dice navigation — 2026-11-02

The user accepts a less precise displayed Gumball position if geometry remains correct. The existing exact centre cache is retained: profiling identified a different cost. In a temporary headless debug UI probe with the selected 23,368-vertex dice, warm frames spent approximately 96 ms in the standard toolbar; tracing its icons showed about 4.7–5.2 ms per unresolved feature lookup. Those calls repeatedly scanned the complete icon palette for every feature candidate. The probe was removed after measurement.

An immutable process-wide index in `crates/om9-app/src/icons.rs` resolves the same case-insensitive names, command keys and feature IDs, keeping the first matching icon in existing palette order. Existing explicit aliases remain unchanged. On the same headless probe warm toolbar time was approximately 6 ms; this was a short debug experiment and excludes GPU presentation.

Validation: `cargo test -p om9-app --lib -j 2 icons::tests` passed 3 tests, including a new palette-wide comparison against the former linear lookup and all embedded icon rendering; the first comparison attempt incorrectly compared pointers to separate promoted copies of a constant palette and failed, then the corrected test compared the resolved icon fields and passed.
