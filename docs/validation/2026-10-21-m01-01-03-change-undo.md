# Host Undo/Redo in the change feed — 2026-10-21

The recorded feed now also carries host Undo/Redo, so a plugin sees the last committed
document change even when the user (not a plugin) reversed the edit. Owner: `OM9-L2-01-03`
(`OM9-L3-01-03-011`).

## Changed

| Layer | Change |
|---|---|
| App | `undo`/`redo` snapshot the document, perform the history action and record `ChangeBatch::between(before, after, Undo/Redo)` into the same bounded feed the plugin reads. |
| Public SDK | `last_change` documentation now states the feed covers plugin commands and host Undo/Redo; other host edits are covered by `document_info().revision`. |
| Tests | Native DLL test: `CreateProfile` then host `undo` → `ChangeDemo` reports cause `undo` with 3 `entity_removed` entries. |

## Semantics fixed by this slice

- The feed holds one batch for the last committed change: plugin `edit`, host `undo` or
  host `redo`; cause distinguishes them.
- Revisions remain real (before/after documents), so `from_revision`/`to_revision` are
  trustworthy.
- Other host edit paths are still documented as outside the feed; plugins compare
  `document_info().revision` for those.
- Recording Undo/Redo stages no new mutation and does not change Undo/Redo behaviour.
