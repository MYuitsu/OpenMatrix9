# Save memory reservation

Previously Save computed the remaining budget once before archive serialization. A competing shared-account reservation could then consume that same headroom while the serializer and validation decoder were still live. Save now atomically reserves currently available managed headroom while including the current scene and other caller-held usage, and limits archive work to the current document plus that reservation. A physical-memory sample, when available, also caps the reservation after existing reserved bytes and the required headroom. The guard remains live through archive verification and publication and is released on success or error.

This is deliberately conservative: it reserves all currently available managed headroom, so another job may be refused during synchronous Save even if a more precise per-stage estimate would have allowed it. If physical sampling is unavailable, this path uses managed admission without claiming physical headroom was checked. Archive accounting is an estimate and does not certify allocator or process peak; scene owners not passed by the caller, GPU/native allocations, the existing 256 MiB limit and full P0 remain open.

On the external E: target with `-j 2`, the focused physical-headroom test and five app replacement-budget tests passed. The Save fixture verifies a competing reservation is refused while Save owns its lease, an injected cancellation preserves destination and document, and success/error release the lease. All 20 file-lifecycle tests and the `om9-archive` test suite passed. The public source audit reported no errors. The injected cancellation occurs before serialization; archive atomic-save tests separately cover cancellation and invalid-save destination preservation.
