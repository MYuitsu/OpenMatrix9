# STL source-scoped edge-connected components

The STL topology report now counts connected components of triangles sharing indexed edges in the pre-encoding, source-scoped soup. Union by rank and path compression join all triangles incident on each edge, including edges with more than two incident faces. Triangles touching only at a vertex remain separate components; distinct selected objects remain separate even when their coordinates coincide. Empty input has zero components. The count is exposed in the receipt, its message and MCP alongside the existing separate defect counts.

The exchange policy suite passed eight tests, including a cube, two tetrahedra touching at one vertex, three faces sharing a non-manifold edge, a disconnected face and empty input. The application fixture checks two coincident open objects and the reported message; the MCP fixture checks the structured value. All 47 application STL integration tests and 21 STL session unit tests passed on the E: default-feature build with `-j 2`. Public source audit reported no errors and artifact pruning removed no runs.

This is not a count of independent solids, cavities, shells, encoded-STL components or connected geometric regions. Unwelded legitimate source seams can increase the count; coincident or intersecting shells can have different geometric relationships. The code does not check containment or self-intersections, and a count of one does not establish watertightness. The new union-find arrays require fallible scratch allocation proportional to triangle count, and one extra triangle index is retained per indexed edge. The extra peak is not yet reserved or measured; this makes complete P0/P3b admission and the large-model memory/performance acceptance more urgent, not complete. The operation checks cancellation before allocating and periodically through existing traversal. No desktop or release performance claim is made.
