## Semantics fixed by this slice

- `layers()` reports name, colour and effective visible/selectable/locked flags for the
  captured document plus the command's own created/updated records, and marks the current
  layer including a staged selection. Created layers appear in `layer_order` order after
  the captured layers.
- `layer_create` validates the document's name grammar and budget in the host and leaves
  name uniqueness, preset-slot and layer budget admission to `LayerPlan::admit`; the new
  layer ID is returned. `make_current` creates and selects it in the same plan.
- `layer_update` renames, recolours or changes flags of one layer. It requires an editable
  (unlocked) layer; a created layer can be updated in the same command.
- `set_current_layer` selects or clears the current layer; selecting a layer created by the
  same command folds into its creation plan because a separate `SetCurrent` cannot resolve
  a layer that is not in the captured world yet.
- `assign_objects_to_layer` accepts an existing or this-command-created layer, requires the
  source layer to be editable (the application also protects the source side), clears the
  object colour so the layer colour applies, and assigns already-staged additions directly.
- A command cannot add objects to a layer whose flags change in the same command: the
  application's permission-read rule exists so a lock/assignment change cannot be evaluated
  on stale permissions, and the host reports that as a `layer` refusal instead of letting
  the prepare step fail opaquely.
