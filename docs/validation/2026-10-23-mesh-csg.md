# Mesh CSG kernel — 2026-10-23

Target: standalone OM9 safe Rust `om9-core`, Windows x64. Build from root with
`CARGO_TARGET_DIR=L:/om9-target` and `-j 2`. No native adapter or dependency added.
Owner: AFTER `OM9-L2-10-02`, geometric service slice for `OM9-L3-10-02-002`;
M03 `OM9-L3-03-19-006` only consumes the checked self-overlap prepass.

The former repair deleted the smaller intersecting face, iterated, then attempted
centroid hole fill. The new checked repair splits both sides, classifies material
with nonzero winding, and rebuilds a closed oriented shell. Unsupported or
numerically ambiguous input returns an error; there is no deletion fallback.

## Scope limits

This is a bounded `f64` arrangement kernel, not exact arithmetic or a claim of
perfect manufacturing repair. Default input limit: 2,000 triangles; fragment/output
limit: 50,000; work limit: 10 million. Open meshes, quads, vertex colours,
inconsistent winding, sub-tolerance features and ambiguous configurations are
refused. Primary `Mesh.corner_uvs` is interpolated; normals are invalidated.
`MeshUv` compatibility is retained elsewhere.

No new Menu/CMD/SDK command, UI preview/Undo workflow, general hole repair, macOS
execution or production-scale speed has been certified. Existing basic reduction
can still truncate/fill independently; its final result does not inherit the CSG
shell guarantees. See [the API contract](../features/OM9-L3-10-02-002.md).

Full regression/lint/audit command exits and source fingerprints are recorded in
[the receipt](../../implementation/evidence/AFTER/mesh-csg-2026-10-23/receipt.json).
Manual gates remain pending; no unrelated changes are staged or committed.
