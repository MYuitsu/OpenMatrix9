# Top11 periodic grips: 3DM outer knots

openNURBS stores two fewer knot values than OM9's expanded representation. For a periodic curve with certified-style noncanonical outer knots, the native adapter now writes the actual compact native knot vector and stores the two omitted expanded values in a namespaced geometry user string. It validates their ordering and consistency with the periodic interval on both write and read. The existing canonical case does not acquire the user string. The export receipt warns that an external editor may remove or invalidate this metadata.

This is a selected openNURBS serialization exception: C++ owns only native knot/user-string translation and native API validity; Rust continues to own model validation, edit points, control points, transactions and publication. The metadata is not a substitute for proof of native or FFI memory safety. Source classification retains ordinary native user data and reports it as omitted from the owned projection; the exporter-generated string is decoded only for an actual periodic NURBS and is size- and format-bounded. Invalid or stale values cause per-object projection refusal, not invented geometry. If another editor removes the string, import uses canonical expanded end knots; the exact two original values and OM9's repeated-basis certification may then be lost. The result has not been tested in an external Rhino editor.
