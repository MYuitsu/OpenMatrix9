# Gumball and viewport refinement

The user reported that a visible Gumball in Perspective did not respond to dragging in the navigation release. One independent defect was confirmed: while a Gumball gesture blocks navigation, repeated `NavigationController::cancel` calls advanced the generation even when the viewport was already refining. This can repeatedly invalidate an in-flight viewport publication. Cancellation now advances the generation only when cancelling an active drag or zoom; repeated calls leave an already-refining generation stable.

The `repeated_cancel_keeps_refinement_generation_stable` regression failed before the change (generation 3 rather than 2) and passed afterward. Eight navigation unit tests passed. Eleven `gpu_navigation_publication`, six `gesture_regressions`, and three `preview_drag` tests passed. A subsequent simulated egui test, `perspective_gumball_can_drag_after_orbit`, passed and verifies an actual camera orbit, Gumball preview and committed placement. The GPU regression checks that repeated navigation blocking does not starve final publication. Public source audit reported no errors.

The preexisting OS mouse audit could not provide desktop evidence in this automation environment: first it stalled awaiting repaint-driven readiness; after test-window-only synthetic mouse-move events supplied repaints, Windows screenshot capture failed with an invalid handle before the drag. Both audit windows were closed; the user's unsaved OM9 session was preserved. These automated checks do not establish that the reported desktop drag failure is fully fixed; verify the new release with the user's actual Perspective interaction.
