# Open-source Boolean comparison

Research 2026-11-02; static inspection, no cross-application runtime benchmark or code copied. Existing OM9 no-Undo dice comparison and limits: `2026-11-02-boolean-dice-topology-performance.md`.

- [CadQuery shapes.py](https://raw.githubusercontent.com/CadQuery/cadquery/master/cadquery/occ_impl/shapes.py): `_bool_op` passes argument/tool lists to OCCT, enables `SetRunParallel` by default and runs `Build` once; `Shape.cut` can pass multiple tools. Its newer builder helper also configures OBB and non-destructive mode. A separate API warns that overlapping members of a Compound may silently produce an incorrect result: test overlap and coincident cases explicitly; do not generalize a Compound to arbitrary cutters.
- [FreeCAD TopoShape binding](https://github.com/FreeCAD/FreeCAD/blob/main/src/Mod/Part/App/TopoShapePyImp.cpp) receives a sequence of shapes and delegates to `makeElementBoolean`; [Part Cut](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Part_Cut.md) uses OCCT shapes. This shows the public binding/representation, not a verified speed claim or detailed worker implementation.
- Local QymCAD `crates/qymcad-kernel/src/occt_common.hpp` uses argument/tool lists, a configurable OCCT algorithm and a single Build; `occt_io.cpp` constructs multiple hole tools and performs one cut. It is a sample source, not OM9's runtime or UI. `inside/multiprofile.rs` checks a separate fuse-then-Boolean case.
- [OCCT Boolean documentation](https://occt3d.com/dev/doc/overview/html/specification__boolean_operations.html) documents parallel processing, OBB, multiple tools, non-destructive inputs and gluing. Gluing assumes specific coincident geometry and can be incorrect otherwise; it must not be enabled as a general dice shortcut. Current OM9 re-reads owned serialized sources per operation, so native input sharing assumptions must be checked before interpreting non-destructive mode.
- [OpenSCAD](https://github.com/openscad/openscad/blob/master/src/openscad.cc) offers Manifold and CGAL geometry backends. [Manifold](https://github.com/elalish/manifold) operates on triangle meshes and parallelizes; its representation does not preserve exact analytic BRep surfaces. It is a candidate for an explicitly mesh-based task, not a drop-in replacement for OM9's BRep editing/3DM contract.

Priority for experiments: (1) benchmark OCCT serial versus parallel and OBB for single cuts, using matched release binaries, controlled thread budgets, 21-step fixture and direct geometry validation; (2) prototype explicit multi-cutter Boolean in an isolated branch/fixture, compare one cut to sequential cuts and preserve the existing interactive command, atomicity, DeleteInput and Undo contracts; (3) profile Rust retained validation, publication and meshing separately before caching, and preserve tamper detection, budgets and stale guards. Measure p50/p95, peak memory, output topology/volume, empty/disjoint/overlapping and tangent cutters, and Undo/Redo. Batch semantics cannot replace 21 already committed interactive operations without changing their observable history.
