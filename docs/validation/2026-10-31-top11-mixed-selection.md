# Top11 mixed selection: grips and Join availability

With a curve or surface selected alongside an unsupported object, Control/Edit Points was enabled but enumerating grips returned an error for the unsupported object; the UI consequently displayed no grips. The Rust grip owner now skips incompatible object types while enumerating compatible curves and surfaces. An entirely incompatible nonempty selection and a missing object still return errors. This is an OM9 interpretation for mixed selection, not evidence of original Matrix behavior.

Join was also enabled for two curves plus a selected point or mesh, although its curve owner requires every selected object to be a curve. The curve Join availability check now requires that complete selection; the separately implemented all-surface/BRep application path is unchanged. CMD and toolbar invocation refuse the unsupported mixed selection without document or Undo changes.

Both problems were reproduced by failing tests before the fixes. Controller fixtures exercise Control and Edit Points via CMD and toolbar with a line, surface and point, verify only compatible grips, move a line grip, retain the other objects, and check `.om9`, Undo and Redo. An egui fixture drags a line grip with a point also selected in both modes. Core tests cover an all-incompatible selection, a missing object and mixed Join availability. The fixture is simulated input, not OS-level mouse/GPU or human M03-UI acceptance. Unsupported curve or surface subtypes can still fail explicitly; arbitrary mixed geometry and actual Matrix behavior remain unverified.
