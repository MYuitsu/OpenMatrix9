# OM9-L2-01-08 units and tolerance through SDK v1 — 2026-10-21

The first implementation slice of
[SDK-INTEGRATION-PLAN](../../OM9_Milestones/SDK-INTEGRATION-PLAN.md) is delivered inside
its existing owner, `OM9-L2-01-08` (Be Units Tolerances Basic Parameters), instead of a
separate SDK phase. The host already implemented typed lengths/angles, coordinate input
and a per-document tolerance policy; this slice adds the public adapter and proves it
from a plugin built outside the checkout.

## Changed

| Layer | Change |
|---|---|
| Public DTOs | `DocumentUnits` (display unit, millimetres per display unit, stated tolerance or none), `DocumentTolerance`, `LengthValue`, `AngleValue`, `Coordinates`. |
| Public methods | `Host::document_units`, `Host::parse_length`, `Host::parse_angle`, `Host::parse_coordinates`; four new `HostRequest` methods and capability entries. |
| Host dispatch | `crates/om9-plugin-host/src/staged.rs` calls `om9_core::units::{LengthMm, AngleDeg}` and `om9_core::coords::parse_local`. There is no second parser, no duplicate unit table and no new algorithm: the document's own unit contract and the command prompt's grammar are reused. |
| Errors | Unit refusals are split into `unit` (unknown/unsupported token), `number` (malformed or non-finite value), `coordinate` (coordinate grammar), `budget` (one numeric field longer than 256 bytes). A refused call still poisons the invocation, so no partial command commits. |
| Example plugin | `UnitsReport` command reads the units/tolerance and parses `1 in`, `2.5`, `90`, `1rad` and `10, 20, 30`; it stages no mutation. |
| Tests | Host-level units/tolerance and refusal tests; an ignored native test that loads the real `.om9p` and asserts the returned JSON, the empty Undo/Redo state and the `null` tolerance of a document that states none. |
| Tooling | `tools/validate_plugin_sdk.py` now extracts each batch's SDK into a fresh `mkdtemp` directory, so a previous batch cannot block or be overwritten by a re-run. |

## Semantics fixed by this slice

- `document_units().tolerance` is `None` when the document states no tolerance. The host
  does not substitute the OM9 template policy; a plugin that needs a tolerance must ask
  the document for it.
- `parse_length("2.5")` uses the document display unit; `parse_length("2.5 mm")`,
  `"0.1 in"`, `"1.5 cm"`, `"1 m"`, `"1 ft"`, `"250 um"` carry their own unit. Results are
  canonical millimetres. A negative or zero length is a valid length value; only
  non-finite/malformed text is refused.
- `parse_angle` accepts degrees (`"90"`, `"90deg"`, `"90°"`) and converts an explicit
  `rad` token; it returns canonical degrees plus the explicit radian value and keeps the
  document's absolute-degree admission bound.
- `parse_coordinates` is exactly the command prompt's grammar: `x,y` or `x,y,z` in the
  display unit, comma separated, `z` defaults to zero, every component finite. The result
  is a pre-CPlane millimetre tuple. Local-frame to world resolution remains owned by the
  view/CPlane service, so no placement is applied here and a plugin cannot apply it twice.

## Not proved here

- Only `OM9-L3-01-08-001/002/003/007` receive a scoped public adapter. L3-004 (typed
  builder parameter values), L3-005 (builder parameter range validation) and L3-006
  (unit-safe parameter serialization) still have no plugin-facing surface.
- Tolerance is read, not written; display/page unit mutation is not exposed.
- Local-frame/CPlane resolution, view services and interactive numeric input stay
  host-owned and are the concern of M01 `03-01` / M02 `02-02`.
- macOS host and plugin execution are unverified; the SDK ZIP and package target support
  are structural only on this host.
- Interactive UI acceptance was not performed; this slice is a headless SDK/Controller
  and CLI proof.
