# Boolean Difference false-empty witness

The checked Boolean kernel path returned `Empty` for a radius-3 sphere minus a nonuniformly scaled, baked box covering its positive-X half. The analytic remainder is a hemisphere of volume `18π` mm³. The new regression reproduced that false empty at output profile 0.5 before the change. The normal Difference command already refused to commit an empty result, but an `Empty` outcome can also be used as an intermediate Boolean result, so its incorrect classification matters beyond the error wording.

For a checked solid Difference whose native result has no faces, the bridge now samples 27 points inside the argument's bounding box. It rejects the empty outcome if OCCT classifies a point strictly inside an argument solid and outside every tool solid. The additional sampling is used only when both inputs contain at most eight solids; the number of classifier calls is limited, but native cost and memory per call depend on geometry. OCCT's classification is numerical with a 1e-7 mm tolerance; this is a conservative diagnostic, not a proof of correctness. If no witness is found, or the solid-count limit is exceeded, the existing empty outcome remains possible. This does not cover empty Intersection, multi-tool fast Difference, unchecked internal kernel calls or the general baked-affine Boolean problem.

The kernel regression now rejects the sphere/box fixture with the witness diagnostic at both 0.5 and 0.01 mm. A separate kernel control accepts truly empty differences for a contained box and an identical box at both profiles. A product-controller fixture saves and reopens the same sphere/box, invokes Difference through menu and CMD, verifies the diagnostic, and checks document and Redo remain unchanged. This does not demonstrate that every incorrect empty result is detected, or that valid thin/complex geometry never yields a false rejection. Native peak, large-model latency, imports and desktop remain unmeasured.

Verification: kernel Boolean 82 passed/1 known affine reproducer ignored; Solid controller 89 passed; Solid integration 198 passed/1 ignored; Solid workflows 114 passed/1 ignored. No new desktop executable was built or tested.

## Disjoint multi-tool path

The same sphere and baked box plus a distant, disjoint second cutter reproduced `Empty` at profile 0.5 on the optimized multi-tool path. That path now builds a temporary compound of the tools and runs the same numerical witness test before returning an empty result, for at most eight tool shapes and at most eight solids per side. A two-tool control containing the target completely still returns `Empty` at both profiles. In a saved/reopened controller fixture, menu and CMD routes reject the false empty at profiles 0.5 and 0.01 while preserving document and Redo. Existing kernel tests cover overlapping-tool fallback and a valid 21-cutter result; the latter does not exercise the new empty-result witness because the result is nonempty. The first edit accidentally landed in the plane-trim function and failed to compile; it was moved to the multi-tool function before verification.

The absence of a witness remains inconclusive, tool counts above eight skip this diagnostic, and native classifier time and memory depend on shape complexity. No claim is made for all erroneous empty results, thin features, empty Intersection, unchecked internal calls or the underlying baked-affine defect. Verification: kernel Boolean 83 passed/1 ignored; Solid controller 90 passed; Solid integration 198 passed/1 ignored; Solid workflows 114 passed/1 ignored. Interactive desktop and native peak were not measured.
