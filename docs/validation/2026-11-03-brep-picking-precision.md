# B-rep picking: coarse display candidate versus one exact face

The current `om9-scene` picker intersects the scene's display triangles and maps a successful candidate back to a B-rep face ID. The returned candidate's `world_point` is on that triangle; the mapping to a stable face ID does not itself project the point onto the exact surface. A separate existing OCCT `surface_ray_hit` operation supports a single face and is used by selected Top 11 surface operations; this is not yet a generic scene-picking refinement path.

## Independent analytic fixtures

`cargo test -p om9-app -j 2 --test brep_picking_precision -- --nocapture`, default OCCT features, Windows, `L:/om9-target`: 1 test passed with two OCCT spheres. Each uses a display deflection of 10% of its radius and the same fractional ray position. The oracle is the analytic sphere equation in world millimetres; the existing OCCT single-face ray operation is independently compared with that oracle.

| Sphere radius | Display triangle candidate error along Z | OCCT ray hit error, displayed precision |
|---:|---:|---:|
| 5 mm | 0.034966349 mm | < 0.000000000001 mm |
| 0.05 mm | 0.000349663 mm | < 0.000000000001 mm |

The test independently queries the default `Surface` snap candidate; it has the same measured errors as the triangle candidate in both fixtures. The current UI can use that candidate as an input point or Gumball snap, so this is a modeling-accuracy risk rather than only an issue in a diagnostic API. These values describe two points and builds, not an error bound for general B-reps. The test also verifies the candidate maps to a B-rep face ID and passes existing source/camera/viewport revalidation.

## Remaining work

### Cached Surface candidate context

The UI's direct Surface refinement cache previously returned an equal cached candidate without revalidating the caller's camera, viewport and current source/placement. A focused OCCT sphere test first cached a correct hit, then passed the old candidate with a changed camera: the old code returned it instead of rejecting the stale context. Cache hits now perform the same controller validation as uncached refinement, and each entry also holds a weak identity of the captured scene document so a replacement snapshot with the same IDs and revisions cannot reuse the previous allocation's cached result. A test replaces the controller with an independently captured clone and verifies recomputation rather than a cache hit; the weak identity does not retain the document. This is an internal stale-input regression, not evidence that the normal desktop event path actually generates that stale call.

On the default-feature E: debug build with `-j 2`, the targeted red/green test passed after the fix, together with 18 B-rep precision, 19 OSnap UI, 11 gesture and 10 offscreen GPU/egui Gumball tests. No GPU skip was reported. Native refinement remains synchronous; the worker is not wired to UI, snapshot/worker admission is incomplete, silhouette omissions and desktop validation remain open.

### Surface worker and replacement snapshots

A worker receipt previously accepted a newly constructed controller containing an independent clone of the original document with identical document/object IDs and revisions. The focused receipt test failed before the fix. Each job and receipt now carries a weak identity of the scene's captured document and confirms that the coordinator's retained source is the same snapshot; acceptance refuses a replacement snapshot even if its IDs match. The scheduler uses that identity when coalescing equal input, and pending work is refused if its original snapshot is replaced. Tests cover a fresh request on the replacement while older work is active, rejection of a pending request from the old snapshot, and release of both accounts' reservations. These changes do not keep old documents alive through their weak identities.

All 18 B-rep precision and 10 offscreen GPU/egui Gumball tests passed on the E: default-feature debug build with `-j 2`, without GPU skips. The worker is still not connected to UI; its caller-provided reservation is not a measured native-peak estimate, and publication/occlusion, actual desktop interaction and concurrent native safety remain separate open gates.

### Surface worker slot per shared account

The experimental Surface worker now acquires a single slot from its coordinator's shared reservation account before spawning, and releases it only after its native refinement loop has ended, just before it signals completion. A failed start drops its RAM reservation. The shared account follows the existing New/Open coordinator adoption path. A two-thread barrier test admits exactly one competing slot holder and checks replacement and release; the worker test holds the slot externally and verifies a rejected start releases its reservation. Existing cancel/drop tests exercise eventual release but do not deterministically interrupt an in-progress native call.

On E: with `-j 2`, the slot unit test, all 18 B-rep precision tests and 17 STL cancellation/resource tests passed. An initial STL test filter matched zero tests and was corrected; it is not counted as evidence. The slot serializes only Surface workers sharing an account. It does not serialize independent accounts or Surface work against STL, synchronous UI or other OCCT operations, does not establish native thread safety or production RAM sizing, and does not wire the worker to UI. Busy-slot retry and latest-input behavior across multiple schedulers need integration tests before UI use.

### Retrying a busy Surface slot

Previously, submitting to a scheduler while another holder owned the shared Surface slot returned an error and discarded the request. A focused test held that slot, submitted three cursor positions and reproduced the first failure. The scheduler now holds only the most recent pending request and its reservation, retries nonblocking on polling, validates snapshot/selection/preview before starting, and releases the pending reservation on cancellation or staleness. After releasing the slot the fixture refines the final cursor against the sphere; it also tests cancel and changed selection while blocked. This controlled holder simulates contention; it is not a fairness or starvation guarantee for independently polling schedulers.

All 18 B-rep precision and 10 offscreen GPU/egui Gumball tests passed on the E: default-feature debug build with `-j 2` and no GPU skip. The scheduler is still not connected to UI, so repaint scheduling, pointer-release behavior and desktop latency are not tested; callers must poll while busy and separately validate publication and occlusion. Native admission and concurrency with other kernel operations remain open.

### Surface worker candidate storage floor

The previous worker reservation check counted two candidate structs per input but ignored spare capacity in the retained input vector and its instance-path vectors. A controlled test reserved enough for the old floor while independently adding spare candidate-vector capacity or path capacity. The old check accepted the first case; the revised check refuses both and releases the rejected reservation. It counts input candidate capacity, result candidate length, each input path capacity and corresponding cloned path length, with checked arithmetic. A full 18-case B-rep precision run and the expanded focused test passed on E: with default features and `-j 2`; `cargo check --no-default-features` passed with 17 existing warnings.

This is a minimum for identifiable Rust candidate storage, not an allocation upper bound: allocator rounding, result excess capacity, channels, thread stack, source document, prior candidate enumeration and OCCT native memory are not bounded by it. Input allocations already exist before this check. The worker still requires a caller-supplied reservation and is not wired to UI; no managed-process RAM ceiling or desktop responsiveness is claimed.

#### Bounded grouped face refinement

The experimental worker groups consecutive candidates only when root, source stamp, instance path, leaf, epoch, placement, camera, viewport and cursor match. Each native call handles at most eight face IDs, reconstructs one call-local OCCT source, preserves face order and returns an error for the entire group if any face cannot be resolved. Rust retains document, transaction and worker ownership; no native handle escapes. Cancellation is checked between worker groups, not during one native call. Non-B-rep or single candidates retain the existing path. The UI does not invoke this worker.

On the E: default-feature debug build, a two-face box compares grouped results with individual refinement and checks front/back depth, invalid IDs, zero and over-eight inputs; six box faces under nonuniform and mirrored placements compare grouped and individual results. The matching OCCT/openNURBS-enabled kernel surface suite passed 14 tests. The first Rust build failed from an ambiguous numeric type and was corrected. The no-default-features check passed with 17 pre-existing warnings after two new unused-variable warnings were fixed.

This fixture does not establish a general locked-object policy, all geometry occluders, physical mouse behavior or desktop presentation.

## Direct NURBS surface snapping

Visible NURBS display triangles now provide candidates bound to the document source, instance path, placement, camera and scene epoch. The controller resolves that source and uses the existing OCCT single-face ray solver with the ray origin as reference, selecting the nearest forward intersection or refusing an ambiguous result. The selected surface instance is excluded from the display-occlusion check so it cannot occlude itself; other visible display surfaces remain occluders. Previously a direct NURBS surface could only occlude a B-rep snap; it was not itself a Surface snap target.

The default-feature E: test build with `-j 2` passed 19 `osnap_ui` tests, 11 existing precision tests, nine gesture tests, and seven combined offscreen GPU/egui tests. The NURBS fixtures check an analytic curved quadratic surface, a plane in front of or behind a sphere in Shaded/Wireframe or hidden, and a Snappy Gumball drag to a plane with one Undo. A separate new precision test passed for a cylindrical NURBS with two forward intersections under nonuniform and mirrored scale, checking the first intersection and stale camera/source rejection. `cargo check --no-default-features` passed with 17 existing warnings; that build does not provide exact OCCT refinement.

These fixtures do not establish complete picking accuracy: candidate generation still depends on display triangles, periodic/trimmed and self-overlapping surfaces need more coverage, and display-based occlusion may conservatively refuse a valid hit. The synchronous solver and display scans need measured budget and nonblocking integration. The offscreen GPU tests are regressions, not direct NURBS pixel or desktop pointer evidence; the active desktop was not operated.

A red/green test placed the near clipping plane between the two ray intersections of a NURBS cylinder. Surface candidate generation and kernel refinement now start their ray at the camera near plane. The test passes for that cylinder and a B-rep sphere in both perspective and orthographic cameras, including a far plane that excludes the rear hit. The original failure was reproduced before the code change. These checks are headless/offscreen; they do not prove behavior exactly on clipping boundaries, all trimmed or self-overlapping surfaces, the visibility of a physical monitor image, or general selection picking. Candidate discovery still depends on display tessellation and refinement remains synchronous.

## Surface candidate broad phase

Surface candidate enumeration previously intersected display triangles for every visible B-rep, NativeBrep and NURBS surface even when the cursor ray was far from them. It now queries the existing scene bounding-volume index using the visible ray and tests triangles only in returned occurrences. Unknown, degenerate or non-finite occurrence bounds are included rather than discarded. Surface triangle checks are skipped when Surface snap is disabled. The index is invalidated on changed Gumball previews by the existing controller path; a new B-rep fixture verifies candidates and canonical refinement before a preview, after a 1000 mm move and after cancellation.

A separate red/green test exposed a pre-existing index error: a direction component of `1e-13` was treated as exactly parallel and omitted a hit at large distance. The slab test now distinguishes zero from nonzero direction components and divides directly. A second test compares index candidates against analytically intersected spheres for 240 rays. This is bounded coverage, not proof for every floating-point scale or malformed geometry.

An opt-in release fixture uses 200 dispersed instances of one B-rep sphere (868 display triangles each), with 20 cursor positions and a warmed index. Candidate enumeration alone was p50/p95/max **8.547/8.688/9.016 ms** before and **0.277/0.280/0.287 ms** after, on E: with `-j 2`. The fixture verifies the expected single source-bound candidate. Runs were separate and system load was not controlled. They exclude cold index build, preview invalidation/rebuild, OCCT refinement, occluder scan, GPU and presentation; overlapping scenes may still require many exact intersections. They do not establish desktop FPS or a general speedup.

Two spatial-index tests, 13 existing B-rep precision tests plus the new preview test, 19 snap UI, nine gesture, six camera/grid, eleven scene snap, five shared-instance, seven world-picking and seven offscreen GPU/egui tests passed. The per-query mask and index allocations are not yet integrated with the planned production memory reservations. Display-mesh candidate omissions, asynchronous kernel admission and desktop evidence remain open.

## Shared triangle edges and indexed surface coverage

A new independent planar oracle compares the set of Surface candidate roots with analytic ray/rectangle intersections for 60 shared NURBS instances, including mirrored and nonuniform placements. It sends 720 rays across perspective/orthographic cameras and before/after a preview. Sixty rays per configuration are aimed at plane interiors, including the triangulated center; the remaining rays sample the viewport. An initial random screen landed exactly on a rectangle's outer edge, where a strict interior oracle was inappropriate; those samples were offset. A later aimed-center ray still failed: its object was present in the spatial query, but the display triangle intersection rejected it at a shared edge due to floating-point roundoff.

The triangle test now permits a dimensionless barycentric margin of `1e-12`; `64 * f64::EPSILON` did not suffice for the reproduced fixture. The plane oracle then passed. An application test reproduces the Perspective preview case and verifies that OCCT refinement reaches the analytic source point within `1e-7` model units and rejects the old candidate after preview cancellation. The margin can conservatively classify a point extremely close to a mesh edge as a candidate or occluder; it is not a document tolerance or a general robust-predicate guarantee. Source refinement remains necessary, and this test does not establish accuracy for arbitrary coordinates, topology, or display-mesh omissions.

On the default-feature E: build with `-j 2`, the 720-ray oracle, two spatial-index tests, eleven scene snap tests, seven world-picking tests, 15 precision tests, 19 snap UI tests, nine gesture tests and seven offscreen GPU/egui tests passed. The GPU tests are regressions, not direct pixel evidence of the edge case. A new release performance comparison and desktop validation were not run after this change.

Generic `PickHit.world_point` and raw B-rep `Surface` snap candidates remain display approximations. The older single-face adapter rejects shapes containing more than one face; the new indexed adapter has only the stated fixture coverage, including mirror and nonuniform scale for boxes, one drilled trim and one sphere seam. More complex trims/periodic surfaces, ambiguous depth, native B-reps, curves/edges, editing during refinement, performance and desktop input need separate coverage. Native B-rep surface snap is explicitly unavailable until a verified face binding is supplied. A ray refinement after candidate generation cannot find a small feature that the coarse display mesh did not represent, and is not a proof of general accuracy. The analytic fixtures are not evidence of desktop pointer behavior.

## Analytic sphere silhouette coverage

On the current default-feature E: debug build, `analytic_sphere_silhouette_surface_candidate_coverage` casts 144 orthographic cursor rays at the analytic sphere of radius 5 mm, constructed with 0.5 mm display deflection. At each of six radial fractions it tests 24 angles and independently compares every available refined hit with the analytic sphere within 0.000001 mm. All 96 returned candidates refined within that bound; no candidate was returned for the 48 rays at radial fractions 0.995 and 0.999, while all 24 rays at each of 0.9, 0.95, 0.98 and 0.99 returned candidates. The scene spatial index included the sphere on every missed ray: this fixture therefore locates the omission after the index, at display-triangle candidate discovery or later scene candidate admission, not the analytic source intersection. The fixture reports missed candidates without asserting the bug must continue, so a future fix can turn the misses into valid refined hits.

The 0.995 and 0.999 points are on the true sphere but outside the tested faceted display silhouette; no desktop pixel or physical-pointer test was performed. A conservative source-candidate strategy must separately define visible-image behavior, all intersected face identities, depth/occlusion, clipping, stale publication and resource limits; blindly accepting a bounding-volume or rear candidate is not a valid fix. The current UI remains unchanged. A current default-feature run passed 15 pre-existing B-rep precision tests, 19 snap UI, 9 gesture, 7 Gumball interaction and 11 GPU navigation/publication tests; these are headless/offscreen and do not establish desktop presentation.

## Scale-dependent display-triangle intersections

The Surface candidate and shaded-display occlusion path share a ray/triangle intersection that previously rejected every determinant with absolute value at most `1e-12`. Because this determinant scales with triangle area, the old check missed a face-on, visible planar display surface when a 2-by-2 local plane was placed at XY scale `1e-7` (world width `2e-7` model units); an independent analytic point and the scene index both confirmed the ray and object. The new regression failed on that exact case before the change.

The intersection now normalizes the two edge vectors before testing parallelism, making the threshold relative to orientation rather than triangle size, and explicitly rejects non-finite/zero-length inputs and non-finite computed values. It keeps the existing barycentric margin and still requires subsequent canonical refinement where applicable. The analytic planar fixture now passes at XY scales `1e-4` and `1e-7` in orthographic and Perspective cameras. A separate scene test verifies that a tiny displayed mesh blocks a target behind it but not a target in front. These are extreme numerical stress fixtures, not a claim of submicron manufacturing accuracy. They exercise display candidate/occlusion only, not kernel refinement for such scales.

## Indexed display occlusion

The shaded-display occlusion check previously examined the triangles of every visible mesh, hatch and NURBS display surface. It now queries the scene's existing ray index first and conservatively includes occurrences with non-finite or non-positive bounds. It still performs the same triangle, clipping, source-exclusion and depth checks on returned occurrences. A deterministic analytic fixture exercises 80 separated quad meshes, both camera types, a moved preview with bounds invalidation, targets in front/behind and explicit source exclusions. This is a bounded coverage fixture, not proof for all transforms, numerical boundaries, unknown bounds or occluder types. Index construction, temporary query allocation, warm/cold performance and actual desktop latency remain unmeasured; no speedup is claimed. The index and its memory admission remain existing shared scene responsibilities.

## Exact misses among grouped display candidates
