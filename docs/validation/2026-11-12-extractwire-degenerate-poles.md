# ExtractWireframe: sphere pole edges

The earlier ExtractWireframe slice refused a whole B-rep when any native edge was degenerate, so a reopened sphere produced no wireframe. The user approved changing that behavior for the tested scope. For all-source extraction, the native adapter now omits an OCCT-degenerate edge only when its two topological vertices are the same and it has no 3D curve. An inconsistent degenerate edge, or failure on another edge, is still refused. The ordinary selected-edge/DupEdge path and boundary-only path do not acquire this skip behavior. Native OCCT parsing and conversion allocations remain outside the Rust reservation.

A reopened radius-5 sphere with translation, at 0.5 and 0.01 mm display profiles and through command/menu dispatcher, now produces its single nondegenerate meridian seam. Sampled points lie on the analytic sphere and its endpoints are the opposite poles; Undo/Redo restores the entity sets. The two pole edges do not become point curves. A reopened box and sphere as separate roots, and a compound made from a box and translated sphere, each produce 13 curves with Undo/Redo. A source-level test with `max_outputs = 1` confirms skipped poles do not consume output slots; total topology remains constrained by `max_nodes`. The original tests expecting rejection for these exact sphere fixtures have been replaced because the behavior intentionally changed. Separate injected output-pressure, object limit, pressure/retry and DupEdge degenerate-edge refusal regressions remain in the suite.

Verification with OCCT 8.0.1: `cargo test -p om9-kernel --features 3dm-brep --test l2_01_10 --target-dir L:/om9-target -j 2` passed 87 with one known affine Boolean test ignored. `cargo test -p om9-app --test wireframe --test curve_menu --test dup_border --target-dir L:/om9-target -j 2 -- --test-threads=1` passed 41 wireframe (3 ignored), 6 menu and 9 DupBorder tests. The controller did not add a native mutation or worker; the command remains synchronous. Existing unreachable-pattern and unused-method warnings remain.

No claim is made that all degenerate topology is safe to omit: the runtime checks the flag, endpoint identity and absence of a 3D curve, while the successful geometry fixture here is an authored sphere. Malformed degenerate edges, arbitrary imports, nested blocks, non-rigid placements, desktop behavior and native peak have not been independently validated. The tests use headless dispatch, not a desktop click. The user approved updating the feature guidance to the tested behavior on 2026-11-12.
