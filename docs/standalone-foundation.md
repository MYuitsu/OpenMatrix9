# Standalone OM9 foundation

Active specification: `../OpenMatrix9_Codex_Spec_v2/specs/00-rhino-core/00-qymcad-foundation-migration.md`.

This workspace owns model, transactions, source admission, History/results, embedded resources, jobs, scene and `.om9` persistence. Validation passed 260 workspace Rust tests plus 7 explicitly invoked native export tests and 8 native import tests. The `om9` executable provides initial headless and native UI slices with four Matrix9 viewports, finite grids, a protected CMD transcript and shared Line/Point sessions. The latest supplied Matrix9 image governs the left sidebar, classic compact gray chrome, top toolbars and view ordering. Full Matrix9 interaction, selected native CAD/openNURBS exchange and migration gates remain under implementation. Unsupported commands/options remain visible disabled; no FreeCAD or QymCAD desktop is a dependency.

Run these from the OpenMatrix9 root. Cargo's default build directory is `standalone/target` on H:. UI dependencies require Rust 1.95 or later; the current build uses Rust 1.98. Validation records actual source/binary/fixture fingerprints and live module/child observations. Initial UI receipts do not close full Matrix9/native/performance gates.

Launch `target/release/om9.exe` with no arguments for a new document, or `--ui path.om9` for a saved document. CMD supports `Line` and `Point`, then `x,y[,z]` in page units and the captured CPlane; Line exposes `BothSides=Yes|No`. Esc cancels, `Undo`/`Redo` operate the owned document. The initial `BothSides=No` choice is an explicit OM9 policy, not a recovered Matrix9 default. Specialized branches, file dialogs, editable Layers, full F6 context/placement and GPU geometry caching remain pending. Native UI validation injects events only into this application's normal widget path and captures its rendered framebuffer.

Startup opens maximized with a 300-point left sidebar. Looking Down/Perspective occupy the upper row, Through Finger/Side View the lower row, with separate dropdown titles and axis triads; Through Finger projects global XZ and Side View global YZ. Initial orthographic span 41 and perspective eye [35,-35,35]/FOV35 are explicit OM9 visual-fit choices for the supplied reference. Embedded authored SVG icons use pinned pure-Rust resvg 0.45.1, rasterized once and cached; no screenshot bitmap is included. Decorative Project/Builder previews and layer slots do not create document objects or claim unavailable editors.

Schema 3 uses `OM9\0\r\n\x1a\n` magic, a version/chunk count and 72-byte chunk entries. Kind 1 stores typed JSON metadata; kind 2 stores immutable embedded resource bytes with exact ResourceId, length and SHA-256 correspondence. Missing/orphan/duplicate payloads, malformed ranges and noncanonical UUID keys reject. Resource insert/delete joins one coordinator transaction and Undo/Redo, with permanently retired IDs. Runtime restore admits the input/document/diagnostics/traversal peak before allocation, gates replay modules and creates a fresh owner session. Undo stacks are session-only.

Schema 1 requires explicit `om9 --migrate-v1 path.om9`, schema 2 `om9 --migrate-v2 path.om9`; default open/inspect rejects both. Migration preserves durable IDs, schema-2 payloads and existing resource kinds, creates empty provenance and checks runtime restoration before replacement. Absent replay modules remain unresolved. It preserves the original file on failure. Windows save verifies and publishes through the same held file handle in `om9-native-owner`; this adds no openNURBS process or CAD backend to the application. Schema 3 adds document-owned source/namespace tables with original resolved units, namespace-local native keys, streaming host baselines, retained-only records and sticky edited/deleted dispositions. Atomic import bundles publish resource/source/namespace/layers/definitions/entities together, with one Undo and retired identities. Existing direct edits and solver publication reconcile bindings; tombstones prevent resurrection on cold load, and unsupported retained cross-document transfer rejects. Structural ownership tests do not establish native import correspondence or preservation export. Full resource families, general native family admission/current-state merge, further migrations and external relinking remain pending.

The separate native `--inventory-source` operation emits schema-2 source DTOs with strict registered-table completeness checks, original units, native keys/relations, userdata descriptors and exact geometry projections. All DTOs require host admission; SDK-decoded indices are explicit and original source bytes remain authoritative. Actual source fixtures and independent native Circle D0–D3 oracles are recorded by `tools/validate_native_source_inventory.py`; this operation enables no application import/export command.

`--project-source` emits schema 3 tied to the SHA-256 of the actual held source bytes. Its application-authored resolution packet chooses explicit factors for unknown model/page/definition units; declared units reject conflicting choices. Definition members use their local canonical scale and instance placements conjugate parent/definition scales. Rust owns source snapshotting, strict DTO/relationship/depth/budget admission, fresh namespace identities and guarded atomic import. Default `Preserve` keeps uncovered geometry/attributes/dependencies retained-only. Explicit `Geometry` names omitted bound fields, including unsupported parent/material color selectors. Imported sources keep durable original/resolved definition contexts and bytes after the external file is removed. Eight actual tests with 15 source files are recorded in [import evidence](../docs/validation/2026-10-13-standalone-import.json). This slice does not enable an app import dialog or a retained merged writer.

Owned circles keep native `domain` and optional `angle_domain` for affine parameter-to-angle correspondence. Missing/null `angle_domain` preserves native radians. The current native Circle writer requires an exact full angular turn; near-full and partial arcs remain unsupported/retained-only. Fractional D0–D3 uses the composed angular map to avoid canceling intermediate scale overflow and narrow-domain phase loss. Display/picking retain reproducing native parameters; unresolved f64 sample bindings emit a precision diagnostic without modifying the durable circle.

QymCAD remains reference-only; no code has been copied. The bounded rational evaluator ports authored OM9 Rust code under LGPL-2.1-or-later, recorded in `provenance.json`. Dependency versions/licenses are pinned in Cargo metadata/lock. The native UI uses eframe/egui and wgpu; selected native CAD adapters are not present in this profile. Affine scene previews reuse immutable geometry buffers; the initial egui painter still projects/tessellates on the CPU, so warm-pointer GPU performance is not accepted.

`native/` separately builds the authored openNURBS dependency probe and `om9-exchange-native` against official pin `eb92af3ba1806b0a34a99aba0d3bda83e3d46083`, cached at `build/standalone-deps/opennurbs`. Native JSON uses nlohmann/json 3.11.3, with header/license hashes checked by CMake; its MIT notice is in `Resources/licenses/nlohmann-json.txt`. Configure with CMake/VS2022 x64, then build targets `om9-opennurbs-probe` and `om9-exchange-native` in `build/standalone-native` Release. Run `rtk proxy python tools/validate_standalone_opennurbs_probe.py` and `rtk proxy python tools/validate_native_exchange_conversion.py`.

`om9-exchange` captures current owned masters and runs the pinned native binary in a dedicated bounded process. It checks cold on-disk native geometry/IDs/layers/definitions/units, then revalidates sources and cancellation before same-directory atomic replacement. Failed/stale/canceled/readonly/tampered output preserves the good destination and document/Undo. Seven real Rust lifecycle tests are explicitly ignored in portable workspace runs; `rtk proxy python tools/validate_standalone_exchange.py` invokes them and writes the receipt. Geometry-only export discloses omitted History/results/runtime/document metadata and native default-layer/false-only cloud-channel conversions. Unsupported native fields reject explicitly. These components are not linked into the `om9.exe` UI and do not enable an application import/export capability. Retained-source merge, full import namespace/clipboard/archive fixtures, aggregate concurrent job reservations and actual Rhino 5 open/edit remain pending.
