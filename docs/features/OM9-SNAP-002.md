# OM9-SNAP-002 — End Snap / shared snap foundation

Status: in progress. Rust state and cursor candidate ranking are connected to native topology, original Osnap E menu/CMD and the main O-Snap sidebar switch. Earlier entries below retain historical milestones; latest native evidence is in docs/validation/2026-10-05-core-end-snap.md.

Local End Snap requires curve ends, interior polyline/joined-curve vertices, closed seams and surface/polysurface corners. Both master O-Snap and End Snap must be enabled. Original command Osnap E. Source defaults are not normalized; OM9 foundation currently defaults master and End off, with user choices preserved independently.

Rust core_snaps::State holds master/End toggles and encoded states 0..3; invalid encoding rejected. Disabling master preserves End. Candidate ranking uses logical screen pixel distance and exact supplied world position, rather than world-distance ranking. The earliest candidate wins equal-distance ties. Candidates must have finite world coordinates within ±1e9 mm and finite projected coordinates. Aperture must be finite, positive and ≤256 logical pixels (OM9 range choice). Native extraction must supply correct visibility/placement/clipping semantics; pure candidate validity cannot prove these.

Tests rust/tests/core_snaps.rs: state persistence across master toggles, encoding, nearest/tie/aperture boundary and invalid coordinates/projections. Stub failed candidate-selection test; implementation passed all three tests. No snap geometry has yet been verified in FreeCAD, and no other mode is claimed implemented by this module.
