# Checked triangle-mesh CSG and self-overlap repair

Owner: `OM9-L2-10-02` / `OM9-L3-10-02-002`, AFTER advanced mesh repair.
The user explicitly selected implementation of a mesh boolean/CSG kernel on
2026-10-23. This extends the owner's geometric service; it does not move advanced
repair onto the M03 basic mesh-reduction critical path or close the AFTER owner.
Foundation: M01 document typed geometry (`OM9-L3-01-03-002`). Existing Matrix
command identifiers and UI remain unchanged.

Source requirements are the local milestone contracts and the direct request.
The inherited Matrix Book 2 range is printed 376–377 / PDF 150–151; it is not
claimed to specify this new algorithm. The algorithm is an OM9-authored Rust
implementation; no QymCAD, commercial, or third-party implementation was copied.
The mathematical basis for classification is the signed solid-angle winding
number, with boolean material classification as described in
[Jacobson, Boolean Operations using Generalized Winding Numbers (2016)](https://arxiv.org/abs/1601.07953).
This implementation uses bounded local plane arrangements rather than claiming to
implement that paper's entire robust processing pipeline.

## API and geometry

`om9_core::mesh_csg::mesh_boolean(a, b, op, options)` returns a new owned
`Mesh` and `CsgReport` for union, A-minus-B or intersection.
`mesh_csg::repair_self_intersections(mesh, options)` extracts the nonzero-winding
material boundary from one oriented, potentially self-crossing mesh.
The old `mesh_repair::repair_self_intersections` path re-exports this checked API;
its former `(mesh, max_pairs) -> (mesh, removed_faces)` signature is replaced by
`(mesh, CsgOptions) -> Result<(Mesh, CsgReport)>`.

Inputs must be nonempty triangle meshes with finite coordinates, valid indices,
two oppositely directed incident faces per edge, one face fan per vertex, and no
isolated vertices. Self-intersections are permitted at input. Quads, open surfaces,
inconsistent index winding, and vertex colours return explicit errors. Normals
are invalidated and can be regenerated from the result.

For boolean operands, UV presence must match. `Mesh.corner_uvs` is the source of
UV data; new corners interpolate within their source face, preserving seams even
when their geometric vertices weld. No dependency on `MeshUv` is introduced.
The compatibility sidecar remains unchanged elsewhere in OM9.

1. Normalize coordinates for arithmetic, retaining world-space output units.
2. Query a BVH for overlapping triangle bounds, confirm actual contact, then split
   local triangle/polygon fragments. Coplanar overlays also split by edge planes;
   the lowest source index owns coincident material to avoid duplicate sheets.
3. Probe the two sides of each fragment with BVH-accelerated signed ray crossings
   (integer winding for closed oriented meshes). Retry ambiguous edge/parallel
   rays in three directions, then fall back to the solid-angle sum; apply union,
   difference, intersection, or single-input nonzero winding classification.
   Bound the probe along its actual normal intersection with finite nearby
   triangles. Keep probes at most one quarter of that clearance; proximity to an
   infinite supporting plane alone does not establish a wall. The minimum probe
   displacement and all geometry tolerances remain unchanged.
4. Retain only the material boundary, orient it outward, and deduplicate coincident
   fragments. Internal pieces are classified away; no original crossing triangle
   is discarded merely because its area is smaller.
5. Weld positions, query a vertex BVH to insert vertices along fragment edges and
   remove T junctions, then triangulate cells with interpolated corner UVs.
   An already triangular conforming cell stays one triangle.
6. Require closed oriented edge incidence, one vertex fan, and no improper
   triangle intersections within tolerance (BVH candidates plus the unchanged
   geometric predicate) before returning success.

`triangle_intersection` exposes a noncoplanar segment, point, positive-area
coplanar overlap polygon, or disjoint classification. It uses the same tolerant
geometry predicates as result validation. Shared edges and vertices are excluded
from the existing self-intersection diagnostic; coplanar area overlap is included.

## Options, errors and limits

Default tolerance is an OM9 engineering choice, `1e-8` in mesh coordinate units,
not a recovered Matrix default. After the measured optimization on 2026-10-23,
default limits are 25,000 total input triangles, 50,000 live fragments/output
triangles and 20,000,000 work units. Report counters
are input/output triangles, split events, classified/internal/duplicate fragments,
work units, candidate pairs, ray/triangle tests and solid-angle fallbacks;
they are not counts of repaired intersection pairs. BVH construction/traversal
and narrow-phase work consume the shared budget. The triangle limit admits
input; it does not guarantee a complex arrangement fits the other budgets.

The kernel uses `f64`, not exact predicates. Normalized tolerance must fall in
`1e-13..=1e-4`; world-coordinate precision, near-threshold cells, ambiguous
winding, collapsed fragments, nonmanifold contact and exhausted budgets fail
explicitly. Local supporting-plane cuts can still over-split; dense intersections
can still exhaust the budget. Adaptive exact arithmetic and production-mesh
performance certification remain open. The earlier global all-plane arrangement
and all-pairs verification have been replaced by conservative BVH queries.
Within a single repair mesh, opposite oriented shells cancel in overlaps;
oppositely oriented nested shells define cavities. This is nonzero winding fill,
not an attempt to infer the intended solid of arbitrarily unoriented triangles.

There is no deletion/fill-hole fallback on a CSG error. Open-hole repair is still
outside this implemented slice. Basic cleanup, centroid hole filling and QEM
reduction remain separate utilities; the reduction result is not certified by
the new CSG validator after subsequent collapses/truncation.

## Ownership and lifecycle

These are immutable-input core services: no document pointers, identity mutation,
native FFI, transactions or implicit publication. An error returns no partial
result. Callers retain the source mesh and choose when to publish one result.
There is no new Menu/CMD/SDK boolean route, preview, History or UI cancellation
session in this delivery. Existing ReduceMesh's self-overlap prepass now uses the
checked API and propagates its error; later reduction remains its existing scope.
New geometric results serialize as ordinary `Mesh` data; JSON roundtrip is tested,
while a new interactive `.om9`/Undo/Redo workflow is not claimed.
