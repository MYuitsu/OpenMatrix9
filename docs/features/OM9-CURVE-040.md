# OM9-CURVE-040 — DupEdge (implementation in progress)

Menu and `DupEdge` share the standalone dispatcher. The established slice accepts preselected edges or a viewport selection session followed by Enter/right click, on one root OCCT B-rep with verified topology and rigid placement. A first single-edge viewport route for sources without an in-session proof is described below. Ambiguous viewport hits and unsupported inputs are refused. Each selected edge becomes a source-derived NURBS curve preserving its trimmed geometry and orientation, placed in world coordinates on the current layer. Closed edges are covered for the attested route; seam-specific behavior is not yet established.

All curves are prepared before one transaction; one Undo/Redo covers the set. Cancel writes nothing. A failed commit keeps the pending selection for retry. The command does not modify its source, and no command options or preview geometry are implemented. Input lengths and geometry retain document units through the existing B-rep kernel path. No separate History recipe is produced. Save/open of the resulting curve is checked for the quarter-arc fixture described below.

Evidence: [headless geometry, menu, selection and viewport tests](../validation/2026-11-10-dupedge-source-first-slice.md). Manual desktop interaction, native peak usage, proof availability after reopening/eviction, nested instances and affine placements remain outside the verified slice. M03 manual UI signoff remains open.

The reopened-file route supports viewport preselection or invoking the command before selecting one or more root BRep edges. A product Box saved and opened with the current v4 encoder was checked at two distinct edges individually and together in headless viewport tests, including preselection, analytic endpoints and Undo/Redo. A tracked pre-change v4 Box fixture was also checked for one edge and Undo/Redo. Separate current-v4 fixtures cover a cylinder's closed circle and a trimmed quarter arc at 0.5 and 0.01 mm, and a Sphere seam with analytic geometry and Undo/Redo; selecting near a degenerate pole is refused by the source resolver. The selected display-segment endpoints are checked against source curves and only one matching candidate is accepted. This correspondence check uses at most 1e-6 mm, capped by an explicitly smaller document absolute tolerance. A shifted arc display and two independent coincident boxes are refused after save/open with existing Redo preserved; arbitrary display alteration and coincident topology remain unproven. Narrow tests cover source-point screen/depth mismatch and a later unmatched edge preserving pending selection and Redo. General seam topology, occlusion and desktop remain open.

An authored unit Box imported from 3DM was converted to editable OCCT, isolated from other imported objects in the test, saved/reopened and duplicated with analytic endpoints and Undo/Redo. Synthetic 3DM cylinder and quarter-cylinder-face documents were imported and saved/reopened; their closed circle and trimmed quarter-circle respectively were checked against sampled analytic geometry with Undo/Redo, and the cylinder cancel preserved existing Redo. For that imported arc, ordered output endpoints also match the generating ON_Brep edge orientation. A source geometry or placement change after a captured pick causes stale-context refusal and ends the old command without changing the post-edit document or existing Redo in the tested cases. Authored Box and cylinder cases also passed ON_Brep payload conversion. These samples do not establish general 3DM import, arbitrary trims or multi-object selection behavior; at one view the unit Box pick was conservatively refused because another edge was within the screen pick radius.

In Shaded mode the viewport checks whether displayed triangles lie in front of the candidate before accepting a DupEdge pick or eligible edge preselection; the tested self-occluded and other-object-occluded edges are refused. Wireframe remains selectable in the tested overlapping-view fixture. An offscreen GPU test also checks mode switches while the old frame is published and validates the selected output. This is sampled visual-picking behavior, not a general exact-geometry occlusion guarantee; OS desktop behavior remains unverified.

For a reopened Box, synthetic egui events clicked the Curve palette icon or typed `DupEdge` in CMD, selected an edge and completed by right-click; both routes produced the analytic edge and passed Undo/Redo. A narrow [process memory sample](../validation/2026-11-11-dupedge-process-memory.md) includes OCCT calls but cannot attribute or bound the native peak.

A synthetic native-order fixture combines an OCCT source with reversed face insertion order and the original display/UUIDs; after save/open, two picked Box edges produced the expected curves in one Undo/Redo. The fixture verifies the source edge index actually changed, but does not prove behavior for every permutation or historical file.

The selected display point must be within the declared display deflection plus endpoint-matching tolerance of its resolved source edge; cursor pick radius is not added to that geometric bound. The adapter adaptively bounds distance along each segment to the bounded source curve using numerical OCCT projections; it refuses when its bounded verification work cannot establish a match. A modified circular chord and a NURBS curve that defeats three fixed samples are refused in targeted fixtures. This is not an interval-arithmetic certificate: OCCT and floating-point behavior, declared deflection, arbitrary input and native resource peaks remain limitations.
