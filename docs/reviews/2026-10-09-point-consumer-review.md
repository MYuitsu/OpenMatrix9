## Contracts checked without another defect established

- **Borrowed ABI bounds:** length limits (text 1,024 bytes, units 512, UID 256), null/nonzero combinations and UTF-8 are checked before constructing nested slices. Request-array count is limited to 64 before array construction. Alignment, readable allocation size, valid writable outputs and disjoint memory remain explicit caller obligations; the ABI cannot prove arbitrary native pointers valid.
- **Output atomicity:** parsing, resolution and report construction precede result writes. Short/invalid report capacity refuses before copying either numeric or report output. Size query leaves the numeric value untouched. A later invalid input in a combined report prevents any report copy. The bounded error output is intentionally allowed to change on failure and is NUL-terminated.
- **Ownership:** Rust `Resolved` owns context and original text; native `CoordinateInput` owns context, raw input, optional previous point and provenance. Native request pointers refer to stable owned strings during synchronous calls. Requests assembled for combined reports remain backed by the unchanged input vector throughout both size-query and write calls. No host/App/Qt pointer is retained by Rust.
- **Serialization:** Rust reconstructs combined provenance from validated request values, rather than accepting native JSON fragments. Control characters, quotes and backslashes are escaped; owner/revision identifiers are strings, avoiding JSON integer precision loss. Float formatting retains round-trip precision. Combined reports reject mixed command contexts and excessive input/output budgets. World snaps explicitly report unavailable source identity rather than inventing an object reference.
- **Phase and unit semantics:** Point-only phases reject scalars; PointOrLength permits a scalar using captured model scale. Explicit unit suffixes use the shared unit parser. World pick/snap/F4 bypass both CPlane transform and model-unit multiplication. Previous points are validated world millimeters. Existing strict Cartesian grammar is reused; malformed input does not fall back to C++ parsing.
- **Actual identity and frame revision:** CoreCPlanes supplies the registered runtime document owner, raw frame and actual `om9_cplane_read` revision. The registry drops owners on document deletion and allocates a new monotonically increasing owner. Captured logical slots are labeled as logical slots, not unique native viewport identity. UID plus runtime owner and exact unit-context text are revalidated; the current frame is intentionally not compared under the start-latch policy. The numerical raw-versus-realized frame issue is the second finding above.
- **PictureFrame modal start:** the frame/context are captured before image selection and revalidated after the modal dialog. A deleted/reopened document cannot reuse its old runtime owner even if its persistent UID or memory address matches. Units changed during selection are rejected. The source does not claim an active-view transition epoch or a complete shared command reducer.
- **Accepted-only PictureFrame inputs:** the first corner is retained only after validation; rejected width/reference values and hover preview do not append provenance. Scalar width remains a tagged length. The candidate second input is serialized with the accepted corner before mutation. Failed geometry plans do not advance accepted state or consume Once.
- **Transaction content:** on a successfully opened transaction, image file/dimensions/placement, coordinate report and unit context share the same transaction. Recompute error detection and Base/std/unknown exception handlers abort before success feedback. The source checks pending transaction only after mutation has materialized the lazy transaction, which agrees with this SDK. `hasPendingTransaction()` is explicitly `activeUndoTransaction != nullptr` (`Document.cpp:690–692`); no UndoMode finding is made.
- **FFI panic boundary:** normal malformed-input paths return errors and no input-driven indexing panic was identified. Formatting into `String` is infallible apart from process allocation failure; private `Resolved` fields preserve the validation invariant used by `expect`. The release profile is `panic="abort"`; these new entry points do not add unwind recovery, so this is not a claim of crash containment for allocation failure or a future internal panic.
