# Independent review: authored instance isolation — 2026-10-10

**Conclusion:** No remaining blocker for the authored RCORE-01.T06 fixture.
The reviewed native and FreeCAD evidence supports advancing this numbered
acceptance fixture: two placements share one definition, B has reflection and
nonuniform scale, world coordinates match independent tables, changing B leaves
the definition/member/A unchanged, and the exercised unsupported transforms
reject explicitly without replacing the destination. This conclusion does not
close the broader instance, History, reference-owner or all-P0 contracts.

Review baseline: `661529f`. Scope: the instance-isolation plan, new native and
host fixtures, native CMake registration, unchanged production routes, and

comparisons, artifact hash checks and direct byte comparisons; no build, native

## Findings and resolved corrections

1. **Resolved host oracle gap:** the initial host macro allowed two expanded
   leaves belonging to A while omitting B: item count and membership in the
   selected pair did not establish coverage. The working-export loop also
   treated every non-A name as B. The final macro checks unique exact root UUIDs,
   then requires the structural set to equal `{A UUID, B UUID}`; working output
   requires unique authored A/B names and the final set `{A, B}`. Fresh run
   `7df9aa4dabe7493bbd9b142d940c0559` exercises these assertions. The earlier
   64-check run had correct observed data but is superseded as acceptance for
   the current macro.
2. **Resolved cache description:** `AddModelGeometryComponent` duplicates the
   geometry, and pinned `ON_Brep::operator=` copies `src.m_bbox`. The fixture
   adds its model-owned member before computing the standalone box's bounds;
   later priming the standalone object does not prime the separate model member.
   The final source primes the actual model-owned member and asserts exact
   local bounds `(1,2,3)..(3,5,7)` before writing the source baseline. Its comment
   now describes this initialization order without claiming that cloning always
   clears the cache. The exact full-payload comparison remains unchanged.

The earlier compiler/API failure, wrong name-based corner-table selection
(`A/Canonical` versus `A`), and unprimed-cache comparison are fixture diagnostics,
not passing production evidence. The persisted payload diagnostic failed
`B overlay leaves exact native canonical geometry payload`. The parent isolated
13 differing bbox/chunk-CRC bytes before correcting the authored baseline;
that byte-level diagnosis is parent-supplied historical evidence. The reviewer
independently checked the final raw pairs and source initialization order. No
payload fields are omitted, quantized or normalized in the final native oracle.
No claim is made that an unprimed runtime bbox cache remains unchanged on export.

## Independent geometry and identity oracles

The box dimensions are `(2,3,4)`, with member translation `(1,2,3)` and definition
translation `(4,5,6)`. A has translation `(100,200,300)` and unit scale. B has
translation `(20,30,40)`, positive 90-degree Z rotation and scale `(-2,3,0.5)`.
Both host links have `LinkTransform=True` and the exact same target definition.

For already member-local coordinates `p`, let `q=p+(4,5,6)`. The independently
authored maps are `A(p)=(100+qx,200+qy,300+qz)` and
`B(p)=(20-3*qy,30-2*qx,40+0.5*qz)`. The native matrices explicitly contain the
definition translation once. Their B linear determinant is `-3`; neither
expected table is generated by the adapter being tested.

All eight corners are matched bijectively within the unchanged **1e-7 mm**
geometry tolerance, with exactly eight native vertices. A bounds are
`x[105,107], y[207,210], z[309,313]`; B bounds are
`x[-10,-1], y[16,20], z[44.5,46.5]`. Moving B alone by `(7,-11,13)` produces
`x[-3,6], y[5,9], z[57.5,59.5]`. Native `readCorners` resolves leaves by exact
authored root UUID and requires each root once. Host structural imports now do
the same; the working route verifies both independently baked CAD leaves.
Thus duplicate roots, an omitted sibling, incorrect order of scale/placement,
or applying definition/instance transforms twice cannot satisfy the fixture.

Host bounds use a deep geometry copy without copied mesh and
`optimalBoundingBox(False,False)`. The bbox-only allowance is separately
declared as `1e-7 + 64 * ulp(max(1,abs(actual/expected bounds)))` mm. Local
`BRepBndLib.hxx:69–81` documents `Precision::Confusion()` for numerical bounds
when shape tolerance is disabled; local `Precision.hxx:165` gives `1e-7`.
This enclosure allowance does not enlarge the corner tolerance, change model
tolerance, or weaken exact source/sibling fingerprints. Every persisted bbox
delta lies within its recorded allowance. Reported signed volumes vary with
native wrapper orientation; volume is diagnostic, not the transform/isolation
predicate or a universal orientation assertion.

Host isolation compares exact canonical member BRep SHA, member UUID/placement,
definition UUID/placement/member order, and A UUID/target/placement/scale/
LinkTransform/world-BRep SHA. These remain exact after the B-only transaction,
Undo, Redo, and actual structural/working exports. The B-only move adds exactly
one Undo entry. These assertions establish the exercised local editing contract,

Each host structural V5 export contains one shared definition, one BRep member,

## Scope left open

The tested fixture is a live, owned box definition and two direct placements in
millimeters, edited through existing APIs. It does not certify nested or empty
definitions, arbitrary representations, overflow determinants from otherwise
finite coefficients, reference-owner mutations, universal attributes parity,
History, Mirror/Scale command UI/defaults, worker cancellation, stale handles,
fresh-process FCStd reload or whole-process memory safety. The outer archive
instance gate still checks IsValid/IsAffine/nonzero determinant without its own
explicit finite-determinant check; nonempty leaves reach the stricter existing
native transform gate. Empty definitions/overflow cases need separate direct
evidence before any universal unsupported-transform claim. No new Rhino5
runtime parity is implied. T07/T08/T09/T10/T11 and wider P0 clauses remain open.
