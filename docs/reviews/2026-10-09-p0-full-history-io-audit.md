## Conclusion

Neither P0 chapter is complete. History has substantial native family implementations and verified bounded lifecycle behavior, but lacks the required common durable schema and shared state/identity/job contracts. Exchange has a substantial **current-state preservation writer** after main integration; it must not be described as wholly absent. It remains bounded by explicit type/resource/unit/metadata exclusions and lacks the Rhino geometry clipboard and full cancellation/resource contracts.

The old RCORE-10 update paragraph and `docs/validation/2026-10-09-rhino-core-history-io.md` overstate the absence of a preservation writer after main was merged. Conversely, the merged writer and existing native/GUI checks do not close all RCORE-10 acceptance fixtures.

- **Verified slice**: existing result artifacts inspected and hash checked, plus matching current test source. This is prior execution evidence, not a new test run.
- **Implemented / unverified**: inspected implementation and/or fixture exists, but no matching complete acceptance evidence inspected here.
- **Gap**: an explicit required contract is absent or only family-specific in the inspected paths.
- **Historical claim**: a committed ledger reports a result whose raw artifact was unavailable or not independently inspected here.

## Historical Rhino limitations that must remain scoped

The capability-slice ledger describes real target-specific incompatibilities, not generic missing editor work: CurveOnSurface optional m_c3 omission in Rhino5.14; invalid/Unset standalone PolyEdgeCurve/PolyEdgeSegment roots and loss of reversal/wrapper metadata; mixed reference-root losses; some inward-cavity BRep preservation without equivalent editable OCCT representation. Current code deliberately refuses unsafe public V5 writes and can retain immutable source data in FCStd. Do not promise to turn these into compatible exports by merely changing archive version or dropping metadata. Raw target artifacts need recovery/rerun before independently confirming each reported case at this HEAD.

Conversely, the ledger has scoped actual-Rhino success claims for ordinary and nested no-C3 CurveOnSurface controls, analytical multi-shell/cavity BReps, seam profiles and two analytic BRep owner geometries. Do not erase that work by saying no Rhino application testing has ever occurred.

## Recommended complete-scope dependency order

1. Implement durable Rust History schema and family adapters with explicit version/migration, source/output revisions, typed contexts and shared state/diagnostics. Preserve existing native geometry solvers.
2. Add proposed-link/placement DAG validation and semantic subelement unresolved policy; then test full cross-family T01–T08/T10–T12 against that schema.
3. Implement shared Rust jobs/snapshot/cancellation/budget policy, correct import worker planning, and prove both History and I/O late-result rejection plus atomic failure cleanup.
4. Complete existing current-state writer field/table/unit options and the existing support matrix, with combined edit/delete/new fixtures. Preserve fail-closed target incompatibilities.
5. Add geometry clipboard protocol/direction/focus/ownership support, then run target Rhino tests and recover historical artifacts. Finish acceptance evidence for every fixture; do not substitute a bounded increment or a matrix of implementation labels for complete P0.

No product files, feature statuses or specs were edited by this audit. Final Git status showed concurrent parent/team tolerance work in `rust/src/lib.rs`, new tolerance source/tests/macro, and two new plans; those changes were not made or evaluated by this audit.
